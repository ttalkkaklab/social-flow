# Reply guidance — context, useful feedback and actual authorization

Follow [automation guidance](../../_shared/automation-guidance.md). Replies are
person-to-person conversation: read the original comment and the channel's post
before writing. Reply only within explicit user or standing authorization; a
published post alone does not authorize sending replies.

When helpful, use `check-style.py --surface reply` or a growth-post-reviewer read
to find concrete wording problems. Neither a score, an S1/C7 label nor a fixed
number of review rounds gates sending an otherwise authorized reply. Non-Korean
copy outside the checker's coverage is `not_applicable`, not failed or approved.
Do not force sentences to become longer solely to satisfy a style heuristic.

Revise the actual problem while preserving meaning, context and the speaker's
voice. Deletion is one option, not a mandatory editing operation. Record useful
unresolved findings without inventing a clean result or automatically skipping a
reply because a number is below a threshold. A reply stays unsent only for an
unresolved factual or context problem — it would assert something unverified, or
it answers past what the comment says — or for missing authorization; a creative
shortfall is revised, not a reason to skip. Record the reason when a reply is not sent.

## Context to read

| Platform | Relevant context |
|---|---|
| Instagram | Original comment and the caption of the channel's post |
| YouTube | Original comment and the video's title and description |
| Threads | Original comment and the channel's post text |

Use actual platform reply identifiers and resolve uncertain prior publish results
before retrying. Do not duplicate a reply or extend a conversation's authorization
to hiding comments, blocking accounts or changing account settings. Spam or abusive
comments may be left unanswered; explain that choice when relevant.
