1.The whole picture — what connects to what

The core idea: the recording, not web research, is the primary source. What you said while showing the screen becomes a timeline.md with per-sentence timestamps, and the storyboard skill designs scenes out of that material.

9:16 short-form + per-platform text
→
YOU
Publish approval
Threads · IG · FB · YouTube

Green borders are your turn; Claude runs the rest. There are two approval gates — storyboard approval (before production) and publish approval (before anything goes public).

2.Setup (once)

2-1. Load the plugin

Start from a Claude Code session with this repo loaded as a plugin:

claude --plugin-dir /path/to/social-flow

2-2. Check the prerequisites

ItemHow to checkIf it's missing
whisper.cpp command -v whisper-cli brew install whisper-cpp
STT model (1.5GB) ls ~/.cache/whisper-cpp/ggml-large-v3-turbo.bin download it from ggerganov/whisper.cpp on huggingface
Screen Recording · Microphone permission checked automatically on the first recording attempt System Settings → Privacy & Security → Screen Recording / Microphone, allow your terminal app
ffmpeg · python3 command -v ffmpeg python3 brew install ffmpeg
✓ INSTALL ONCE, DONE

whisper.cpp and the model are installed once, and the Screen Recording and Microphone permissions are granted once. After that you go straight to section 3.

2-3. Create a channel

Content accumulates as data/[channel]/episodes/[topic]/. If you don't have a channel yet, make the profile first (channel tone, domain vocabulary, and visual theme are recorded there):

/social-flow:channel add "Money Talk"

The channel name is converted into an English slug used as the directory name — the money in the examples below is that slug. From here on, the channel you type in commands is the slug, not the original name.

3.Recording while you talk

YOU

Start recording

/social-flow:ingest money record

Claude starts a screen + microphone recording with screencapture and tells you to go ahead and demonstrate while talking.

YOU

Demonstrate out loud

  • Explain into the microphone while you work the screen — what you show and what you say is the raw material.
  • When you change subject, pause for a second or more and then switch the screen — this one habit decides how accurate the scene boundaries are. A long pause overlapping a screen change is what gets read as a boundary.
  • When you're done, type "recording done" in the chat.
🖥 ONLY THE MAIN DISPLAY IS RECORDED

The recording captures only the display set as main in System Settings. With two or more monitors, demonstrate on the main one and use the secondary freely for script notes or progress — it won't be in the recording.

⚠ BEFORE YOU HIT RECORD

Turn on Do Not Disturb — notification banners on the main screen are captured too. Avoid screens showing anything sensitive: emails, account names, tokens, amounts. (If they do get recorded, the review step catches and reports them, but not recording them in the first place is better.)

If you already have a recording

Give a file path instead of record. Leave the topic slug out and you'll be offered one based on the transcript:

/social-flow:ingest money ~/Movies/demo.mov fx-app-intro

4.Automatic processing — recording to timeline

After "recording done", Claude works through the steps in order. The only place you step in is the final check.

STT
① Transcribe
whisper.cpp + a domain glossary injected (heads off misheard terms)
→
SIGNAL MERGE
② Scene split
boundaries computed from silence length + screen changes
→
VISION
③ Screen analysis
keyframe per scene → screen description · transcript correction · sensitive-data review
→
YOU
④ Check
review scene count and summaries → pick the next step

What comes out

data/money/episodes/<topic>/recording/
├── raw/                 # raw STT · silence · screen-change signals (whisper output kept verbatim)
├── timeline.json        # machine-readable scene timeline
├── timeline.md          # ★ for humans — scene table + per-sentence timestamps + screen descriptions + correction log
└── keyframes/seg-N.jpg  # representative frame per scene

Your three jobs

  1. Check the timeline — when the scene count and per-scene summaries come up, skim them and choose [go to storyboard / adjust boundaries / stop here].
  2. Report mishearings — if the transcript is off, just say "it heard ○○ as △△". The glossary gets reinforced and it re-transcribes, or the text is corrected against screen OCR. Corrections are written as original(→corrected) plus a correction log, so they stay auditable.
  3. Decide on sensitive data — scenes with personal information on screen are reported as a list. All you decide is whether those frames can be used in the video.
✓ HOW LONG IT TAKES

large-v3-turbo transcribes at roughly 3–5× realtime on Apple Silicon — a 10-minute recording is 2–3 minutes of STT. The whole pipeline usually finishes inside half the recording's length.

5.Turning it into content — storyboard through publishing

/social-flow:storyboard money <topic>   # scene design with the timeline as the primary source → [approval]
/social-flow:produce money <topic>      # 9:16 video + per-platform text
/social-flow:publish money <topic>      # [approval] → Threads · IG · FB · YouTube

When recording/timeline.md exists, storyboard uses it as material instead of doing web research. Each step checks the previous step's output — produce stops on an unapproved storyboard, publish stops on unfinished production, and each points you back to the step that's missing.

✗ WHAT YOU SAID ON THE RECORDING IS NOT A SOURCE

Numbers you said while recording — prices, tax rates, deadlines, anything time-sensitive — are claims, not sources. They go through the same two-independent-source cross-check at the storyboard step. Fillers and slips of the tongue in the spoken transcript aren't copied into the narration either; the sentences get rebuilt.

6.The script-first flow — storyboard, then filming

This mode flips the flow of sections 3–5 (improvised recording → timeline → storyboard). The storyboard and shooting script are settled first, you record against the script, and Claude cuts the raw recording into the final edit. Because what you'll say is designed up front, the quality is even, and the picture and the voice are a real demonstration in your own voice rather than generated.

AUTO
Script design
research · scene design · shooting script (script.md)
→
YOU
Approve + film
script on the secondary display, demo on the main one
→
AUTO
Align + edit
transcript → scene alignment → cuts · zoom · subtitles · BGM
→
YOU
Publish approval
along with the per-platform text
/social-flow:storyboard money <topic> as a shooting script   # scene design + script.md → [approval]
/social-flow:ingest money record <topic>                    # film against the script → transcript · alignment
/social-flow:produce money <topic>                          # cut the recording into a 9:16 edit + platform text
/social-flow:publish money <topic>                          # [approval] → publish
YOU

Filming rules (also printed at the top of script.md)

  • Put the script on the secondary display — only the main display is recorded.
  • At the end of a scene, stop talking for a second, then switch the screen — that point becomes the edit cut.
  • Enlarge the fonts and windows of whatever you're demoing (⌘+ in a browser) — it all gets scaled down to a 1080px-wide portrait video, so small text disappears. If the focus is one part of the screen, the edit crops in on that area.
  • If you fumble, don't stop the recording — start that scene over from the top. The edit uses the last take.
  • No need to recite the sentences — just keep the key numbers and proper nouns word for word.

The edited video is a dark canvas with the scene title (top) + a band of your recording (middle) + subtitles (bottom). The subtitles come from the corrected transcript of what you actually said, not from the script, and the BGM automatically drops its volume under your voice (ducking). Improvised lines that aren't in the script, missing scenes, and numbers that don't match get reported as a table before the edit, for you to decide on.

💡 WHICH FLOW TO USE

To get something already clear in your head out fast, use improvised recording (sections 3–5) — the recording becomes the storyboard's material. For a polished tutorial or demo, use script-first filming (this section) — the storyboard becomes the plan for the recording.

📼 TWO FILMING LANES

Short-form full shoot (9:16) is the flow above — you film it in one pass, ingest builds the alignment (alignment.json), and the edit places cuts in the silences. YouTube long-form (16:9) mixes filmed scenes with generated ones in one episode, so you film each scene separately and save it under the filename the script assigns — there's no alignment step, because the filename is what pairs a clip with its scene. Which lane you're in is decided along with the format while writing the storyboard, and the files to shoot are listed in the "What to film today" table at the top of script.md.

For the details (all the filming rules, alignment drift reports, the edit's screen layout, troubleshooting), see the dedicated guide, Short-form from a shooting script.

7.Troubleshooting and tuning knobs

SymptomWhat to do
Recording won't start System Settings → Privacy & Security → allow your terminal app under Screen Recording and Microphone, then retry.
Proper nouns or jargon misheard Say "it heard ○○ as △△". If it's widespread, reinforce the WHISPER_PROMPT glossary and re-transcribe (cheapest); if it's a handful, correct them against screen OCR.
Sentences you never said whisper hallucination — it invents sentences over silent stretches. The automatic filter removes most of them; point out any that survive.
Too many / too few scenes Ask for a boundary recompute — the --min-scene (default 8s) and --max-scene (default 45s) knobs (fast, since it reuses the raw signals).
Scrolling read as a screen change Raise SCENE_THRESH from 0.04 to 0.15 and rerun. False positives during speech are harmless anyway — they don't count toward the boundary score.
Pauses not detected in a quiet room Lower SIL_DB from -35dB to -40dB and rerun.

What each knob means and where its default comes from is in skills/ingest/references/timeline-schema.md. All of these adjustments happen if you just describe the symptom to Claude — you don't have to memorize the knob names.
