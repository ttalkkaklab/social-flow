1.전체 그림 — 무엇이 어떻게 이어지는가

핵심 아이디어: 웹 조사 대신 녹화가 콘텐츠의 1차 소스가 된다. 화면을 보여주며 말한 내용이 문장별 타임스탬프가 달린 timeline.md 로 정리되고, 스토리보드 스킬이 이것을 재료로 씬을 설계한다.

초록 테두리가 사용자 차례, 나머지는 Claude 가 자동으로 진행한다. 승인 게이트는 두 곳 — 스토리보드 승인(제작 전)과 게시 승인(공개 전)이다.

2.준비 (최초 1회)

2-1. 플러그인 로드

이 레포를 플러그인으로 로드한 Claude Code 세션에서 시작한다:

claude --plugin-dir /path/to/social-flow

2-2. 전제 조건 확인

항목확인 방법없을 때
whisper.cpp command -v whisper-cli brew install whisper-cpp
STT 모델 (1.5GB) ls ~/.cache/whisper-cpp/ggml-large-v3-turbo.bin huggingface ggerganov/whisper.cpp 에서 다운로드
화면 기록 · 마이크 권한 첫 녹화 시도 시 자동 확인됨 시스템 설정 → 개인정보 보호 및 보안 → 화면 기록 / 마이크에 터미널 앱 허용
ffmpeg · python3 command -v ffmpeg python3 brew install ffmpeg
✓ 한 번만 깔면 끝

whisper.cpp 와 모델은 처음 한 번만 설치하고, 화면 기록·마이크 권한도 처음 한 번만 허용한다. 그다음부터는 바로 3장으로 넘어가면 된다.

2-3. 채널 만들기

콘텐츠는 data/[채널]/episodes/[주제]/ 구조로 쌓인다. 채널이 아직 없으면 프로파일부터 만든다 (채널 톤 · 도메인 용어 · 비주얼 테마가 여기 기록된다):

/social-flow:channel add 재테크

채널명은 폴더 이름으로 쓸 영문 slug 로 바뀐다 — 아래 예시의 money 가 그 slug 다. 이후 명령에 넣는 채널은 원래 이름이 아니라 slug 다.

3.녹화하며 말하기

사용자

녹화 시작

/social-flow:ingest money record

Claude 가 screencapture 로 화면+마이크 녹화를 시작하고 "말씀하시면서 시연하세요"라고 알린다.

사용자

말하며 시연

  • 마이크에 대고 설명하면서 화면을 조작한다 — 보여주는 것과 말하는 것이 곧 콘텐츠 재료다.
  • 화제를 바꿀 때 1초 이상 말을 멈추고 화면을 전환한다 — 이 습관 하나가 씬 경계 정확도를 좌우한다. 긴 쉼 + 화면 전환이 겹친 지점이 씬 경계로 인식된다.
  • 끝나면 채팅에 "녹화 끝" 이라고 입력한다.
🖥 녹화 범위는 메인 모니터 하나

녹화는 시스템 설정에서 메인으로 지정한 모니터만 찍는다. 모니터가 둘 이상이면 시연은 메인에서 하고, 보조 모니터는 대본 메모 · 진행 확인 등 자유롭게 써도 녹화에 포함되지 않는다.

⚠ 녹화 전 체크

방해 금지 모드를 켠다 — 메인 화면의 알림 배너까지 전부 찍힌다. 이메일 · 계정명 · 토큰 · 금액 등 민감정보가 보이는 화면은 피한다 (찍히면 이후 검수 단계에서 잡아 보고해 주지만, 애초에 안 찍는 게 최선).

이미 녹화한 파일이 있다면

record 대신 파일 경로를 준다. 주제 slug 는 생략하면 전사 내용을 보고 제안받는다:

/social-flow:ingest money ~/Movies/demo.mov fx-app-intro

"녹화 끝" 이후는 Claude 가 순서대로 진행한다. 사용자가 개입할 지점은 마지막 확인뿐이다.

산출물

data/money/episodes/<주제>/recording/
├── raw/                 # STT · 무음 · 화면전환 원신호 (whisper 원문 보존)
├── timeline.json        # 기계용 씬 타임라인
├── timeline.md          # ★ 사람용 — 씬 표 + 문장별 타임스탬프 + 화면 설명 + 교정 로그
└── keyframes/seg-N.jpg  # 씬 대표 프레임

사용자가 할 일 세 가지

  1. 타임라인 확인 — 씬 수 · 씬별 요약이 제시되면 훑어보고 [스토리보드 진행 / 경계 조정 / 여기까지] 중 선택한다.
  2. 오인식 신고 — 전사가 이상하면 "○○를 △△로 잘못 들었어" 라고만 말하면 된다. 용어집을 보강해 재전사하거나, 화면 OCR 을 근거로 교정한다. 교정은 원문(→교정) 표기와 교정 로그로 남아 검수 가능하다.
  3. 민감정보 판단 — 화면에 개인정보가 찍힌 씬이 있으면 목록으로 보고된다. 해당 프레임을 영상 소재로 쓸지 여부만 판단하면 된다.
✓ 처리 시간 감각

large-v3-turbo 는 Apple Silicon 에서 대략 실시간의 3~5배 속도로 전사한다 — 10분 녹화면 STT 에 2~3분. 전체 파이프라인은 녹화 길이의 절반 안쪽으로 끝나는 게 보통이다.

5.콘텐츠로 만들기 — 스토리보드부터 게시까지

/social-flow:storyboard money <주제>   # 타임라인을 1차 소스로 씬 설계 → [승인]
/social-flow:produce money <주제>      # 9:16 영상 + 플랫폼별 텍스트 제작
/social-flow:publish money <주제>      # [승인] → Threads · IG · FB · YouTube 게시

storyboard 는 recording/timeline.md 가 있으면 웹 조사 대신 그것을 소재로 쓴다. 각 단계는 이전 단계 산출물을 검사하므로 — 스토리보드 미승인이면 produce 가, 제작 미완이면 publish 가 스스로 중단하고 이전 단계를 안내한다.

✗ 녹화 속 발언은 근거가 아니다

녹화에서 말한 수치(가격 · 세율 · 기한 등 시효성 값)는 주장이지 출처가 아니다. 스토리보드 단계에서 독립 출처 2개 교차 검증을 그대로 거친다. 구어 전사의 필러 · 말실수도 나레이션에 복사되지 않고 재구성된다.

6.대본 먼저 찍는 흐름 — 스토리보드 선행 촬영

3~5장의 흐름(즉흥 녹화 → 타임라인 → 스토리보드)을 뒤집은 모드다. 스토리보드·촬영 대본을 먼저 확정하고, 대본대로 녹화하면, Claude 가 녹화 원본을 잘라 최종 영상으로 편집한다. 말할 내용이 미리 설계되므로 품질이 고르고, 영상 화면·음성이 생성물이 아니라 실제 시연·육성이다.

사용자

촬영 수칙 (script.md 상단에도 인쇄돼 있다)

  • 대본은 보조 모니터에 띄운다 — 녹화는 메인 모니터만 찍는다.
  • 씬이 끝나면 말 멈추고 1초 → 화면 전환 — 이 지점이 편집 컷이 된다.
  • 시연 앱 폰트·창을 키운다(브라우저 ⌘+) — 세로 영상 폭 1080px 로 축소되므로 작은 글씨는 안 보인다. 초점이 화면 일부면 편집에서 그 영역만 확대한다.
  • 틀리면 녹화를 끊지 말고 그 씬 처음부터 다시 — 편집이 마지막 테이크만 쓴다.
  • 문장 암송은 불필요 — 단 핵심 수치·고유명사만 대본 그대로.

편집된 영상은 다크 캔버스 위에 씬 타이틀(상단) + 녹화 화면 밴드(중단) + 자막(하단) 구성이다. 자막은 대본이 아니라 실제 발화의 교정 전사에서 나오고, BGM 이 육성에 맞춰 자동으로 볼륨을 낮춘다(덕킹). 대본에 없는 즉흥 발화 · 누락 씬 · 수치 불일치는 편집 전에 표로 보고되고 사용자가 판단한다.

💡 어느 흐름을 쓸까

머릿속에 이미 정리된 내용을 빠르게 쏟아내려면 즉흥 녹화(3~5장) — 녹화가 스토리보드의 재료가 된다. 완성도 있는 튜토리얼 · 시연 영상을 만들려면 대본 촬영(이 장) — 스토리보드가 녹화의 설계도가 된다.

📼 촬영 레인은 둘

쇼트폼 전편 촬영(9:16) 은 위 흐름 그대로다 — 한 번에 쭉 찍고 ingest 가 정합(alignment.json)을 만들면 편집이 무음 자리에서 컷을 잡는다. 유튜브 롱폼(16:9) 은 촬영 씬과 생성 씬을 한 편에 섞기 때문에 씬마다 따로 찍어 대본이 지정한 파일명으로 저장한다 — 정합 단계가 없고 파일명이 곧 씬과의 짝이다. 어느 레인인지는 스토리보드를 쓸 때 포맷과 함께 정해지고, script.md 맨 위 「오늘 찍을 것」 표에 찍을 파일이 나열된다.

단계별 상세(촬영 수칙 전체 · 정합 이탈 보고 · 편집 화면 구성 · 문제 해결)는 전용 가이드 촬영 대본으로 쇼트폼 만들기를 참조한다.

7.문제 해결과 조정 노브

증상대응
녹화 시작 실패 시스템 설정 → 개인정보 보호 및 보안 → 화면 기록 · 마이크에 터미널 앱 허용 후 재시도.
고유명사 · 용어 오인식 "○○를 △△로 잘못 들었어"라고 알린다. 광범위하면 WHISPER_PROMPT 용어집을 보강해 재전사(비용 최소), 소수면 화면 OCR 근거 교정.
말한 적 없는 문장이 보임 whisper 환각 — 무음 구간에서 문장을 지어낸다. 자동 필터가 대부분 제거하지만 남아 있으면 해당 구간을 알려주면 된다.
씬이 너무 많다 / 적다 경계 조정 재실행을 요청한다 — --min-scene(기본 8s) · --max-scene(기본 45s) 노브로 재산출 (raw 신호 재사용이라 빠름).
스크롤이 화면 전환으로 오탐 SCENE_THRESH 를 0.04 → 0.15 로 올려 재실행. 단 발화 중 오탐은 경계 점수에 반영되지 않아 무해하다.
조용한 방에서 쉼이 검출 안 됨 SIL_DB 를 -35dB → -40dB 로 내려 재실행.

노브의 상세 의미와 기본값 근거는 skills/ingest/references/timeline-schema.md 를 참조한다. 이 조정은 전부 Claude 에게 증상만 말하면 알아서 적용된다 — 노브 이름을 외울 필요는 없다.

한 줄 요약 /social-flow:channel add 한 번 → /social-flow:ingest <채널> record → 말하며 시연 → "녹화 끝" → 확인만 하면 스토리보드 → 영상 → 게시까지 이어진다.
