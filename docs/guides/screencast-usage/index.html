촬영 대본으로 쇼트폼 만들기
— 스토리보드 선행 촬영 가이드

스토리보드와 촬영 대본을 먼저 확정하고, 대본대로 화면을 녹화하면, Claude 가 녹화 원본을 잘라 9:16 쇼트폼으로 편집한다. 영상의 화면은 실제 시연, 음성은 사용자의 육성이다 — 생성 배경도 TTS 도 쓰지 않는다.

1.전체 그림 — 즉흥 녹화와 무엇이 다른가

즉흥 녹화 흐름(ingest 가이드)은 녹화가 스토리보드의 재료다. 이 흐름은 반대로 스토리보드가 녹화의 설계도다 — 말할 내용과 보여줄 화면이 미리 설계되므로 완성 품질이 고르고, 편집도 대본 기준으로 정확해진다.

2.준비 (최초 1회)

전제 조건은 즉흥 녹화 흐름과 같다 — whisper.cpp · STT 모델 · 화면 기록/마이크 권한 · ffmpeg. 상세 확인 방법은 ingest 가이드 2장을 그대로 따른다. 채널(/social-flow:channel add)도 미리 있어야 한다.

✓ 이 머신은 준비 완료

whisper.cpp · 모델 · 권한이 이미 설치·허용돼 있다 (2026-07-29 실측). 바로 3장으로 넘어가면 된다.

3.1단계 — 스토리보드·촬영 대본 만들기

사용자

촬영 모드로 스토리보드 요청

/social-flow:storyboard 재테크 "홈택스 연말정산 미리보기" 촬영 대본으로

"촬영 대본으로", "내가 녹화할게"처럼 직접 시연할 의사를 밝히면 촬영 모드로 진행된다 (애매하면 Claude 가 물어본다).

Claude

조사 → 씬 설계 → 촬영 대본 저작

  • 자료조사·사실검증은 일반 스토리보드와 동일 — 시효성 수치는 독립 출처 2개 교차 검증을 통과한 것만 대본에 들어간다.
  • 씬별로 보여줄 화면 · 말할 문장 · 전환 신호 · 목표 길이를 설계하고 storyboard/script.md(촬영 대본)로 정리한다. 씬 이미지 생성은 없다 — 화면은 촬영에서 나온다.
  • 씬 목표 길이는 8~20초 — 말속도(초당 5~6자)로 역산해 문장 수가 잡힌다.
사용자

대본 승인 (승인 게이트 1)

씬 수 · 커버 제목 · 핵심 수치·출처를 보고 [승인 / 수정 요청 / 보류]를 고른다. 승인 전에는 촬영을 안내하지 않는다. 승인되면 다음 명령이 안내된다:

/social-flow:ingest 재테크 record "홈택스 연말정산 미리보기"

4.2단계 — 대본 보며 촬영하기

녹화는 메인 모니터만 찍는다. 대본(script.md)을 보조 모니터에 띄워 놓고 보면서 말하면 된다 — 대본 화면은 녹화에 포함되지 않는다.

촬영 수칙 5가지 (script.md 상단에도 인쇄돼 있다)

  • 씬이 끝나면 말 멈추고 1초 → 화면 전환 — 이 무음+전환 지점이 편집 컷이 된다. 이 습관 하나가 편집 정확도를 좌우한다.
  • 시연 앱의 폰트·창을 키운다 (브라우저 ⌘+) — 세로 영상 폭 1080px 로 축소되므로 작은 글씨는 안 보인다.
  • 틀리면 녹화를 끊지 말고 그 씬 처음부터 다시 말한다 — 편집이 마지막 테이크만 쓰고 앞 테이크는 버린다.
  • 문장을 정확히 암송할 필요 없다 — 자연스럽게 말하되 핵심 수치·고유명사만 대본 그대로 (자막·사실검증의 기준값이다).
  • 방해 금지 모드 켜기 — 메인 화면의 알림 배너까지 전부 찍힌다. 계정명·이메일이 보이는 화면은 대본의 "화면" 항목에서 미리 피하도록 설계돼 있다.

끝나면 채팅에 "녹화 끝"이라고 입력한다. 이후 전사(STT)·타임라인 생성은 즉흥 녹화 흐름과 동일하게 자동으로 돈다 (10분 녹화 기준 2~3분).

5.3단계 — 정합·편집·게시

Claude

대본 정합 — 녹화와 스토리보드 씬 매칭

  • 전사 타임라인과 대본을 대조해 씬별 컷 구간을 잡는다 (recording/alignment.json). 컷은 항상 무음 안에 놓인다 — 발화 중간에서 잘리지 않는다.
  • 같은 씬을 여러 번 말했으면 마지막 테이크 채택.
  • 씬별 키프레임을 보고 시연 초점이 화면 일부면 그 영역만 확대(crop) 하도록 잡는다 — 5K 화면 전체를 넣으면 글씨가 4.7배 축소돼 안 읽힌다.
  • 자막은 대본이 아니라 실제 발화의 교정 전사에서 나온다 (숫자·고유명사 원표기).
사용자

이탈 보고 확인 (승인 게이트 2)

대본에 없는 즉흥 발화 · 누락 씬 · 순서 바뀜 · 대본과 다른 수치·고유명사 발화가 있으면 표로 보고된다 — [부분 재촬영 / 씬 제외 / 그대로 채택]을 고르면 정합이 확정된다.

Claude

편집 빌드 + 플랫폼 텍스트

/social-flow:produce 재테크 "홈택스 연말정산 미리보기"
  • 씬별 컷 → 확대 → 9:16 합성 → 타이틀 오버레이 → 자막 번인 → BGM 덕킹(육성에 맞춰 자동 볼륨 다운) → 아웃트로 접합. 오디오·비디오 드리프트 0 을 빌드가 단언한다.
  • 폰 뷰포트 검수 · 플랫폼별 텍스트(Threads/IG/FB/YT) · 품질 게이트는 일반 제작과 동일하게 이어진다.
✗ 녹화 속 발언은 근거가 아니다

대본의 수치는 이미 교차 검증을 통과한 값이다. 촬영 중 말이 대본과 다르게 나왔다면 대본 쪽이 기준 — 재촬영하거나 자막을 교정할지 사용자가 정한다. 즉흥으로 말한 새 수치는 검증 없이 영상에 실리지 않는다.

이후 /social-flow:publish 의 게시 승인(승인 게이트 3)은 일반 흐름과 같다.

6.편집된 영상의 화면 구성

1080×1920 다크 캔버스에 세 층으로 합성된다:

y 190~460 씬 타이틀 키커 + 제목 (커버는 +핵심 수치)
녹화 화면 밴드
(씬별 컷 · 필요 시 확대)
“실제 발화의 교정 자막”
y 1380~1560 자막 밴드 · 하단은 플랫폼 UI 존
  • 타이틀(상단) — 스토리보드 씬 제목이 씬 내내 표시된다. 지금 어느 단계인지 소리를 꺼도 알 수 있다.
  • 녹화 밴드(중단) — 씬의 시연 화면. 전체 화면 또는 확대(crop)된 초점 영역. 축소가 3배를 넘으면 빌드가 가독 경고를 낸다.
  • 자막(하단) — 실제 발화의 교정 전사. IG 액션바·캡션 존을 피하는 위치에 번인된다.

7.문제 해결

증상 / 리포트대응
화면 축소 3배 초과 경고 확대 영역(crop)을 더 좁게 잡아 달라고 하거나, 시연 앱 폰트를 키워 해당 씬만 재촬영한다.
씬 길이 20초 초과 경고 씬을 둘로 나눠 달라고 하거나(정합에서 컷 추가), 발화를 압축해 재촬영한다. 대본 단계에서 씬을 잘게 설계하는 편이 싸다.
누락 씬 / 순서 바뀜 보고 그 씬만 다시 찍는다 — 새 녹화 파일로 ingest 를 다시 돌리면 해당 씬 컷만 교체된다. 전체 재촬영은 필요 없다.
재촬영했는데 앞 테이크가 쓰였다 정합 노트(테이크 채택 기록)를 보여 달라고 한 뒤 해당 씬의 컷 구간 수정을 요청한다.
고유명사 오인식 · 씬 경계 문제 전사·타임라인 계층의 문제 — ingest 가이드 7장의 노브(WHISPER_PROMPT 등)를 그대로 쓴다.
총길이 90초 초과 컷을 조이거나(씬별 앞뒤 여백 축소) 씬을 줄인다 — 60~75초가 권장 구간.

기술 계약(edit.json · alignment.json · 빌드 게이트)의 상세는 skills/produce/references/screencast-pipeline.md 와 skills/ingest/references/timeline-schema.md §alignment.json 에 있다. 사용자는 증상만 말하면 된다.
