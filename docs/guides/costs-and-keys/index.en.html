Where the money goes, and where it doesn't

Video and music default to billed APIs. Images and speech can be generated on-device for free on Apple Silicon, and transcription has no paid path at all. When MLX Core is up, mlx_video_generate and mlx_music_generate are the $0 understudy — the defaults stay Veo/Seedance and Lyria.

Each free lane has something it can't do, though. That list of limits is also the list of things worth paying for.

The default pipeline makes zero video calls. It fills the runtime with still images under an ffmpeg Ken Burns move, plus narration, subtitles, and BGM, so generated video only appears when a human or the metrics promote one slot. That means a real episode is usually just one cover image plus one BGM clip — worked out in §8.

Every price on this page comes from one file, skills/autoproduce/references/prices.tsv. Each line carries an evidence grade, and this page repeats that grade rather than flattening it.

  • official read directly off the vendor's pricing page
  • derived computed from an official value — a resolution ratio applied, or an example price divided by seconds
  • unconfirmed the vendor publishes no price. Written as ?, and the calculator refuses to return a verdict when it meets that line

Images

Free — image_local_generate

Z-Image Turbo running on-device through mflux/MLX. No key, no network, no billing — electricity only.

  • Apple Silicon only
  • uv tool install --python 3.12 mflux
  • First call downloads about 31GB of weights
  • 9:16 is 1088×1920 (both edges must be multiples of 16)

Paid — gpt_image_text2img · img2img

OpenAI GPT Image. Billed per image, and the quality tier changes the price a lot.

  • Needs OPENAI_API_KEY
  • Renders text inside the image properly
  • Arbitrary dimensions · up to 16 reference images · mask inpainting

The wall on the free lane — text in pictures

The local engine can't produce an image with text in it. Korean glyphs come apart into scattered jamo and lookalike characters. Measured: "딸깍연구소" came out as "달닥연구소".

So the cover and any frame carrying text are pinned to the paid lane. Text-free pictures — scene backgrounds and the like — all default to local.

Local generation goes in the ledger too, as image.local. The value is 0 so the total doesn't move, but a key the calculator doesn't recognize stops it with exit 1 and blocks the whole episode's tally.

On a machine without mflux, scene backgrounds fall back to gpt_image_text2img at quality low. At $0.007 each that's small, but 2–4 of them add $0.014–0.028 to an episode — and that number matters against the cap in §8.

Video

Generated video has no free lane. This plugin ships no on-device video engine, and both hosted engines bill by the second.

The default is still zero video calls. The economy tier fills 60 seconds with stills and Ken Burns. Veo makes at most 8 seconds per call, so covering a whole episode with generated footage means pulling eight clips and stitching them — and the stitching layer is needed anyway. That leaves exactly one question: which single slot gets generated video.

Veo 3.1 — per second, audio always on, lengths on a 4/6/8s grid

Veo runs on GEMINI_API_KEY and always includes audio — it can't be turned off, and there's no free tier. Lengths are locked to a 4/6/8-second grid, and 1080p and 4K are 8-second only.

A 4-second cut still pays for 8 seconds. The API has no way to generate 4 seconds at 1080p. Comparing per-second prices alone understates real spend, which is why the ledger records generated length, not used length.

Every Seedance line is derived because the vendor bills in tokens. These are the official docs' "5s · 16:9" example price divided by 5; 9:16 only swaps width and height, so the token count and the price are the same. The bill's real source of truth is the response's completion_tokens, so record that value in the ledger's memo column. Limited-time discounts are deliberately not baked in — they'd turn into silently wrong numbers the day the promo ends.

Seedance 2.x doesn't open on a key alone. The Dreamina Seedance 2.5 and 2.0 family needs an account balance over $30, or a resource pack, before it activates. The 1.5 pro and 1.0 families have no such gate. Separately, every model has to be switched on once under the console's Model activation, or task creation fails with ModelNotOpen.

The one escalation slot — when video is worth paying for

The only slot the autonomous loop can promote on its own is the opening b-roll in the segment after the cover. The schema allows two slots, but the second one is a call a human makes while approving the storyboard. The cover itself never escalates — Veo can't write Korean, so the hook title is code-rendered.

The escalation verdict is a trend, not an absolute threshold. With a fixed threshold, a channel whose measured numbers sit permanently above it escalates every episode, which is 5× the cost every episode — and that money doesn't fix the problem, because the b-roll attaches after the cover while the skipping happens inside it.

PlatformMetricEscalation verdict
YouTubeaverageViewPercentagelast-3-episode average down 5+ points from the previous 3
Instagramreels_skip_ratelast-3-episode average up 5+ points from the previous 3
Bothunder 6 published episodesno comparison window, so no escalation

Escalation also freezes right after a hook-contract revision. Once the hook changes, earlier episodes' metrics are no comparison, so the loop runs economy baseline only until 3 new-baseline episodes accumulate.

Speech (TTS)

Free — tts_local_generate

Supertonic 3, on-device. No key, no network. Measured at 6.3× real-time on CPU alone.

  • pip install supertonic
  • First call downloads 385MB of weights into ~/.cache/supertonic3 (about 24s)
  • 10 voices · 31 languages · mono 44.1kHz
  • Installed in a virtualenv? Set SUPERTONIC_PYTHON

Paid — tts_generate · tts_multi_speaker

Gemini TTS. Priced per 1,000 characters.

  • Needs GEMINI_API_KEY
  • Takes acting direction (stylePrompt)
  • 30 voices · 2-speaker dialogue · mono 24kHz

Third lane — ElevenLabs (tts_elevenlabs_generate · tts_elevenlabs_dialogue)

Paid, opt-in per channel (engine: elevenlabs in profile §2), needs ELEVENLABS_API_KEY. Dearer than Gemini — $0.10 per 1,000 characters on multilingual_v2 and v3, $0.05 on flash and v3 conversational, the same on every plan (the vendor's metered count in the character-cost header sits below the raw character count — Korean 18 characters billed as 10, measured) — so it is not the narration default. Three things only it does: inline acting with audio tags on eleven_v3 ([whispers], [laughs] exactly where the delivery changes), a dialogue scene with up to 10 voices in one request, and per-character timestamps for subtitle sync. The default output is mono 24kHz WAV — the same spec as the Gemini lane, so the builder takes it as-is; never pick an mp3 format for narration, the builder reads non-RIFF files as raw PCM. Korean quality depends on the voice more than the model: English-trained premade voices carry an accent, Korean Voice Library voices (paid plans) don't.

Free-tier audio is non-commercial and the vendor asks for attribution; a monetized channel needs Starter ($6/month) or above. The account's plan is visible from tts_elevenlabs_voices when the key carries user_read.

Licensing — read this if the channel is commercial

Supertonic's code is MIT and its weights are OpenRAIL-M. Commercial use is allowed, but with use-based restrictions attached: you can't use it for the purposes the license prohibits, and if you redistribute it, the same restrictions travel with it. If you're running a monetized channel, read the license text once.

Gemini actually bills in audio tokens (25 per second), not characters. The values above take 1M characters at the measured Korean speech rate of 6.55 chars/s and fold the result back into a per-1,000-character price, which is why they're derived.

Mixing the two engines in one video breaks on sample rate. Local is 44.1kHz and Gemini is 24kHz, so concatenating them directly fails. Mixing needs a resampling step, and the automated authoring path sidesteps the problem by using one engine per video.
Never switch a running channel's engine. Moving a gemini channel to local because local is free means the narrator becomes a different person partway through the channel's run. The engine changes only when you edit profile.md §2 yourself — automated authoring has an absolute rule forbidding it.

Hence the division of labor: narration bodies go local, and only cuts that need acting go to Gemini. Intro lines and character dialogue are where the paid engine earns its price.

Transcription (STT)

Transcription is free-only. There is no paid STT in this plugin. The ingest skill, which turns a screen recording into source material, runs whisper.cpp on-device.

It costs nothing, but it does need two things installed.

  • whisper.cpp itself — brew install whisper-cpp
  • The model file — download ggml-large-v3-turbo.bin (1.5GB) from huggingface.co/ggerganov/whisper.cpp into ~/.cache/whisper-cpp/. Keep it elsewhere and point WHISPER_MODEL at it.

Recording also needs Screen Recording and Microphone permission for your terminal app (System Settings → Privacy & Security). Without them the recording step stops.

The tuning knobs are documented at the top of skills/ingest/references/transcribe.sh — language (WHISPER_LANG, default ko), glossary injection (WHISPER_PROMPT), silence threshold (SIL_DB), and scene-change sensitivity (SCENE_THRESH).

Music

Default BGM is Lyria, on GEMINI_API_KEY. When MLX Core is up, mlx_music_generate is the $0 understudy — the default stays Lyria.

KeyUnitUSDGradeNotes
music.lyria-clipclip0.04officialmusic_generate_clip — fixed 30s
music.mlxsecond0.000officialmlx_music_generate — on-device, electricity only
music.lyria-realtimesecond?unconfirmedmusic_generate — no row in the official price table

The default BGM path is music_generate_clip: one 30-second clip that the builder stretches with -stream_loop -1. That's what the economy tier uses, and it's the only music item with a confirmed price.

Lyria RealTime has no published price. It's an experimental model with no row in the official price table at all (checked 2026-08-15). But the manual produce skill builds its BGM with that tool, at 90 seconds, so an episode made through the manual path ends its cost report at exit 1.

That's correct behavior, not a bug. Write an unknown value as 0 and the episode's cost silently shrinks. The calculator still prints the total of the remaining items, so report it as "total $X + 1 item excluded from the tally (BGM)". Don't write it as 0, and don't delete the line.

Research — quota, not money

What one episode costs

Three configurations people actually run, computed from prices.tsv. The arithmetic is spelled out so you can redo it when a price changes.

Configuration A — economy tier · local narration (the automated default)

The cover background is a paid image at quality high; the 2–4 scene backgrounds are local, narration is local, and there's one BGM clip.

Cover image image.gpt-image-2.high × 1 = 1 × $0.220 = $0.220
Scene backgrounds image.local × 3   = 3 × $0.000 = $0.000
Narration tts.local, 400 chars       = 0.4 × $0.000 = $0.000
BGM music.lyria-clip × 1          = 1 × $0.04  = $0.040
─────────────────────────────
total $0.26

Configuration B — economy tier · Gemini narration

For channels whose profile pins the narration engine to gemini. A 400-character narration adds this much.

Images and music from A                = $0.260
Narration tts.gemini-flash, 400 chars = 0.4 × $0.038 = $0.0152
─────────────────────────────
total $0.2752 — call it $0.275
Character counts are divided by 1,000. 400 characters is 0.4. Write 400 and that line inflates 1,000×. On a local channel the price is 0 so nothing shows; on a Gemini channel it shows up at the size of the invoice.

Configuration C — the same, plus one Veo escalation

The opening b-roll slot promoted to Veo lite 1080p, 8 seconds.

Configuration A (local narration)   = $0.260
b-roll veo.lite.1080p, 8s       = 8 × $0.08 = $0.640
─────────────────────────────
total $0.90  (on top of configuration B, $0.915)

The model-ladder doc quotes this combination at about $0.91 per episode, rounding the economy baseline to $0.27. Either way it's three times over the default $0.30 cap.

How that meets the cap

The growth plan's max_cost_per_video defaults to $0.30. With the cover pinned at high, that value passes the economy tier and blocks every Veo escalation. To let one through, you raise the cap in the plan to $1.00 or more. The autonomous loop never raises it on its own — while the escalation condition holds, it keeps building at economy baseline and says so in the completion report.

Machines without mflux

With no local image engine, scene backgrounds fall back to gpt low and the old arithmetic returns.

Narration engine2 low images3 low images4 low images
Local$0.274$0.281$0.288
Gemini (400 chars)$0.289$0.296$0.303 — over the cap

A Gemini channel using 4 low images busts the default $0.30 cap, so use at most 3 in that case. With mflux installed, image count stops being a cost question — pick 2–4 purely on screen rhythm.

The zero-cost configuration

The pipeline runs with no paid keys at all. Here's what you get and what you give up, stated plainly.

Still works

  • Scene background images — local generation
  • Narration — local TTS
  • Transcription and timelines — whisper.cpp
  • Subtitles, Ken Burns, the build — ffmpeg
  • Research — built-in WebSearch
  • Per-platform copy and the style gate

What you give up

  • A proper cover — no text-bearing frames
  • BGM — the video comes out silent under the voice
  • Generated video — the default is zero calls anyway, so this one barely stings
  • Acted, emotive narration
  • Naver and SerpApi research

The two losses that actually hurt are BGM and cover quality. Generated video was never in the default build, so its absence changes little. But a short-form video with no music sounds thin, and the cover doubles as the thumbnail — miss the hook there and the viewer scrolls past.

There's a middle step. Add just OPENAI_API_KEY and the cover comes back, at $0.22 an episode. Add GEMINI_API_KEY on top and BGM joins it, at $0.26. Those two keys are the whole economy tier.

Key setup, one at a time

Keys go in as shell environment variables. .mcp.json passes your shell environment straight through to the server, so no key value ever lands in a committed file. The variable list and its comments live in .env.example at the repo root.

# Working from .env.example
cp .env.example .env
$EDITOR .env
set -a && . ./.env && set +a

Writing export lines into ~/.zshrc works the same way. Either way, a session freezes the environment it started with — add a key and you have to restart claude for it to take effect.

OPENAI_API_KEY production

platform.openai.com/api-keys

Unlocks — gpt_image_text2img · gpt_image_img2img. Covers and text-bearing frames.

export OPENAI_API_KEY="sk-..."

Confirm it works — listing models isn't billed.

curl -s https://api.openai.com/v1/models \
  -H "Authorization: Bearer $OPENAI_API_KEY" | head -c 200

The key alone isn't enough. With no credit on the account, image generation fails — add a payment method and credit under Billing in the OpenAI dashboard. A 401 or 403 from the check above means the key is wrong or billing isn't attached.

GEMINI_API_KEY production

aistudio.google.com/apikey · GOOGLE_API_KEY works as an alias

Unlocks — veo_* (generated video) · tts_generate and tts_multi_speaker (acted speech) · music_* (BGM). All three share this one key.

export GEMINI_API_KEY="..."

Confirm it works

curl -s "https://generativelanguage.googleapis.com/v1beta/models?key=$GEMINI_API_KEY" | head -c 200

A JSON model list means you're set. A 401 or 403 means the key is wrong or billing isn't attached.

ARK_API_KEY optional

ai.byteplus.com/ark — BytePlus ModelArk

Unlocks — seedance_*, the second video engine. Without it, Veo still runs on GEMINI_API_KEY.

export ARK_API_KEY="ark-..."
# Leave the region endpoint alone — the video models only exist in ap-southeast-1
# export ARK_BASE_URL=https://ark.ap-southeast.bytepluses.com/api/v3

There are three gates, and calls only work once you're past all of them.

  1. Use the API Key the console issues separately (it starts with ark-), not the signing AccessKeyId/SecretAccessKey.
  2. Switch your models on under Model activation in the console. Skip this and task creation fails with ModelNotOpen. The first activation asks for TOS, VPC, and ML-platform cross-service authorization, which the account owner has to click.
  3. The Dreamina Seedance 2.5/2.0 family additionally needs a balance over $30 or a resource pack.

Confirming — there's no read-only check endpoint, so lean on the tool's own error message, which distinguishes the three gates above. A real generation call is a billed call.

ELEVENLABS_API_KEY optional

elevenlabs.io/app/settings/api-keys — ElevenLabs

Unlocks — tts_elevenlabs_generate · tts_elevenlabs_dialogue · tts_elevenlabs_voices, the third speech lane. Without it, Gemini (tts_generate) and the on-device engine keep running.

export ELEVENLABS_API_KEY="..."

Keys can be restricted per permission. Synthesis needs text_to_speech; the voice listing needs voices_read; the plan-usage line needs user_read. A key missing one of these fails with missing_permissions naming the permission — that is the key's scope, not a wrong key.

Confirming — with voices_read:

curl -s -H "xi-api-key: $ELEVENLABS_API_KEY" "https://api.elevenlabs.io/v2/voices?page_size=1" | head -c 200

A JSON voice list means you're set; invalid_api_key means the value is wrong. A synthesis-only key has no free check — the first tts_elevenlabs_generate call is the check, and it bills a handful of characters.

SERPAPI_API_KEY optional

serpapi.com — 250 free searches/month

Unlocks — serp_web_search · serp_news_search · serp_naver_search · serp_image_search · serp_trending_now, and sns_issue_scout.

export SERPAPI_API_KEY="..."

Without it, research falls back to the built-in WebSearch. Confirming means calling serp_web_search once — and that once comes out of the 250.

NAVER_CLIENT_ID · NAVER_CLIENT_SECRET optional

developers.naver.com — 25,000 free calls/day

Unlocks — naver_search. Register an application and apply for the Search API to get both values.

export NAVER_CLIENT_ID="..."
export NAVER_CLIENT_SECRET="..."

The allowance is generous and it's the first tool for Korean topics, so it's worth setting if you make Korean-language content. Confirm it by calling naver_search once — well inside the free tier.

DATA_GO_KR_API_KEY optional

data.go.kr My Page — Korea's open-data portal

Unlocks — datago_file_fetch · datago_api_call. Dataset search, detail, and file download (datago_search · datago_detail · datago_file_download) work with no key.

export DATA_GO_KR_API_KEY="..."
The key alone doesn't open anything. Each individual API needs its own usage application on the portal (usually auto-approved). If the key is set and one specific API still fails, that application is almost always what's missing.

YOUTUBE_API_KEY optional

console.cloud.google.com/apis/credentials

Unlocks — the public-query path of youtube_topic_scout. Unlike OAuth it doesn't spend your channel's quota. Without it the scout falls back to channel OAuth (youtube.readonly).

export YOUTUBE_API_KEY="..."

Create an API key in the Cloud console and enable YouTube Data API v3 in the same project. Issuing the key and enabling the API are separate gates — you need both before calls go through.

Platform tokens are files, not keys. Threads, Instagram, Facebook, and YouTube credentials live as files under ~/.config/social-flow/<channel-slug>/ (chmod 600), not as environment variables. Issuance is covered in the getting-started guide and in skills/publish/references/token-setup.md. Skip the whole thing if you don't need publishing or the growth loops.

Installing the on-device engines

The three free lanes each install once. All three download weights on their first call, so know going in that the first run takes a while.

mflux — local image generation

image_local_generate · Z-Image Turbo

Prerequisite — Apple Silicon Macs only (it's MLX-based). On Intel Macs and Linux this lane doesn't exist, so images go to gpt_image_text2img.

uv tool install --python 3.12 mflux

First call — downloads about 31GB of weights into ~/.cache/huggingface. The server detects the first call and adds a separate download allowance to the timeout, so a slow download won't get killed mid-way.

Confirm it — check the executable landed.

ls ~/.local/bin/mflux-generate-z-image-turbo

Installed elsewhere? Point MFLUX_ZIMAGE_BIN at the executable. There's deliberately no PATH-scanning fallback — silent auto-discovery turns into "what worked yesterday gives different results today".

export MFLUX_ZIMAGE_BIN=~/.venvs/mflux/bin/mflux-generate-z-image-turbo

Measured on an M4 Max at 9 steps: 1024×1024 takes 116–197s, 1088×1920 takes 443s. Peak memory runs 32–39GB.

Supertonic — local TTS

tts_local_generate · Supertonic 3

Prerequisite — a Python runtime.

pip install supertonic

First call — downloads 385MB of weights into ~/.cache/supertonic3, about 24 seconds.

Installed in a virtualenv? Put that interpreter's path in SUPERTONIC_PYTHON. No auto-discovery here either — picking up a different venv per repo changes the voice.

export SUPERTONIC_PYTHON=~/.venvs/tts/bin/python

Confirm it

$SUPERTONIC_PYTHON -c "from supertonic import TTS; print('ok')"

If the package is missing, calling the tool returns an error with install instructions in it. Licensing is in §4 — MIT code, OpenRAIL-M weights.

whisper.cpp — local STT

transcription for the ingest skill
brew install whisper-cpp

The model — get ggml-large-v3-turbo.bin (1.5GB) from huggingface.co/ggerganov/whisper.cpp and put it in ~/.cache/whisper-cpp/.

Confirm it — both lines have to pass before ingest will start.

command -v whisper-cli
ls ~/.cache/whisper-cpp/ggml-large-v3-turbo.bin

Model somewhere else? Point WHISPER_MODEL at it.

export WHISPER_MODEL=~/models/ggml-large-v3-turbo.bin

Recording also needs Screen Recording and Microphone permission for your terminal app.

Never mix the two. Merge them into one file and the post-hoc report counts the same spend twice. Conversely, mid-run re-verdicts also use the estimate file — when you decide to regenerate something, put that line on the estimate and rerun the cap check. Judge against the actual ledger and the spend that hasn't gone out yet (BGM, narration) is missing, the total looks small, and a cap-busting regeneration passes.

A ledger line is three tab-separated columns.

image.gpt-image-2.high	1	storyboard: cover background scene-1
image.local	3	storyboard: points backgrounds scene-2~4
veo.lite.1080p	8	produce: b-roll a1 — 8s generated, 4s used
tts.local	0.412	produce: narration, 412 chars
music.lyria-clip	1	produce: BGM 30s

The quantity is an amount in the unit, not a count. TTS is characters ÷ 1,000; Veo is generated length, not used length; Seedance is the requested seconds as-is. Log discards too — images regenerated after a review, clips redrawn because you didn't like them, TTS rerun after failing a length check. They don't reach the deliverable, but they do get billed.

The calculator — read the exit code literally

REF=${CLAUDE_PLUGIN_ROOT}/skills/autoproduce/references
$REF/cost-report.sh .work/cost-estimate.tsv --cap 0.30; echo "cost_exit=$?"
ExitMeaningWhat to do
0ok (and within the cap, if one was given)The total is the episode's cost
1verdict unavailableCopy the !! lines into your report verbatim
2over the capCancel the escalation, back to economy baseline
3input errorFix the path or format, then rerun
Never read 1 as a pass. Hit an unknown key or an unconfirmed price (?) and the total can look like 0. That doesn't mean free — it means the math didn't happen.

Exit 1 has two causes with different responses. !! unknown key is our mistake: align the key with prices.tsv and rerun. !! price unconfirmed is an item the vendor doesn't publish a price for, and right now that's exactly one, music.lyria-realtime — report those as "total $X + 1 item excluded from the tally (BGM)".

Never report a $0 total as-is either. If storyboard/images/*.png exist but the ledger is empty, they weren't made for free — the logging was skipped. Count the files, backfill the ledger, and say you backfilled it.

Daily and weekly caps

The three cap values live in the growth plan's autoproduce: block.

SettingDefaultWhat it stops
max_cost_per_video$0.30One episode — passes economy tier, blocks Veo escalation
daily_cost_cap$0.60One day, channel-wide
weekly_cap$2.00One week, channel-wide

The running totals accrue in data/<channel>/growth/autoproduce.json, and the growth loop reads that file against the caps above before it starts authoring. Episode counts are per caller (plan); money is channel-wide — episode caps belong per platform, but the money comes out of the same wallet whichever loop spent it. Separately, 2 episodes per platform loop per day is a hard cap, counting successes and failures together.

When prices change

One file to edit: skills/autoproduce/references/prices.tsv. The calculator reads only that file, and the explanatory docs never copy the numbers — write a value in two places and one of them always goes stale.

  • Keep the evidence grade (official / derived / unverified) and the source on the same line.
  • Leave unconfirmed values as ?. A ? fails the report and summons a human — fill in an invented number and the cap is silently disarmed.
  • Vendor prices move. Reopen the sources every quarter.
