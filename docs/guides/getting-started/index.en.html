GETTING STARTED

From install to your first video

social-flow is a Claude Code plugin that takes one topic, makes a short-form video and the social posts to go with it, and — once you approve — puts them on your accounts. Install takes five minutes; the first video takes four commands.

What this tool does

Putting up one video usually means all of this: find the material, write the script, get the pictures, record a voice, add subtitles, then write a different post for every platform. social-flow bundles that into four commands.

STEP 1 Channel decide once who you're talking to and in what voice
STEP 2 Storyboard research, then a script and scene images
STEP 3 Produce one video plus per-platform text
STEP 4 Publish you look it over, approve, and it goes up

Each step needs the one before it. Skip ahead and it stops right there and tells you what's missing.

Three things worth knowing up front

  • There are two video formats. The default is one 9:16 portrait build (1080×1920 · 30fps), exported for Reels, Shorts, and Threads. YouTube long-form is 16:9 landscape (1920×1080). You pick which one while writing the storyboard, and a single window.FORMAT line in scenes.js fixes the canvas, length, and subtitle values for every step after it.
  • The same post never gets pasted in several places. The facts stay the same; the sentences get rewritten per platform. Threads is casual spoken Korean, YouTube is a searchable title and description — different jobs.
  • The default flow has two human approvals. One when the storyboard is settled, one right before anything goes public. The growth loops are the exception — the grow-* skills run your account on a growth plan you approve once, and that plan stands in for per-post approval. Inside its scope they post without asking, so keep the scope tight when you approve it.

This assumes a Mac or Linux terminal with Claude Code already installed.

Install

1

Install from the marketplace

Two lines inside Claude Code and you're done. The server ships as a single dependency-inlined bundle, so there is nothing to download or build.

/plugin marketplace add ttalkkaklab/social-flow
/plugin install social-flow@social-flow

Prefer the terminal? claude plugin marketplace add ttalkkaklab/social-flow followed by claude plugin install social-flow@social-flow does the same thing.

The repo is public. It installs without authentication, and the license is Apache 2.0.
2

Pick a working folder and start Claude Code inside it

Finished videos and scripts pile up in a data/ folder, and that folder is created where you started Claude Code — not where you cloned the plugin. So pick one working folder and always start there.

# e.g. one working folder under your home directory
mkdir -p ~/social-work && cd ~/social-work
claude
3

(Optional) Clone it if you want to hack on the code

Only for people who plan to edit the skills or the server. Point Claude Code at your clone and that session runs the clone's code.

git clone https://github.com/ttalkkaklab/social-flow.git ~/social-flow
claude --plugin-dir ~/social-flow

It runs as-is; only after editing server/src do you need cd ~/social-flow/server && npm install && npm run check for the build and the self-check tests. They call no external API, so they pass without any keys.

It attaches outside Claude Code too. Grok CLI connects skills and the MCP tools with one line — grok plugin install https://github.com/ttalkkaklab/social-flow.git --trust (measured on grok 1.0.5). Codex CLI loads the 18 skills via codex plugin marketplace add ttalkkaklab/social-flow then codex plugin add social-flow@social-flow — MCP tools don't wire up yet as of codex 0.147.0. API keys travel the same shell-environment route as under Claude.
4

Check that it loaded

/mcp lists the connected servers. If social-flow is there with a list of tools, you're done.

Seeing only 42 tools is normal. Of the 51 total, the nine publish and insight tools show up only for platforms whose credential file exists. If you haven't connected an account yet, they're supposed to be missing.

Setting up API keys

The keys come in two groups that have nothing to do with each other. Stopping after either one still leaves you a usable tool.

  • Production keys — the video-making half. OPENAI_API_KEY and GEMINI_API_KEY are enough for a first video.
  • Platform credentials (Threads · Instagram · YouTube · Facebook) — optional. Set them up and the tool handles publishing and day-to-day account operation; skip them and the finished video and per-platform text land in output/, and uploading is the only part you do by hand.

Where the keys go

Keys go in as shell environment variables, not in a config file. Put them in ~/.zshrc (or ~/.bashrc) and open a new terminal.

export OPENAI_API_KEY="sk-..."     # cover and any frame with text
export GEMINI_API_KEY="..."        # generated video, acted narration, BGM

# everything below is optional
export NAVER_CLIENT_ID="..."       # Korean-language research
export NAVER_CLIENT_SECRET="..."
export SERPAPI_API_KEY="..."       # precision and international search
export ARK_API_KEY="..."           # the second video engine (Seedance)
export SUNO_API_KEY="..."          # sung songs / Suno loop beds (sunoapi.org, not Gemini)
export ELEVENLABS_API_KEY="..."    # third speech lane — acted cuts, 3+ speaker dialogue, timestamps
export DATA_GO_KR_API_KEY="..."    # data.go.kr API calls
Never write key values inside the repo. .mcp.json only passes your shell environment through to the server, so no committed file holds a key. If a value is missing, only the tools that need it say so — plainly, at call time — and everything else keeps working. A session carries the environment it was started with, so after adding one of these API keys, restart claude for it to take effect. Platform tokens are a different story — see below.

Two engines that need no key at all

On an Apple Silicon Mac, scene backgrounds and narration are made on the machine — no key, no network, no billing. They each need one install first.

  • image_local_generate (Z-Image Turbo) — uv tool install --python 3.12 mflux. The first call downloads 31GB of weights. It can't put text inside an image.
  • tts_local_generate (Supertonic 3) — pip install supertonic. The first call pulls 385MB of weights into ~/.cache/supertonic3 (about 24 seconds). If you installed it in a virtualenv, put that interpreter's path in SUPERTONIC_PYTHON. It has no acting or emotion controls, so intro lines and character dialogue go to tts_generate (Gemini) instead.

Platform credentials are optional

Threads, Instagram, YouTube, and Facebook tokens are set up one platform at a time. Connect YouTube alone and YouTube publishes itself while Threads and Instagram stay manual — it isn't all-or-nothing.

  • With them — publish posts straight to your accounts, and the grow-* skills run on /loop: comment replies, insight snapshots, keyword conversations, queue refills, posting. The scope is whatever the growth plan you approved once at init allows.
  • Without them — research, storyboard, images, voice, and the build all run as usual. produce writes the finished video and per-platform text to data/<channel>/episodes/<topic>/output/ and you upload those files yourself. The only consequences are that the nine publish/insight tools aren't listed and the growth loops have nothing to drive.

Tokens are files rather than environment variables, so adding one later needs no server restart. The next time the tool list is read, that platform's tools are there and the count moves from 41 toward 50. Account signup and token issuance are covered in section 6 below.

Checking that a key works

Two lines, before you spend anything on a video. Both are list calls, so neither is billed.

curl -s https://api.openai.com/v1/models \
  -H "Authorization: Bearer $OPENAI_API_KEY" | head -c 200

curl -s "https://generativelanguage.googleapis.com/v1beta/models?key=$GEMINI_API_KEY" | head -c 200

A JSON list of models means you're set. 401 or 403 means the key is wrong or no payment method is attached. For platform tokens, the sns_account_check tool checks them all at once — it never prints token values, only which account each one resolves to.

Making your first video

Say you run a personal-finance channel and want one video about exchange rates. Type the commands in order inside Claude Code.

1

Create the channel — once per channel

/social-flow:channel add "Money Talk"

The first thing it does is propose a kebab-case English slug for the channel name — here, something like money. That value becomes the directory name and the key for publish accounts, so a name in Korean or any other non-Latin script gets converted rather than used as is. From here on, the channel you type in commands is that slug, not the original name.

Then it asks a few questions — who's watching, what voice to use, where you publish — and writes the answers to data/money/profile.md. Every later step reads that file first and inherits the tone and voice from it.

The narration voice is also picked and pinned here. A channel whose voice changes every episode doesn't sound like one channel.

2

Write the storyboard — the longest step

/social-flow:storyboard money "July FX swings"

It asks about format first — 9:16 short-form by default, 16:9 if you want a chaptered YouTube long-form. Then it researches, splits the scenes, writes the lines, and generates an image per scene. The result is a storyboard.html you can open in a browser.

Before any of it reaches you, a review agent reads the storyboard six separate times, once each — whether the sentences sound AI-written, whether each scene does its job, whether the word choice is how people actually talk, whether the camera knows where to move and where to stop, what the episode will sound like, and whether each picture matches what its scene says. Findings get applied once, and anything left over shows up on the approval screen. This step taking a while is normal. When it finally asks for a decision, approve it.

3

Build the video and the posts

/social-flow:produce money 20260729-fx

The topic name is the folder name step 2 created. It draws and captures the frames, lays in the voice, adds BGM, burns subtitles, and builds the video — plus separate posts for Threads, Instagram, Facebook, and YouTube.

Everything lands in data/money/episodes/20260729-fx/output/. You get a version with subtitles burned in and one without: Instagram can't take a subtitle file so it uses the burned one, while YouTube and Facebook get the subtitles uploaded separately.

4

Publish

/social-flow:publish money 20260729-fx

It shows you the final copy for every platform and the accounts they'd go to, and waits for approval. Nothing is called until you approve; the resulting links are recorded in publish-log.md.

If you haven't connected social accounts yet, skip this step. The video files are already in your hands — upload them yourself.

If you want it in one shot — /social-flow:autoproduce money "July FX swings" drives steps 2 and 3 with no human check-in. Eleven machine gates stand where the approvals were, and any one of them failing hands the episode back to a person. The default economy tier makes no generated-video calls at all, so an episode costs roughly $0.26–0.29 (capped at $0.30).

Publishing to social accounts

Publishing needs each platform's API token. Only platforms with a token file get their publish and insight tools, so seeing none right after install is normal.

You can skip this whole section. With no tokens at all, everything through step 3 still runs, and you upload the video and per-platform text sitting in output/ yourself. Tokens are per platform, so connecting YouTube first is fine — YouTube then publishes itself while the rest stays manual. The moment a token exists, it opens up not just publishing but the growth loops and metrics too.

Letting the tool do the setup

Each platform has a skill that drives the browser for you, from account signup through token issuance. It hands control back only where a human is unavoidable — logging in, typing a verification code.

/social-flow:setup-threads money
/social-flow:setup-instagram money
/social-flow:setup-youtube money

Where tokens live

One directory per channel, so running several brands never mixes the accounts up.

~/.config/social-flow/<channel-slug>/
├── threads_token
├── instagram_token
├── facebook_page_token
└── youtube-oauth-client.json

Lock the files down with chmod 600. The issuance procedure is written per platform in skills/publish/references/token-setup.md.

A publish tool call is immediately public. There's no review state and no draft. That's why the publish skill's approval screen and Claude Code's own permission prompt both stand in front of it. Don't raise that prompt to "always allow".

What else it can do

Channel logo

Four candidates for you to choose from, then a review agent polishes the winner up to 95 points.

/social-flow:branding money

Channel intro video

A 4-second intro with your character acting. It goes after the episode, not before — brand eating the first 3 seconds gets you swiped away.

/social-flow:intro money

Build from a screen recording

Use your own screen and voice as the source instead of web research. It transcribes and turns that into a timeline.

/social-flow:ingest money record

Film against a script

For demos and tutorials. The script comes first, you record while reading it, then it gets edited.

/social-flow:storyboard money <topic> as a shooting script

Find open data

Dig up statistics on data.go.kr to back a claim and stash them as material.

/social-flow:datago jeonse fraud statistics

Grow the account by itself

Comment replies, metric watching, and posting run autonomously inside the growth plan you approved.

/social-flow:grow-threads money init

Once a growth plan is approved, you run the loop on a schedule — /loop 30m /social-flow:grow-threads money. Every sentence that goes out has to clear the review agent's 95-point bar before it publishes. Per-platform strategy is written up in the Threads · YouTube Shorts · Instagram guides.

When you get stuck

social-flow isn't in /mcp

Start the server directly — the cause shows up immediately. From the install cache for a marketplace install, from your clone otherwise.

node ~/.claude/plugins/cache/social-flow/social-flow/*/server/dist/bundle.js
# from a clone: cd ~/social-flow && node server/dist/bundle.js

If social-flow MCP server started prints, the server is fine and the problem is in how the plugin was loaded. On older Claude Code versions claude plugin update social-flow can answer not found — reinstall with uninstall then install.

The publish tools aren't in the list

That's normal. Only platforms with a credential file get their tools. If you just added a token, you don't have to restart Claude Code — the next read of the tool list picks it up.

The data folder showed up somewhere unexpected

data/ is created where you started Claude Code. Pick one working folder and always run claude inside it and nothing scatters.

It stalls while making the video

Check ffmpeg -version first. If it stalls at the frame-capture step, check that Chrome is installed.

The voice breaks up oddly

One long sentence read in a single pass can fall apart toward the end. Splitting the line into shorter sentences and regenerating usually fixes it.

The storyboard step is taking a while

The review agent is reading it six times and generating the images. It doesn't read the same thing twice — once the six are done it shows you the findings it couldn't resolve and waits for your call.
