1. OAuth 토큰 교환

자격증명 파일은 API 키가 아니라 OAuth 클라이언트 + 리프레시 토큰 JSON이다. 경로는 <SNS_TOKEN_DIR>/[<채널 slug>/]youtube-oauth-client.json 이다.

이 파일이 무엇을 여는가. 파일이 있는 채널에만 youtube_publish·youtube_insights 가 tools/list 에 노출된다(플랫폼 자격증명으로 게이트되는 툴 아홉 중 둘 — 나머지 일곱은 Meta 3종). 요청 시점 평가라 토큰 추가에 서버 재시작이 필요 없다. youtube_update 는 게이트 밖이라 항상 노출되고 토큰이 없으면 에러로 답하며, youtube_topic_scout 는 공개 데이터라 YOUTUBE_API_KEY 하나로도 돈다. 전부 선택 사항이다 — 토큰 없이도 제작까지는 그대로 돌아가고, 완성 영상과 문안이 output/ 에 나오면 사람이 직접 올린다. 
{ "client_id": "…", "client_secret": "…", "refresh_token": "…" }
POST https://oauth2.googleapis.com/token
Content-Type: application/x-www-form-urlencoded

client_id=…&client_secret=…&refresh_token=…&grant_type=refresh_token
→ { "access_token": "…", "expires_in": 3599 }
테스트 모드에서 발급한 refresh_token은 7일 만에 만료된다. OAuth 동의 화면이 "테스트" 상태인 프로젝트의 토큰은 7일 후 무효가 되어 업로드가 갑자기 실패한다. 프로덕션으로 게시한 뒤 재발급해야 영구 리프레시 토큰을 얻는다. 동의 플로우에서 스코프 체크박스를 반드시 선택해야 하는 것도 함께 놓치기 쉬운 지점이다.

필요한 스코프

스코프가능해지는 것
youtube.upload영상 업로드 — youtube_publish
youtube업로드 + 채널 조회 + 썸네일
youtube.readonly채널·영상 조회 — youtube_insights의 통계부
yt-analytics.readonly기간 지표(조회·시청·구독 증감) — youtube_insights의 Analytics부
youtube.force-ssl위 전부 + 자막 업로드(captions.insert) + 댓글 API — youtube_publish의 captionFilePath, sns_comment_inbox/sns_comment_reply
yt-analytics-monetary.readonly수익 지표 — includeRevenue: true
게시용으로 발급한 토큰에는 위쪽 하나(youtube.upload)뿐이다. 그런데 force-ssl은 이제 게시에도 필요하다 — 이 파이프라인은 자막을 영상에 태우지 않고 따로 올리는데(§5), 그 호출이 업로드 스코프로는 거부된다. 옛 토큰으로 게시하면 영상은 올라가고 자막만 실패한다. 성장 루프(/social-flow:grow-youtube)도 나머지를 요구하므로 첫 호출에서 스코프 에러가 나는 것이 정상이며, 에러 본문에 재발급 안내가 실려 온다. 동의 플로우에서 체크박스를 하나씩 다 켜고 재발급한 뒤 refresh_token만 교체한다. 조회 스코프와 댓글 스코프는 별개라 한쪽만 막힐 수 있다.

성장 루프가 쓰는 다른 API 둘

youtube_insights는 Data API 하나로 끝나지 않는다. 채널 통계와 최근 업로드 목록은 Data API(channels.list → playlistItems.list → videos.list, 합쳐서 3유닛)에서 오지만, 기간 지표는 별도 서비스인 YouTube Analytics API에서 온다.

GET https://youtubeanalytics.googleapis.com/v2/reports
  ?ids=channel==MINE&startDate=…&endDate=…
  &metrics=views,engagedViews,averageViewPercentage,subscribersGained,…
  &dimensions=video&filters=video==id1,id2,…   # 영상별은 한 번에 묶어 받는다
Google Cloud Console에서 YouTube Analytics API를 따로 활성화해야 한다. Data API만 켜 두면 스코프가 맞아도 403이 난다. 그리고 Analytics 데이터는 2~3일 지연된다 — 어제·오늘 값이 비는 것은 장애가 아니므로 days를 7 이상으로 둔다. 응답의 rows가 비면 0이 아니라 빈 객체를 반환해 "지연"과 "진짜 0"을 구분한다.

Studio의 "How many chose to view"(시청 대 스와이프 이탈 비율)는 Analytics API 메트릭 목록에 대응 항목이 없다. 쇼츠 훅 판정은 averageViewPercentage로 대신하고, 스와이프 지표는 Studio에서 사람이 확인해야 한다. 메트릭 목록 · reports.query

2. resumable 업로드 2단계

# 1단계 — 세션 개시 (메타데이터)
POST https://www.googleapis.com/upload/youtube/v3/videos?uploadType=resumable&part=snippet,status
Authorization: Bearer {access_token}
Content-Type: application/json

{ "snippet": { "title": "…", "description": "…", "categoryId": "22" },
  "status":  { "privacyStatus": "public", "selfDeclaredMadeForKids": false } }
→ 200, Location: https://…   ← 이 헤더가 업로드 URL

# 2단계 — 바이트 전송
PUT {Location}
Content-Type: video/mp4
<파일 바이트>
→ { "id": "VIDEO_ID", … }

Location 헤더가 없으면 이후 단계가 불가능하므로 즉시 실패로 갈라야 한다. 이 서버는 개시에 30초 타임아웃을 건다.

지원 형식은 video/*, 최대 256GB. 이 서버는 .mp4(video/mp4)와 .mov(video/quicktime)만 받는다.

2단계는 청크 PUT + 재개다

바이트 전송은 한 번의 PUT 이 아니라 기본 8MB 청크(SOCIAL_FLOW_YT_CHUNK_MB 로 조정, 프로토콜이 마지막을 뺀 모든 청크에 256KiB 배수를 요구한다)로 나눠 보내고, 청크마다 Content-Range 를 싣는다. 청크 하나의 타임아웃은 300초다. 파일 전체를 힙에 올리지 않고 파일 핸들 하나와 청크 버퍼 하나만 쓴다 — 8분 넘는 롱폼은 수백 MB라 전체 적재가 그대로 메모리 피크가 된다.

크기로 경로를 나누지 않는다. 위험한 경로는 드물게 도는 경로여서, 쇼트폼이 매일 밟아야 회귀가 롱폼 파일럿이 아니라 그날 게시에서 드러난다. 청크 3~7회의 추가 왕복은 keep-alive 에서 회당 100~300ms, 합쳐 2초 안쪽이다.

끊긴 업로드는 이어서 올린다. 세션 URL·파일 크기·mtime 을 <SNS_TOKEN_DIR>/.yt-upload/ 아래에 적어 두고(수명 24시간 — 유튜브는 7일을 주지만 그만큼 믿지 않는다), 같은 파일을 다시 호출하면 서버에 오프셋을 먼저 묻는다. 우리가 기억한 오프셋을 믿으면 안 된다 — 바이트는 도달했는데 응답만 끊긴 경우가 있어서, 그때 재전송하면 중복 영상이 생긴다. 이미 끝나 있으면 그 videoId 를 resumed: true 와 함께 돌려주고 다시 올리지 않는다. 상태 파일 쓰기가 막히면 조용히 건너뛰고 재개 없는 동작으로 내려간다 — 상태 저장 실패가 게시 실패가 되면 안 된다.

3. snippet · status 필드

필드값이 서버
snippet.title최대 100자. 꺾쇠 <> 거부zod에서 길이·꺾쇠 검증
snippet.description최대 5,000같되 글자가 아니라 바이트다 — 한국어는 글자당 3바이트라 실질 약 1,666자이며, zod 가 바이트로 검증해 업로드를 태운 뒤 400 을 받는 일을 막는다
snippet.categoryId필수. 22=People & Blogs · 24=Entertainment · 25=News & Politics · 27=Education · 28=Science & Tech노출 · 기본 22
snippet.tags키워드 배열미노출 — 쇼츠는 태그보다 제목·설명 키워드의 비중이 크다
status.privacyStatuspublic · unlisted · private기본 public
status.selfDeclaredMadeForKidsbool — COPPA 자기 선언madeForKids 인자로 노출 · 기본 false. 아동 대상 콘텐츠는 반드시 true로 선언해야 한다(허위 선언은 채널 제재 사유, true면 댓글·개인화 광고 비활성)
status.containsSyntheticMediabool — AI 생성·변형 콘텐츠 자기 고지containsSyntheticMedia 인자로 노출 · 기본 true. 이 파이프라인은 Veo 영상과 Lyria 음악을 쓰므로 켜 두는 것이 기본값이다. 고지는 노출·수익 자격에 영향을 주지 않는다고 YouTube 가 명시하므로 애매하면 켜 두는 쪽이 손해가 없고, false로 내릴 자리는 명확한 면제뿐이다 — 대본·제목·썸네일 생성, 자막 생성, 자기 목소리 복제, 사실적이지 않은 애니메이션, 색보정·뷰티 필터
categoryId는 필수인데 잘못 두면 조용히 손해를 본다. 카테고리는 추천·탐색 분류에 쓰이므로, 일반 콘텐츠 채널의 영상이 25(News & Politics)로 올라가면 엉뚱한 관심사 집단에 노출된다. 쇼트폼 콘텐츠의 기본값은 22(People & Blogs)가 맞고, 채널 성격에 따라 호출자가 바꿀 수 있어야 한다.
부분 수정에는 youtube_update 를 쓴다. 공개 범위·제목·설명·categoryId·madeForKids·containsSyntheticMedia·예약 공개(publishAt)를 이미 올라간 영상에 대해 바꾼다. videos.update 는 빼고 보낸 필드를 기본값으로 되돌리는 API 라서, 이 툴이 현재 값을 먼저 읽어 미지정 필드를 그대로 실어 보낸다. 되돌릴 수 없는 변경 앞에는 dryRun: true 로 보낼 본문을 먼저 확인한다.
2020-07-28 이후 만들어진 미검증 프로젝트는 업로드가 private으로 강제된다. privacyStatus: "public"을 보내도 비공개로 올라간다면 API 프로젝트의 컴플라이언스 감사를 통과하지 못한 상태다.

4. 썸네일

POST https://www.googleapis.com/upload/youtube/v3/thumbnails/set?videoId={id}
Authorization: Bearer {access_token}
Content-Type: image/jpeg | image/png
<이미지 바이트>
  • 형식 .jpg/.jpeg/.png, 2MB 이하.
  • 채널에 전화번호 인증(중급 기능)이 없으면 거부된다.
  • youtube_publish 에서는 thumbnailFilePath 가 필수 인자다. 미지정 업로드는 YouTube 가 임의 프레임을 뽑아 제목 커버가 안 보이고, 게시 후 API 로는 세로 표면을 되돌릴 수 없다.
  • 이 지정이 바꾸는 것은 가로 표면(검색결과·공유 미리보기·임베드)뿐이다 — 쇼츠 피드와 채널 쇼츠 탭의 세로 프레임은 YouTube 앱의 프레임 선택으로만 바뀐다.
두 가지 순서 규칙이 있다. ① 썸네일 파일 검증(존재·확장자·2MB)은 업로드 전에 한다 — 업로드 후에 실패시키면 이미 소모된 쿼터와 시간이 낭비된다. ② 반대로 thumbnails.set 호출 실패는 전체를 실패로 만들지 않는다 — 영상은 이미 올라갔고 재업로드는 비멱등·쿼터 소모라, thumbnailWarning으로 낮춰 보고한다.

5. 자막 트랙 — 영상과 따로 올린다

자막을 영상에 태우지 않고 파일로 올리면 게시 후에도 자막만 교체할 수 있고, 시청자가 끄고 켤 수 있고, YouTube 자동 번역의 원본이 된다. 번인 자막은 오타 하나에 재인코딩과 재게시를 부른다.

POST https://www.googleapis.com/upload/youtube/v3/captions?uploadType=multipart&part=snippet
Authorization: Bearer {access_token}
Content-Type: multipart/related; boundary={boundary}

--{boundary}
Content-Type: application/json; charset=UTF-8

{"snippet":{"videoId":"...","language":"ko","name":"","isDraft":false}}
--{boundary}
Content-Type: application/octet-stream

<SRT 바이트>
--{boundary}--
  • snippet.videoId·snippet.language·snippet.name이 필수다. language는 툴 인자 captionLanguage(BCP-47, 기본 ko)로 정하고 YouTube 자동 번역의 원본 언어가 된다. name은 트랙 표시명이라 빈 문자열이 기본 트랙이다.
  • 최대 100MB. MIME은 text/xml·application/octet-stream·*/*를 받는다.
  • 업로드 프로토콜은 Google 공통 규약을 따른다 — 메타데이터와 파일을 한 요청에 싣는 uploadType=multipart가 SRT 같은 작은 파일의 정석이다(영상은 resumable).
두 가지가 영상 업로드와 다르다. ① 스코프가 youtube.force-ssl(또는 youtubepartner)이다 — 게시용 youtube.upload로는 거부된다. 업로드만 켜 둔 옛 토큰으로 게시하면 영상은 올라가고 자막만 실패한다. ② 쿼터가 호출당 400유닛이다 — videos.insert의 1유닛과 400배 차이라, 회차당 한 번만 부른다.
순서 규칙은 썸네일과 같다. 자막 파일 검증(확장자·존재·크기)은 업로드 전에 하고, captions.insert 호출 실패는 전체를 실패로 만들지 않는다 — 영상은 이미 공개됐고 재업로드는 비멱등이라 captionWarning으로 낮춰 보고한다. 스코프 부족이 감지되면 경고에 재발급 절차를 실어 보낸다.

6. 쿼터 — 2026년 개편

videos.insert의 쿼터 계산이 바뀌었다. 과거에는 기본 버킷 10,000유닛/일에서 호출당 약 1,600유닛을 소모해 하루 6건이 실질 상한이었다. 지금은 videos.insert와 search.list가 각자의 버킷으로 분리되어, videos.insert는 Video Uploads 버킷에서 호출당 1유닛(기본 일 100회)을 쓴다.
개편 전개편 후
버킷공용 10,000유닛/일Video Uploads 전용
호출당 비용약 1,600유닛1유닛
실질 일일 상한약 6건약 100건
"하루 6건"을 근거로 업로드를 아끼는 설명은 이제 틀린 안내다 — 모델이 필요한 게시를 미루게 만든다.

channels.list 등 나머지 메서드는 기존 공용 버킷을 계속 쓴다. sns_account_check의 채널 조회가 여기에 해당한다.

7. 쇼츠 분류

쇼츠로 만드는 별도 플래그는 없다. 세로 비율(9:16) + 3분 이하면 YouTube가 자동 분류한다.

  • 제목은 키워드형이 유리하다 — 쇼츠는 제목 검색 노출 비중이 크다.
  • 설명은 첫 줄 요약 + 핵심 포인트 + 해시태그 3~5개(#Shorts 포함).

8. 시장 주제 스카우트

youtube_topic_scout는 게시·내 채널 인사이트가 아니다. 시드 검색어로 관련 채널을 모은 뒤 각 채널의 최근 업로드 조회수 중앙값을 구하고, 중앙값의 5배 이상 나온 영상 제목에서 주제어를 뽑는다. 절대 조회수는 채널 크기마다 기본값이 달라 주제를 고르는 잣대가 못 된다.

GET /search?part=snippet&type=video&order=viewCount&publishedAfter=…   # 100유닛
GET /channels?part=snippet,statistics,contentDetails&id=…             # 1유닛
GET /playlistItems?part=contentDetails&playlistId=uploads             # 1유닛
