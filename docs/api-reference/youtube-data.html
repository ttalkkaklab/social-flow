1. OAuth 토큰 교환

자격증명 파일은 API 키가 아니라 OAuth 클라이언트 + 리프레시 토큰 JSON이다.

{ "client_id": "…", "client_secret": "…", "refresh_token": "…" }
POST https://oauth2.googleapis.com/token
Content-Type: application/x-www-form-urlencoded

client_id=…&client_secret=…&refresh_token=…&grant_type=refresh_token
→ { "access_token": "…", "expires_in": 3599 }
테스트 모드에서 발급한 refresh_token은 7일 만에 만료된다. OAuth 동의 화면이 "테스트" 상태인 프로젝트의 토큰은 7일 후 무효가 되어 업로드가 갑자기 실패한다. 프로덕션으로 게시한 뒤 재발급해야 영구 리프레시 토큰을 얻는다. 동의 플로우에서 스코프 체크박스를 반드시 선택해야 하는 것도 함께 놓치기 쉬운 지점이다.

필요한 스코프

스코프가능해지는 것
youtube.upload영상 업로드
youtube업로드 + 채널 조회 + 썸네일
youtube.force-ssl위 전부 + 댓글 API

이 저장소의 토큰에는 youtube.force-ssl이 없어 댓글 인박스에서 YouTube가 제외된다.

2. resumable 업로드 2단계

# 1단계 — 세션 개시 (메타데이터)
POST https://www.googleapis.com/upload/youtube/v3/videos?uploadType=resumable&part=snippet,status
Authorization: Bearer {access_token}
Content-Type: application/json

{ "snippet": { "title": "…", "description": "…", "categoryId": "22" },
  "status":  { "privacyStatus": "public", "selfDeclaredMadeForKids": false } }
→ 200, Location: https://…   ← 이 헤더가 업로드 URL

# 2단계 — 바이트 전송
PUT {Location}
Content-Type: video/mp4
<파일 바이트>
→ { "id": "VIDEO_ID", … }

Location 헤더가 없으면 이후 단계가 불가능하므로 즉시 실패로 갈라야 한다. 이 서버는 개시 30초 · 업로드 600초 타임아웃을 건다.

지원 형식은 video/*, 최대 256GB. 이 서버는 .mp4(video/mp4)와 .mov(video/quicktime)만 받는다.

3. snippet · status 필드

필드값이 서버
snippet.title최대 100자. 꺾쇠 <> 거부zod에서 길이·꺾쇠 검증
snippet.description최대 5,000자동일
snippet.categoryId필수. 22=People & Blogs · 24=Entertainment · 25=News & Politics · 27=Education · 28=Science & Tech노출 · 기본 22
snippet.tags키워드 배열미노출 — 쇼츠는 태그보다 제목·설명 키워드의 비중이 크다
status.privacyStatuspublic · unlisted · private기본 public
status.selfDeclaredMadeForKidsbool — COPPA 자기 선언madeForKids 인자로 노출 · 기본 false. 아동 대상 콘텐츠는 반드시 true로 선언해야 한다(허위 선언은 채널 제재 사유, true면 댓글·개인화 광고 비활성)
categoryId는 필수인데 잘못 두면 조용히 손해를 본다. 카테고리는 추천·탐색 분류에 쓰이므로, 일반 콘텐츠 채널의 영상이 25(News & Politics)로 올라가면 엉뚱한 관심사 집단에 노출된다. 쇼트폼 콘텐츠의 기본값은 22(People & Blogs)가 맞고, 채널 성격에 따라 호출자가 바꿀 수 있어야 한다.
2020-07-28 이후 만들어진 미검증 프로젝트는 업로드가 private으로 강제된다. privacyStatus: "public"을 보내도 비공개로 올라간다면 API 프로젝트의 컴플라이언스 감사를 통과하지 못한 상태다.

4. 썸네일

POST https://www.googleapis.com/upload/youtube/v3/thumbnails/set?videoId={id}
Authorization: Bearer {access_token}
Content-Type: image/jpeg | image/png
<이미지 바이트>
  • 형식 .jpg/.jpeg/.png, 2MB 이하.
  • 채널에 전화번호 인증(중급 기능)이 없으면 거부된다.
  • 미지정 시 YouTube가 임의 프레임을 뽑는다 — 쇼츠는 제목 커버가 안 보이게 되므로 사실상 필수다.
두 가지 순서 규칙이 있다. ① 썸네일 파일 검증(존재·확장자·2MB)은 업로드 전에 한다 — 업로드 후에 실패시키면 이미 소모된 쿼터와 시간이 낭비된다. ② 반대로 thumbnails.set 호출 실패는 전체를 실패로 만들지 않는다 — 영상은 이미 올라갔고 재업로드는 비멱등·쿼터 소모라, thumbnailWarning으로 낮춰 보고한다.

5. 쿼터 — 2026년 개편

videos.insert의 쿼터 계산이 바뀌었다. 과거에는 기본 버킷 10,000유닛/일에서 호출당 약 1,600유닛을 소모해 하루 6건이 실질 상한이었다. 지금은 videos.insert와 search.list가 각자의 버킷으로 분리되어, videos.insert는 Video Uploads 버킷에서 호출당 1유닛(기본 일 100회)을 쓴다.
개편 전개편 후
버킷공용 10,000유닛/일Video Uploads 전용
호출당 비용약 1,600유닛1유닛
실질 일일 상한약 6건약 100건
"하루 6건"을 근거로 업로드를 아끼는 설명은 이제 틀린 안내다 — 모델이 필요한 게시를 미루게 만든다.

channels.list 등 나머지 메서드는 기존 공용 버킷을 계속 쓴다. sns_account_check의 채널 조회가 여기에 해당한다.

6. 쇼츠 분류

쇼츠로 만드는 별도 플래그는 없다. 세로 비율(9:16) + 3분 이하면 YouTube가 자동 분류한다.

  • 제목은 키워드형이 유리하다 — 쇼츠는 제목 검색 노출 비중이 크다.
  • 설명은 첫 줄 요약 + 핵심 포인트 + 해시태그 3~5개(#Shorts 포함).
