DATA.GO.KR

data.go.kr — Korea's official open-data portal

Government-published source data beats a news article quoting it. This is the Korean government's open-data portal, so the site, the dataset titles, and the response fields are Korean. It also isn't one API but five paths with different characters, and three of them need no authentication at all.

You can get file data all the way through without a key. Search → detail → download, all three unauthenticated, so when you have no auth key or haven't been approved for an API, datago_file_download is the fastest way to collect data.

2. The usage-application trap

The auth key alone isn't enough. It's a two-step gate: on the portal you also have to file a per-API usage application — 활용신청, mostly auto-approved and instant — before your key is registered against that API. Take the key straight from My Page and call an API you never applied for, and you're refused.
  • odcloud: code: -4
  • Standard open APIs: SERVICE_KEY_IS_NOT_REGISTERED_ERROR, or plain text Unauthorized
Translate either of those as "the key is wrong" and the model tries to reissue the key, never reaching the actual fix (file the application).

The portal offers no JSON API for search or detail, so we parse the server-rendered HTML with regexes.

The whitelisted labels are the Korean ones the portal renders — 분류체계 (classification), 제공기관 (provider), 관리부서명 (managing department), API 유형 (API type), 데이터포맷 (data format), 확장자 (file extension), 업데이트 주기 (update cycle), 등록일 (registered), 수정일 (modified), 비용부과유무 (chargeable), 신청가능 트래픽 (allowed traffic), 이용허락범위 (license scope), 키워드 (keywords), 제공형태 (delivery form), 전체 행 (total rows), 매체유형 (media type), 설명 (description). They stay Korean in the code because they're matched against the page.

Parsing breaks when the portal is redesigned. So no parser throws — each one fails gracefully with 0 results plus an explanation: "if this keeps returning 0, a portal redesign may have broken parsing: check … directly with WebFetch and report the parser fix to the user". The point is to stop the model from retrying forever with different queries.

Why the uddi regex hard-codes the pk: the detail page also carries the uddi of related datasets, so taking the first match downloads the wrong dataset.

The portal can block non-browser User-Agents, so we send a normal one (its robots rules target search crawlers).

5. odcloud row queries

GET https://api.odcloud.kr/api/{publicDataPk}/v1/{uddi}?page=1&perPage=10&returnType=JSON
# The tool argument is limit — the server converts it to odcloud's perPage
Authorization: Infuser {auth key}
The key goes in the Authorization header. odcloud also accepts a serviceKey query param, but with the header the key can't leak even when an error body echoes the URL.

The : inside uddi has to pass through literally (measured) — we encode the segment, then turn %3A back into :.

codeMeaningWhat the server says
-1Missing required parameter—
-2Not authorized—
-3Service not registered"the uddi needs to be complete, including the _YYYYMMDDHHMM suffix"
-4Auth key not registered against this API"file the usage application (auto-approved) first … before it's approved, datago_file_download (no auth) gets you the raw file faster"
-5Traffic exceeded"fall back to datago_file_download for today"

Responses are cut at 12,000 characters with a truncation notice appended — lower limit, or point at the rows you need with page.

6. Standard open APIs

GET https://apis.data.go.kr/{path}?{params}&serviceKey={auth key}
# e.g. 1360000/VilageFcstInfoService_2.0/getUltraSrtNcst
returnAuthMsgGuidance
SERVICE_KEY_IS_NOT_REGISTERED_ERRORCheck the usage application and that the key matches. "Do not retry before fixing the key"
DEADLINE_HAS_EXPIRED_ERRORUsage period expired — request an extension on the portal
LIMITED_NUMBER_OF_SERVICE_REQUESTS_EXCEEDS_ERRORDaily traffic exceeded — no more calls to this API today
SERVICE_ACCESS_DENIED_ERRORCheck the approval status of the usage application
TEMPORARILY_DISABLE_THE_SERVICEKEY_ERRORKey temporarily blocked
NO_OPENAPI_SERVICE_ERRORNo such path — compare against the request URL in the usage guide
The gateway answers HTTP 200 for an unregistered key. The body may be an XML error or the plain text Unauthorized, so going by the status code alone reads as success. Inspect the body first.
  • Many of these APIs answer in XML. Where dataType/_type=JSON is supported, asking for JSON is easier to parse.
  • The server injects serviceKey — put it in params yourself and zod rejects the call.
  • Responses are cut at 8,000 characters, with guidance to re-query smaller using numOfRows/pageNo.
  • serviceKey=*** masking on every output path.
Don't guess parameters and call repeatedly. Standard open APIs have daily traffic limits, and calls with wrong parameters count too. The tool description says to read the contract first from datago_detail's endpoint/requestUrls/docs.
