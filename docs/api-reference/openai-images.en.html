OpenAI Images — generation and editing

The GPT Image family's /v1/images/generations and /v1/images/edits. Parameter support differs per model, and sending an unsupported parameter is an error rather than a no-op, so the per-model matrix has to be enforced in the schema.

1. Models and their lifespans

ModelWhere it sitsLifespan
gpt-image-2 defaultNewest · reasoning-based. Strongest at photorealism and instruction adherence, and stable at rendering text inside the image—
gpt-image-1.5Middle of the quality/cost rangeShutdown 2026-12-01
gpt-image-1Previous generationShutdown 2026-10-23
gpt-image-1-miniCheap, lower qualityShutdown 2026-12-01

dall-e-2 and dall-e-3 finished shutting down on 2026-05-12. Once the scheduled EOLs all pass, the only model left on the Images API is gpt-image-2.

Transparent backgrounds go away with the EOLs. background: "transparent" isn't supported by gpt-image-2, and gpt-image-1/1.5, which do support it, end within 2026. Design logo and overlay material on the assumption of post-processing (background removal).
Images get made without a key too — on-device image_local_generate. It runs Z-Image Turbo through mflux/MLX with no OPENAI_API_KEY, no network, and no billing (Apple Silicon required), and it's the default path for scene backgrounds. But frames with text on them go to GPT Image — local generation breaks Korean jamo apart, so it can't be used where the letters have to be readable, like covers and titles. What OPENAI_API_KEY opens is that "text and quality" path. The key is checked at call time rather than at server startup, so on an install without it the rest of the tools run as usual.

Sending input_fidelity to gpt-image-2 is an error. Not "ignored" — the request itself fails. gpt-image-2 handles input images at high fidelity always, so omitting the parameter is the right answer, and this server rejects the combination at the schema stage.

3. size — arbitrary resolution limits

Presets (all models)

auto · 1024x1024 · 1536x1024 (landscape) · 1024x1536 (portrait)

Arbitrary resolution WIDTHxHEIGHT — gpt-image-2 only

ConstraintValue
Width and heightboth multiples of 16
Aspect ratio1:3 ~ 3:1
Longest edge3,840px (max resolution 3840×2160)
Total pixels655,360 ~ 8,294,400
Experimental rangeabove 2560×1440 is experimental
Short-form 9:16 is 1088x1920. 1080×1920 gets rejected because 1080 isn't a multiple of 16, so use 1088 (1088 = 16×68, 1920 = 16×120, 2,088,960px total, ratio 0.567 → passes the constraints).

This server checks the four constraints separately and collects every violation into one message — reporting them one at a time makes the model fire off several rounds of size corrections.

Custom resolution "1080x1921" violates constraints: width and height must be multiples of 16

4. The edit-only contract (/v1/images/edits)

ItemContract
imagepng/webp/jpg, each under 50MB, up to 16. Several images are used as composition references
maskPNG with an alpha channel, under 4MB, the same size as the first image. Fully transparent pixels are the area to repaint, and even with several images the mask applies to the first one only
Model defaultThe API default is gpt-image-1.5 (this server pins gpt-image-2)

Editing is strong at mask inpainting, composing several references, and preserving fine detail such as faces and logos. For making something from nothing, gpt_image_text2img is the right call.

5. Response

{ "data": [ { "b64_json": "…", "revised_prompt": "…" } ] }
  • The GPT Image family is always base64 — there's no URL response.
  • revised_prompt is the rewritten prompt the model actually used. Use it to trace the cause when the result differs from what you intended.
  • The response MIME follows the requested output_format (the edit path too).

Images are the one generation tool that returns base64 into the context. That's because the model has to look at the result and decide whether to regenerate. For video, voice, and music the model can't evaluate the output directly anyway, so those return only a path.
