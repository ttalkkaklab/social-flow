1. OAuth token exchange

The credential file isn't an API key — it's an OAuth client plus a refresh token, as JSON. The path is <SNS_TOKEN_DIR>/[<channel slug>/]youtube-oauth-client.json.

What this file unlocks. youtube_publish and youtube_insights appear in tools/list only for channels that have it (two of the nine tools gated on platform credentials — the other seven belong to the three Meta surfaces). It's evaluated per request, so adding a token needs no server restart. youtube_update sits outside the gate and is always listed, erroring if there's no token, and youtube_topic_scout reads public data, so YOUTUBE_API_KEY alone drives it. All of it is optional: with no token, everything through production still works, and once the finished video and copy land in output/ you upload by hand. 
{ "client_id": "…", "client_secret": "…", "refresh_token": "…" }
POST https://oauth2.googleapis.com/token
Content-Type: application/x-www-form-urlencoded

client_id=…&client_secret=…&refresh_token=…&grant_type=refresh_token
→ { "access_token": "…", "expires_in": 3599 }
A refresh_token issued in testing mode expires in 7 days. Tokens from a project whose OAuth consent screen is still in "testing" go invalid after a week and uploads suddenly fail. You have to publish the project to production and reissue to get a permanent refresh token. Ticking the scope checkboxes in the consent flow is the other thing that's easy to miss at the same moment.

Scopes you need

ScopeWhat it enables

A token issued for publishing has only the first one (youtube.upload). But force-ssl is now needed for publishing too — this pipeline doesn't burn subtitles into the picture, it uploads them separately (§5), and that call is refused by the upload scope. Publish with an old token and the video goes up while the captions fail. The growth loop (/social-flow:grow-youtube) needs the rest, so a scope error on its first call is normal, and the error body carries the reissue instructions. Tick every checkbox in the consent flow, reissue, and swap in the new refresh_token. Read scopes and comment scopes are separate, so only one of them can be blocked.

Two other APIs the growth loop uses

youtube_insights doesn't end at the Data API. Channel statistics and the recent-upload list come from it (channels.list → playlistItems.list → videos.list, 3 units in total), but period metrics come from a separate service, the YouTube Analytics API.

GET https://youtubeanalytics.googleapis.com/v2/reports
  ?ids=channel==MINE&startDate=…&endDate=…
  &metrics=views,engagedViews,averageViewPercentage,subscribersGained,…
  &dimensions=video&filters=video==id1,id2,…   # per-video comes back in one batch
You have to enable the YouTube Analytics API separately in Google Cloud Console. With only the Data API enabled you get a 403 even with the right scopes. And Analytics data lags 2–3 days — yesterday and today being empty isn't an outage, so keep days at 7 or more. When rows comes back empty we return an empty object rather than 0, which keeps "delayed" distinguishable from "genuinely zero".

Studio's "How many chose to view" (watched vs. swiped away) has no counterpart in the Analytics API metric list. Shorts hook verdicts fall back to averageViewPercentage, and the swipe metric has to be read by a human in Studio. Metric list · reports.query

2. Resumable upload in two steps

# Step 1 — open the session (metadata)
POST https://www.googleapis.com/upload/youtube/v3/videos?uploadType=resumable&part=snippet,status
Authorization: Bearer {access_token}
Content-Type: application/json

{ "snippet": { "title": "…", "description": "…", "categoryId": "22" },
  "status":  { "privacyStatus": "public", "selfDeclaredMadeForKids": false } }
→ 200, Location: https://…   ← this header is the upload URL

# Step 2 — send the bytes
PUT {Location}
Content-Type: video/mp4
<file bytes>
→ { "id": "VIDEO_ID", … }

Without the Location header nothing downstream is possible, so that has to fail immediately. This server puts a 30-second timeout on opening the session.

Supported formats are video/*, up to 256GB. This server accepts only .mp4 (video/mp4) and .mov (video/quicktime).

Step 2 is chunked PUTs with resume

The bytes don't go in a single PUT. They're split into 8MB chunks by default (tunable with SOCIAL_FLOW_YT_CHUNK_MB; the protocol requires every chunk but the last to be a multiple of 256KiB), each carrying a Content-Range. One chunk's timeout is 300 seconds. The file never goes into the heap whole — one file handle and one chunk buffer — because long-form past 8 minutes runs to hundreds of MB and loading it all becomes the memory peak.

There's no size threshold branching the code. The dangerous path is the rarely-taken one, and short-form has to walk it daily so a regression shows up in that day's publish rather than in a long-form pilot. The extra round trips for 3–7 chunks cost 100–300ms each over keep-alive, under 2 seconds total.

An interrupted upload continues where it stopped. The session URL, file size, and mtime are written under <SNS_TOKEN_DIR>/.yt-upload/ (24-hour lifetime — YouTube allows 7 days, we don't trust it that far), and calling again for the same file asks the server for the offset first. Trusting our own remembered offset isn't safe: sometimes the bytes arrived and only the response was cut, and resending then creates a duplicate video. If it turns out to be finished already, we return that videoId with resumed: true and upload nothing. If writing the state file is blocked, we skip it silently and fall back to the no-resume behavior — a failed state write must not become a failed publish.

snippet.tagsKeyword arrayNot exposed — on Shorts, title and description keywords weigh more than tags

status.containsSyntheticMediabool — self-disclosure of AI-generated or altered contentExposed as containsSyntheticMedia · defaults to true. This pipeline uses Veo video and Lyria music, so on is the right default. YouTube states the disclosure doesn't affect reach or monetization eligibility, so leaving it on costs nothing when in doubt; the only place to set false is a clear exemption — generating scripts, titles, or thumbnails, generating subtitles, cloning your own voice, non-realistic animation, color grading and beauty filters
categoryId is required, and getting it wrong costs you quietly. The category feeds recommendation and browse classification, so a general-interest channel's video uploaded as 25 (News & Politics) surfaces to the wrong interest group. 22 (People & Blogs) is the right default for short-form, and the caller has to be able to change it to suit the channel.
Partial edits go through youtube_update. It changes visibility, title, description, categoryId, madeForKids, containsSyntheticMedia, and scheduled publishing (publishAt) on a video that's already up. videos.update resets any field you omit to its default, so this tool reads the current values first and sends the unspecified ones back unchanged. Before a change you can't undo, call it with dryRun: true to see the body it would send.
An unverified project created after 2020-07-28 has its uploads forced to private. If you send privacyStatus: "public" and it still goes up private, the API project hasn't passed its compliance audit.

4. Thumbnails

POST https://www.googleapis.com/upload/youtube/v3/thumbnails/set?videoId={id}
Authorization: Bearer {access_token}
Content-Type: image/jpeg | image/png
<image bytes>
  • Format .jpg/.jpeg/.png, 2MB or less.
  • Refused unless the channel has phone verification (intermediate features).
  • thumbnailFilePath is a required argument on youtube_publish. Upload without one and YouTube picks an arbitrary frame, the title cover never shows, and the vertical surface can't be undone through the API afterwards.
  • What it changes is the landscape surface only (search results, share previews, embeds) — the vertical frame in the Shorts feed and the channel's Shorts tab changes only through frame selection in the YouTube app.
Two ordering rules. ① Validating the thumbnail file (exists, extension, 2MB) happens before the upload — failing after it wastes quota and time already spent. ② Conversely, a failing thumbnails.set call doesn't fail the whole operation — the video is already up and re-uploading is non-idempotent and costs quota, so it's downgraded to thumbnailWarning.

5. Caption tracks — uploaded separately

Uploading subtitles as a file instead of burning them into the picture means you can swap the subtitles alone after publishing, viewers can turn them off, and YouTube's auto-translation has a source. Burned-in subtitles turn one typo into a re-encode and a re-post.

POST https://www.googleapis.com/upload/youtube/v3/captions?uploadType=multipart&part=snippet
Authorization: Bearer {access_token}
Content-Type: multipart/related; boundary={boundary}

--{boundary}
Content-Type: application/json; charset=UTF-8

{"snippet":{"videoId":"...","language":"ko","name":"","isDraft":false}}
--{boundary}
Content-Type: application/octet-stream

<SRT bytes>
--{boundary}--
  • snippet.videoId, snippet.language, and snippet.name are required. language comes from the tool argument captionLanguage (BCP-47, defaults to ko) and becomes the source language for YouTube's auto-translation. name is the track's display name, so an empty string is the default track.
  • Up to 100MB. Accepted MIME types are text/xml, application/octet-stream, and */*.
  • The upload protocol follows Google's common convention — uploadType=multipart, metadata and file in one request, is the standard for small files like an SRT (video uses resumable).
Two things differ from the video upload. ① The scope is youtube.force-ssl (or youtubepartner) — the publishing scope youtube.upload is refused. Publish with an old upload-only token and the video goes up while the captions fail. ② The quota is 400 units per call — 400 times videos.insert's single unit, so it's called once per episode.
The ordering rule matches thumbnails. Caption file validation (extension, existence, size) happens before the upload, and a failing captions.insert doesn't fail the whole operation — the video is already public and re-uploading is non-idempotent, so it's downgraded to captionWarning. When insufficient scope is detected, the warning carries the reissue procedure.

6. Quota — the 2026 change

How videos.insert is charged has changed. It used to draw roughly 1,600 units per call from a shared 10,000-unit daily bucket, which made 6 uploads a day the effective ceiling. Now videos.insert and search.list have separate buckets, and videos.insert costs 1 unit from the Video Uploads bucket (100 a day by default).
BeforeAfter
BucketShared, 10,000 units/dayVideo Uploads, dedicated
Cost per callAbout 1,600 units1 unit
Effective daily ceilingAbout 6About 100
Any explanation that rations uploads because of "6 a day" is now wrong guidance — it makes the model postpone publishing it should do.

The remaining methods, channels.list among them, still draw on the shared bucket. sns_account_check's channel lookup is one of those.

7. Shorts classification

There's no flag that makes something a Short. YouTube classifies it automatically from a vertical (9:16) aspect ratio and a length of 3 minutes or less.

  • Keyword-style titles do better — for Shorts, a large share of exposure comes from title search.
  • The description wants a one-line summary, the key points, and 3–5 hashtags (including #Shorts).

8. Market topic scouting

youtube_topic_scout isn't about publishing or your own channel's insights. It gathers related channels from seed queries, takes the median view count of each channel's recent uploads, and pulls topic phrases from the titles of videos that beat that median by 5× or more. Absolute view counts can't be a yardstick for picking topics, because the baseline differs with channel size.

GET /search?part=snippet&type=video&order=viewCount&publishedAfter=…   # 100 units
GET /channels?part=snippet,statistics,contentDetails&id=…             # 1 unit
GET /playlistItems?part=contentDetails&playlistId=uploads             # 1 unit
GET /videos?part=snippet,statistics,contentDetails&id=…               # 1 unit

YOUTUBE_API_KEY takes precedence for authentication — this is public data, so no OAuth is needed and the publishing quota stays untouched. Without a key, the same endpoints go through the channel's OAuth using youtube.readonly. A token holding only the publishing scope youtube.upload gets search refused.

The /social-flow:topic-scout skill defaults to the US (US/en) and China (CN/zh) markets. Rather than feeding Korean seeds in directly, it translates them into English and Chinese nouns, calls the tool once per market, and merges with merge-scout.py. For Korea only, pass regionCode: KR explicitly. The output is the md and html under data/<channel>/growth/keywords/; a grow-youtube plan with topic_source: scout reads the md.
