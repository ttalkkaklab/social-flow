Lyria — 음악 생성

이름은 하나지만 API는 둘이다. Lyria 3는 Interactions API로 한 번 호출해 완성 트랙을 받고, Lyria RealTime은 WebSocket으로 PCM을 스트리밍한다. 파라미터 체계도, 출력 포맷도, 재현성도 전부 다르다.

2. Lyria 3 Clip (Interactions API)

const interaction = await genai.interactions.create({
  model: 'lyria-3-clip-preview',
  input: '차분한 어쿠스틱 기타 루프, 90 BPM, 따뜻한 톤, instrumental only',
});

응답 구조

interaction.steps[]
  ├─ type: "model_output"
  └─ content[]
       ├─ { type: "text",  text: "…가사 또는 곡 구조…" }
       └─ { type: "audio", data: "<base64>", mime_type: "audio/mpeg" }

SDK는 편의 접근자 interaction.output_audio도 제공한다. 필드명은 snake_case다(mime_type, output_audio) — Gen AI SDK의 다른 영역이 camelCase인 것과 다르니 주의.

@google/genai 2.0 미만은 이 경로가 아예 동작하지 않는다. Interactions API는 2026-05 스키마 개편으로 평면 outputs[]를 steps[].content[]로 바꿨고, 서버가 구 스키마 요청을 거부한다: 
The legacy Interactions API schema is no longer supported.
Please upgrade your @google/genai JS/TS SDK to version >= 2.0.0
이 저장소는 ^2.13.0을 요구한다.

프롬프트로 제어하는 것들

  • 장르·악기·BPM·조성·분위기·구조를 전부 자연어로 적는다. 구조화 필드가 없다.
  • 보컬을 원치 않으면 instrumental only, no vocals를 명시한다 — 기본은 보컬이 나올 수 있다.
  • 가사 구조는 [Intro]·[Verse]·[Chorus]·[Bridge]·[Outro] 태그와 [0:00 - 0:10] Intro: … 형식의 타임스탬프로 지정한다.
  • 입력은 멀티모달이다 — 이미지 최대 10장을 함께 넣어 분위기를 지시할 수 있다(이 서버는 텍스트만 노출).
정책 필터가 예민하다(실측). "Calm lo-fi hip hop, 80 BPM, C major, soft piano and vinyl crackle"은 Request blocked for an unspecified policy reason으로 차단됐고, 같은 분위기를 평이하게 서술한 두 개의 대체 프롬프트는 모두 통과했다. 차단은 코드 문제가 아니라 프롬프트 문제이므로 표현을 바꿔 1회 재시도가 올바른 대응이다.

출력에는 SynthID 오디오 워터마크가 들어간다.

3. Lyria RealTime (WebSocket)

const genai = new GoogleGenAI({ apiKey, apiVersion: 'v1alpha' });
const session = await genai.live.music.connect({
  model: 'models/lyria-realtime-exp',
  callbacks: { onmessage, onerror, onclose },
});
await session.setWeightedPrompts({ weightedPrompts: [{ text: 'minimal techno', weight: 1.0 }] });
await session.setMusicGenerationConfig({ musicGenerationConfig: { bpm: 120, density: 0.4 } });
await session.play();

apiVersion — 문서와 실제가 다르다

공식 문서는 v1beta라고 적지만, 실측 결과 동작하는 것은 v1alpha다. 세 조합을 직접 붙여 확인했다:
apiVersion결과
v1alpha정상 — 4초 요청에 384,000바이트 수신 (48,000 × 2ch × 2byte × 4s와 정확히 일치)
v1betaconnect()가 반환되지 않고 무한 대기
(미지정)—
따라서 이 서버는 v1alpha를 유지한다. 문서를 근거로 v1beta로 바꾸면 툴이 조용히 멈춘다.

스트림 종료 조건

서버는 스트림의 끝을 알리지 않는다. 종료 조건은 "받은 양"이다.

목표 바이트 = 요청 초 × 48,000 × 2(채널) × 2(16-bit)
타임아웃    = 요청 초 × 1000 + 30,000ms

목표 바이트를 채우면 세션을 닫고, 정확히 요청한 길이만큼 잘라 WAV 헤더를 씌워 저장한다.

세션 제어

메서드용도
play() · pause() · stop()재생 제어
setWeightedPrompts()생성 중에도 프롬프트를 바꿔 부드럽게 전이시킬 수 있다
setMusicGenerationConfig()설정 변경. bpm·scale은 reset_context() 또는 stop/play 없이는 반영되지 않는다
reset_context()스트림을 끊지 않고 컨텍스트만 초기화
이 서버는 play() 이전에 설정을 한 번만 넣고 이후 바꾸지 않는다. 그래서 bpm·scale의 reset_context 함정에 걸리지 않는다 — 초기 설정으로 전달되면 그대로 적용된다.

Scale enum (13종)

모델은 나란한조를 구분하지 않는다 — 각 값이 장조와 그 나란한단조 양쪽에 대응한다.

C_MAJOR_A_MINOR         D_FLAT_MAJOR_B_FLAT_MINOR  D_MAJOR_B_MINOR       E_FLAT_MAJOR_C_MINOR
E_MAJOR_D_FLAT_MINOR    F_MAJOR_D_MINOR            G_FLAT_MAJOR_E_FLAT_MINOR  G_MAJOR_E_MINOR
A_FLAT_MAJOR_F_MINOR    A_MAJOR_G_FLAT_MINOR       B_FLAT_MAJOR_G_MINOR  B_MAJOR_A_FLAT_MINOR
SCALE_UNSPECIFIED

WeightedPrompt

{ text: "jazz piano", weight: 1.0 }

weight는 0만 아니면 어떤 값이든 된다. 공식 스펙에 ±1 상·하한은 없고, 1.0이 통상적인 출발점이며 값이 클수록 영향이 커진다. 여러 프롬프트를 섞으면 상대 비율로 블렌딩된다.
