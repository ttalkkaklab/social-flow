API REFERENCE

Every API social-flow calls

A reference for the official contracts of the 13 external APIs the internal MCP server (server/src) actually calls. Each page puts what the official docs say next to what this repo's implementation actually does, so you can see where the two diverge. For images and voice the default path is two on-device engines that never touch the network, and those have no external contract to call.

Credential matrix

The keys come in two independent groups, and you can stop after either one.

① Production keys — these make the video. OPENAI_API_KEY renders the cover and any frame with text on it (local image generation garbles Korean glyphs), and GEMINI_API_KEY covers generated video clips, acted narration, and BGM. Strictly speaking both are optional — scene backgrounds default to on-device image_local_generate and narration to on-device tts_local_generate, so a run with no keys at all still produces a video. The research keys (SERPAPI_API_KEY and the Naver pair) are optional too; without them the storyboard skill falls back to the built-in WebSearch.

② Platform credentials (Threads · Instagram · YouTube · Facebook) — optional. Set them up and the pipeline runs end to end and keeps running on its own: publish posts straight to your accounts, and the growth skills (grow-threads·grow-youtube·grow-instagram) operate the channel on /loop — comment replies, insight watching, keyword conversations, queue refill, posting — inside the standing authorization you approved once at init. Skip them and everything up to and including production still works: produce writes the finished video plus per-platform text into data/<channel>/episodes/<topic>/output/ and you upload those files by hand. Only the publishing and growth half is unavailable, and the nine credential-gated tools aren't even listed. It's per platform, not all-or-nothing — connect only YouTube and YouTube publishes and grows while the rest stays manual. Add a token later and nothing needs a server restart.

Keys are validated when a tool is called, not at startup, because publish tools have to work without search keys and vice versa. Record only the variable names below; never commit a value anywhere.

Tokens are read from files, not from values. Meta's 60-day renewal works by overwriting a file, so renewal needs the file-based form, and it also keeps secrets out of .mcp.json, which is committed. Tool ↔ API map

Badges: read no side effects · write creates a local file · public takes effect publicly the moment it's called · key needs a credential · no auth

You won't always see all 50. The nine platform-bound tools (threads_publish·threads_insights·threads_search·instagram_publish·instagram_insights·facebook_publish·facebook_comment·youtube_publish·youtube_insights) appear in tools/list only for platforms that have a credential file. That's evaluated when the list is requested, so adding a token makes them appear without restarting the server; with no tokens at all you see 41. content_feedback·youtube_topic_scout·sns_issue_scout sit outside the gate and stay listed without tokens — the YouTube scout needs YOUTUBE_API_KEY or channel OAuth at call time, the SNS scout needs SERPAPI_API_KEY, and feedback simply skips the sections it has no token for. youtube_update is likewise always listed and errors without a token. Hidden tools still have live handlers — call one directly and you get a missing-token error.

How this reference was built

  • The primary source is the vendor's official documentation. Each page links the original at the top.
  • Where the official docs are silent or don't match reality, the answer was settled with SDK type definitions (node_modules/openai/resources/images.d.ts, node_modules/@google/genai/dist/genai.d.ts) and real calls. Those items say so on the page.
  • One case where a real call overturned the official docs — Lyria RealTime's apiVersion.
  • Where the implementation is narrower than the official contract (say naver_search's display ceiling of 30 against the API's 100), that's deliberate design to protect LLM context rather than a defect, and each table separates it out in an "implementation" column.
