Naver 검색 Open API

한국어 소재 리서치의 1차 도구. 일 25,000회 무료라 SerpApi(월 250회)보다 쿼터가 두 자릿수 크고, 국내 뉴스·블로그 후기·카페 여론은 Google 인덱스보다 이쪽이 정확하다.

1. 엔드포인트 4종

GET https://openapi.naver.com/v1/search/{엔드포인트}
X-Naver-Client-Id:     {클라이언트 ID}
X-Naver-Client-Secret: {클라이언트 시크릿}
type엔드포인트쓰임sort
news 기본news.json국내 뉴스 — 시효성 값(가격·시행일) 교차 검증지원
blogblog.json블로그 후기 — 실사용 경험·체감지원
webwebkr.json웹문서 — 공식 페이지·자료미지원
cafecafearticle.json카페글 — 커뮤니티 여론·불만지원
webkr.json에 sort를 넘기면 400이다. 다른 엔드포인트와 파라미터 표면이 미묘하게 다르므로 type === 'web'일 때는 sort를 아예 빼고 보내야 한다.

자격증명은 헤더로만 전달된다. SerpApi와 달리 URL에 키가 실리지 않아, 에러 본문에 URL이 에코돼도 키가 새지 않는다.

2. 파라미터

파라미터범위기본구현
query—필수1–300자
display1–100101–30으로 축소
start1–100011–1000
sortsim(정확도) · date(날짜)simweb에서는 미전송

start 상한이 1000이라 한 검색어로 수집 가능한 최대 결과는 약 1,099건이다.

display를 30으로 좁힌 것은 결함이 아니라 설계다. API 상한 100건을 그대로 받으면 응답이 LLM 컨텍스트를 크게 잠식하는데, 소재 리서치에서 31번째 결과가 판단을 바꾸는 일은 사실상 없다. 더 필요하면 start로 다음 페이지를 짚는 것이 옳다.

4. 에러와 쿼터

상황응답서버의 대응 지시
키 무효 / 검색 API 미신청401 · 403"키를 교정하기 전 재시도 금지" + 앱 설정 링크
쿼터 소진429"일일 쿼터(25,000회) 소진 — 이번 세션에서는 WebSearch/serp_*로 대체할 것"
결과 없음200 + 빈 items"검색어를 바꿔 1회만 재시도하거나, 확인 실패한 주장은 본문에서 제외할 것"
403은 키가 틀린 게 아니라 "검색 API 사용 신청"이 안 된 앱일 수 있다. Naver Developers에서 앱을 만들어도 API별 사용 신청이 별도다. 에러 메시지가 이 둘을 함께 제시해야 모델이 엉뚱한 방향(키 재발급)으로 가지 않는다.
