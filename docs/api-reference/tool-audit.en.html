2. P0 — the quietly wrong

Two things that raised no error and threw no exception while making the result meaningless. Most of the value in a tool audit is right here — a tool that fails leaves a log line, but a tool that returns a plausible empty result nobody notices.

P0-1 · serp_naver_search's default path always came back empty

This tool defaults to where='web'. The code read only web_results and news_results from the response, but the key SerpApi actually returns for where=web is organic_results. So every search on the default path returned "(no results)".

That response is indistinguishable, character for character, from a search that genuinely found nothing, so the model had no basis for concluding the search was broken. Following the tool description's instruction to "reword the query and retry once" and then dropping the claim from the copy becomes the reasonable behavior — meaning the bias ran quietly toward evidence that existed going unfound and the content coming out thin.

whereSerpApi docsActual response key (measured)
webweb_resultsorganic_results
newsnews_resultsnews_results ✓
nexearchseveral arraysweb_results · ads_results · inline_images_results

Fix: check all three keys. Implementing from the official docs alone would have left this defect in place — catching it takes a real call and a look at the actual response keys.

P0-2 · Clients couldn't tell which tools post publicly on the spot

This server has no pre-publish review gate. Call threads_publish and it publishes at that moment, and because the publish APIs are non-idempotent, a retry means a duplicate post. That fact lived only in each tool's description prose — a form the model reads but the client's approval UI can't.

MCP defines a field for exactly this purpose (annotations.destructiveHint). Leave it empty and the client treats tts_list_voices (returns a constant list) and youtube_publish (uploads publicly, immediately) as equally risky.

Fix: all 31 tools got a title and annotations, and the criteria were pinned down in a decision table. The contract tests check every build for contradictions between hint and description (a readOnly tool whose description says "posts publicly", say).

4. P2 — accuracy and guidance

  • Instagram images — "JPEG recommended" → "JPEG only" (the platform rejects PNG, MPO, and JPS). Publish quota (100 per 24 hours) stated.
  • Threads video — "no video" read like a platform limit. The platform supports VIDEO and CAROUSEL; not supporting them is this pipeline's strategic choice, and the description now says so. Publish quota (250 per 24 hours) added.
  • Google news sorting — an attempt to expose the so sort parameter got a 400 on a real call: "`q` and `so` parameters can't be used together." so is for token navigation only and can't be combined with a query. Exposure was withdrawn, and the description now points at the alternatives (serp_web_search's recency, naver_search's sort=date).
  • GPT Image prompt ceiling — the 32,000-character limit stated in the schema and the description.
  • Lyria 3 Clip — lyric generation and structure tags ([Verse]·[Chorus]·timestamps) documented, and on a policy block the description says "this is a prompt problem, not a code problem — reword and retry once".
  • Comment inbox response size — filling the ceiling (25 posts × 100 comments) eats a large share of the caller's context. There's now a 60,000-character cap that drops the oldest comments first (golden-hour comments have to survive). Aggregates keep the pre-truncation values — recounting from a truncated list under-reports, "3 unanswered" when there are more, and the remaining replies get missed.
  • Meta Graph version as a constant — v23.0 was scattered in two places and is now one constant. The reason for pinning (valid through 2027 · blocks breaking changes in later versions) is in a comment.
  • Three-way version mismatch — plugin.json 0.4.0 · server/package.json 0.3.0 · index.ts 0.3.0 → all 0.4.0.
  • Escaping in the tts_multi_speaker description — the example's \n rendered as an actual newline and showed the wrong format. Also stated: speaker names must match the speakers array.

6. What was left alone, and why

ItemReason
A behavioral eval harness — running multi-step workflows with a real model and measuring tool choice, call count, and tokens The seventh best-practice principle, and the one item this audit fell short on. Because publish tools make real public posts, a safe evaluation needs a dry-run layer first. Building that layer is a design change beyond this audit's scope.
outputSchema for serp_* and datago_* They return JSON text, but the response shape isn't fixed — datago_* especially is parsed out of portal HTML, so the field set differs per dataset. MCP makes conformance a MUST once you declare an outputSchema, so not declaring one is more honest than declaring a contract you can't keep.
Meta Graph staying on v23.0 (latest is v25.0) Meta versions stay valid for roughly two years after release, so v23.0 (2025-05) lives until 2027. Pinning is what stops a breaking change in a later version from quietly breaking publishing. Instead, it's gathered into one constant, so updating means changing one line.
JPEG validation on Instagram image URLs CDN URLs often carry no extension, so judging format from the URL would reject valid requests. Stated in the description, not enforced.
lyria-3-pro-preview not exposed A 1–2 minute track has nowhere to go in a short-form pipeline and only costs more.
Veo numberOfVideos · OpenAI n not exposed Short-form generates one cut at a time by default, and N variants cost N times as much.
mcp__fect-mcp__vision_analyze·vision_ocr in skills/ingest The one remaining external MCP dependency in the plugin. This audit covers the 31 tools this server provides; porting the vision module is separate work. Anyone wanting fully standalone operation for an npm release has to handle this first.

7. Second pass (same day, v0.4.1)

After the first audit converged, the whole source was read adversarially again. Every finding came from a boundary the first pass had decided not to test — the publish path (no real calls allowed) and extreme inputs (max-length captions, 100MB files). The paths that had been pushed on with real calls turned up nothing more.

Left alone this time too: always returning a base64 image block for generated images (its immediate value in HITL review is worth more), tolerating a mismatch between a generated audio file's extension and its real format (renaming arbitrarily after generation is worse), and datago downloads buffering entirely in memory (bounded by the 100MB ceiling). The score stays at 96 — these fixes are new findings rather than items the first pass docked points for, and the one deduction (the behavioral eval harness) is still open.
