ElevenLabs v4 speech API

Generate a single voice or a conversation with eleven_v4. Both plugin tools use Text to Dialogue. This reference describes the current adapter; older v2/v3 measurements are historical research.

Model · Requests · Formats · Timing · Voices · Usage · Verification

Model and limits

The plugin accepts only eleven_v4. eleven_v4_turbo is a separate realtime WebSocket option and is not implemented here. Keep the saved voice and model; errors never trigger a legacy-model fallback.

The model ceiling is 10,000 characters. Dialogue documentation recommends at most 2,000 total characters for reliable generation; larger requests can fail or end early. The adapter warns above 2,000 and rejects above 10,000. REST permits 10 distinct voice IDs; the plugin also limits requests to 50 turns.

Requests and controls

tts_elevenlabs_generate maps one voice to one input. tts_elevenlabs_dialogue sends ordered turns. Both use POST /v1/text-to-dialogue; timestamps:true adds /with-timestamps. The model ID is explicit because the generic API default is still v3.

POST /v1/text-to-dialogue/with-timestamps?output_format=wav_24000
xi-api-key: YOUR_API_KEY
{
  "inputs": [{"text": "[quietly] Hello.", "voice_id": "YOUR_VOICE_ID"}],
  "model_id": "eleven_v4",
  "language_code": "en",
  "settings": {"stability": 0.5, "similarity": 0.75},
  "seed": 42,
  "previous_text": "We arrived.",
  "future_text": "Then we left."
}

Direct delivery with short [audio tags]. v4 accepts slash-delimited /IPA/ for pronunciation. SSML is rejected. Keep subtitle spelling and the exact synthesis request separately. Legacy similarityBoost aliases similarity; speed:1 is a compatibility no-op, never sent.

Output formats

Choose wav_24000 for assembly. The adapter also exposes WAV at 16, 22.05, 44.1 and 48 kHz and MP3 at 44.1 kHz / 64, 128 or 192 kbps. WAV 44.1 kHz requires Pro; MP3 192 kbps requires Creator. The filename extension must match. output_format belongs in the query, never the JSON body. Convert MP3 before using the narration pipeline.

Timing and provenance

With timestamps, the adapter decodes audio_base64 and saves both alignments and voice_segments verbatim in an alignment JSON sidecar. It also saves the provider request, output/logging options and available request ID, metered usage and latency. Do not assume normalized characters index the original text. Mixed-speaker output needs a dialogue-aware assembly route.

Voices and errors

tts_elevenlabs_voices queries GET /v2/voices with filters and pagination; preserve real IDs and preview URLs. The API key needs synthesis permission, plus voices_read for listing; optional subscription information requires user_read. Clone availability depends on the account. v4 can change a cloned voice’s sound and cross-language accent behavior, so do not regenerate existing takes merely to migrate models.

Usage and license

Use the account’s current rate. The returned character-cost is a provider-metered quantity, not a USD price; log it divided by 1,000 in the plugin ledger. Missing usage is unknown, not zero. API retries can cost money. Free-tier output is non-commercial; check the current plan license before publishing. No paid generation or listening test was run for this update.

Implementation and verification

The shared v4 skill contract covers production and targeted retakes. Tests mock provider responses to check payloads, query parameters, validation, timestamps and provenance. This is API-contract verification, not a listening-quality result. Speech stays not_reviewed.

Streaming, WebSockets and provider audio_effects are not exposed by these file-generation tools. Keep sound effects in the existing SFX workflow.
