Gemini TTS — speech synthesis

A generateContent variant that turns text into speech. It isn't a separate TTS endpoint but an ordinary generation call with responseModalities: ['AUDIO'] and speechConfig on top, so an LLM's nondeterminism comes along with it.

1. Models

Model IDCharacterStreamingFree tier
gemini-2.5-flash-preview-ttsCheapest — this server's defaultNoYes
gemini-2.5-pro-preview-ttsHigh quality. The fallback for scripts flash keeps failing onNoNo
gemini-3.1-flash-tts-previewNewest. The only TTS model with streamingYes—
Measured: the flash → pro fallback is a real failure mode. On a short two-person dialogue script, gemini-2.5-flash-preview-tts kept returning a 400 with "Model tried to generate text, but it should only be used for TTS", and swapping just the model to gemini-2.5-pro-preview-tts passed on the first try (regardless of whether the speaker names were Korean or English). The server retries 3 times automatically and then points at this fallback in the error message.

3. Request shape

Single speaker

genai.models.generateContent({
  model: 'gemini-2.5-flash-preview-tts',
  contents: [{ role: 'user', parts: [{ text: contentText }] }],
  config: {
    responseModalities: ['AUDIO'],
    speechConfig: { voiceConfig: { prebuiltVoiceConfig: { voiceName: 'Kore' } } },
    temperature: 0.4,
  },
});

Two speakers

speechConfig: {
  multiSpeakerVoiceConfig: {
    speakerVoiceConfigs: [
      { speaker: 'Host',  voiceConfig: { prebuiltVoiceConfig: { voiceName: 'Kore' } } },
      { speaker: 'Panel', voiceConfig: { prebuiltVoiceConfig: { voiceName: 'Puck' } } },
    ],
  },
}

Prefix each line of the script with the speaker name, as in Host: Hello\nPanel: Good to be here. The name must match the speaker in speakerVoiceConfigs exactly.

Style directives

Language, tone, and pace aren't request fields. You direct them in the prompt body.

Synthesize the following transcript as speech.
Director's Notes — Style: calm and trustworthy, slightly slow
--- TRANSCRIPT BEGINS ---
<transcript>
Unlabeled style: "body" synthesis fails in two ways — the classifier falsely rejects it (PROHIBITED_CONTENT), or the model reads the directive itself out loud. Spelling out the synthesis preamble and the transcript-start label as above avoids both (buildStyledPrompt).

4. Output format

ItemValue
Response locationcandidates[0].content.parts[].inlineData.data (base64)
MIMEaudio/L16;codec=pcm;rate=24000
ContainerNone — raw PCM
Sample rate24,000 Hz (the MIME rate= parameter is the source of truth)
Channels · bit depth1 (mono) · 16-bit

With no container, saving the bytes as they come leaves a file no player can play. The server puts a 44-byte RIFF/WAVE header on it and saves a .wav (media-utils.pcmToWav). The sample rate is parsed from the response MIME rather than hardcoded — if the vendor changes the value, the pitch doesn't go off.

Prompt classifier false rejectionVague directives trigger a rejectionFixed synthesis preamble (§3 above)
Cuts inside the same video must keep voiceName, stylePrompt, and temperature byte-identical. Because it's LLM-based, even a trivial rewording of the directive gets reinterpreted and the narrator's voice wobbles from cut to cut. That's why this server defaults to temperature: 0.4 instead of the vendor default (1.0).
