Lyria — music generation

One name, two APIs. Lyria 3 takes a single Interactions API call and hands back a finished track; Lyria RealTime streams PCM over WebSocket. The parameter systems, the output formats, and the reproducibility are all different.

Clip is the default path for short-form BGM. It's one call, it's cheap, and 30 seconds fits short-form length. Use RealTime only when the length has to match the narration exactly or the same track has to be reproduced across episodes.

There is also a lyria-3-pro-preview in the same family (about 1–2 minutes, MP3 or WAV), but this server doesn't expose it — a two-minute track has nowhere to go in a short-form pipeline and only adds cost.

2. Lyria 3 Clip (Interactions API)

const interaction = await genai.interactions.create({
  model: 'lyria-3-clip-preview',
  input: 'calm acoustic guitar loop, 90 BPM, warm tone, instrumental only',
});

Response shape

interaction.steps[]
  ├─ type: "model_output"
  └─ content[]
       ├─ { type: "text",  text: "…lyrics or song structure…" }
       └─ { type: "audio", data: "<base64>", mime_type: "audio/mpeg" }

The SDK also provides the convenience accessor interaction.output_audio. The field names are snake_case (mime_type, output_audio) — watch out, since the rest of the Gen AI SDK is camelCase.

Below @google/genai 2.0 this path doesn't work at all. The Interactions API's 2026-05 schema overhaul replaced the flat outputs[] with steps[].content[], and the server rejects requests on the old schema: 
The legacy Interactions API schema is no longer supported.
Please upgrade your @google/genai JS/TS SDK to version >= 2.0.0
This repo requires ^2.13.0.

What you control through the prompt

  • Genre, instruments, BPM, key, mood, and structure all go in as natural language. There are no structured fields.
  • If you don't want vocals, say instrumental only, no vocals — by default vocals can show up.
  • Specify lyric structure with the [Intro]·[Verse]·[Chorus]·[Bridge]·[Outro] tags and timestamps in the form [0:00 - 0:10] Intro: ….
  • Input is multimodal — you can pass up to 10 images along with it to direct the mood (this server exposes text only).
The policy filter is touchy (measured). "Calm lo-fi hip hop, 80 BPM, C major, soft piano and vinyl crackle" was blocked with Request blocked for an unspecified policy reason, and two alternative prompts describing the same mood in plainer words both passed. The block is a prompt problem, not a code problem, so the right response is one retry with different wording.

The output carries a SynthID audio watermark.

3. Lyria RealTime (WebSocket)

const genai = new GoogleGenAI({ apiKey, apiVersion: 'v1alpha' });
const session = await genai.live.music.connect({
  model: 'models/lyria-realtime-exp',
  callbacks: { onmessage, onerror, onclose },
});
await session.setWeightedPrompts({ weightedPrompts: [{ text: 'minimal techno', weight: 1.0 }] });
await session.setMusicGenerationConfig({ musicGenerationConfig: { bpm: 120, density: 0.4 } });
await session.play();

apiVersion — the docs and reality disagree

The official docs say v1beta, but what works when measured is v1alpha. We connected all three combinations directly and checked:
apiVersionResult
v1alphaWorks — 384,000 bytes received for a 4-second request (exactly 48,000 × 2ch × 2 bytes × 4s)
v1betaconnect() never returns and hangs
(unspecified)—
So this server stays on v1alpha. Switch to v1beta on the strength of the docs and the tool stops silently.

Stream end condition

The server doesn't signal the end of the stream. The end condition is "how much has arrived".

target bytes = requested seconds × 48,000 × 2 (channels) × 2 (16-bit)
timeout      = requested seconds × 1000 + 30,000ms

Once the target bytes are met, it closes the session, trims to exactly the requested length, puts a WAV header on it, and saves.

Session control

MethodPurpose
play() · pause() · stop()Playback control
setWeightedPrompts()Change the prompt mid-generation for a smooth transition
setMusicGenerationConfig()Change settings. bpm and scale don't take effect without reset_context() or a stop/play
reset_context()Reset just the context without cutting the stream
This server puts the settings in once before play() and doesn't change them afterward. That keeps it clear of the bpm/scale reset_context trap — passed as initial settings, they apply as given.

WeightedPrompt

{ text: "jazz piano", weight: 1.0 }

weight takes any value as long as it isn't 0. The official spec has no ±1 bounds; 1.0 is the usual starting point and larger values have more influence. Mix several prompts and they blend in relative proportion.
