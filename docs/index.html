social-flow user manual

social-flow helps you run a video channel from a local folder. You work with a coding assistant to plan episodes, review shots, assemble videos and publish to the accounts you choose. A channel keeps its cast, voice choices and visual style across episodes.

Start with Getting started. The first exercise sets up a channel and gives you a synopsis to review before you spend money on episode media.

Getting started

This walkthrough uses Claude Code and a new channel called field-notes. You will finish with a local channel profile and a short synopsis. You can leave publishing accounts disconnected.

Install and check the connection

Install Claude Code and Node.js 20 or later. From a terminal, add the marketplace and install the plugin. The plugin ships with its MCP server already built.

node --version
claude plugin marketplace add ttalkkaklab/social-flow
claude plugin install social-flow@social-flow

Create a workspace for your content. You can also use an existing project folder.

mkdir -p ~/Videos/field-notes
cd ~/Videos/field-notes
claude

In the new Claude Code session, enter /mcp and look for the connected social-flow server. Ask “Show the available project setup options using project_manage.” This reads the bundled options without creating project files. If skills appear but the tool is unavailable, check the connection before starting setup. Troubleshooting

Set up the channel

In the same session, run the following skill. Give it your chosen workspace path when prompted.

/social-flow:project-init init ~/Videos/field-notes

Use field-notes as the channel slug. For this example, choose an English-language explainer in portrait format (shorts-9x16). The assistant asks which models you can use, how the channel should look and how many shots should use generated video. You can choose existing music or no new music, and skip separate text-to-speech when the project does not need it. Choose connect later for publishing accounts you want to add later. Configuration and costs

When setup finishes, look for .social-flow/models.json and data/field-notes/profile.md. The former holds workspace choices. The profile describes the channel's audience, tone and recurring cast. To see which choices still need an answer, run:

/social-flow:project-init status ~/Videos/field-notes

Request a first synopsis

Tell the assistant what the audience should learn and which artifact you want.

For field-notes, draft a synopsis for a short called “Window Light.” Show a potter moving a cup from direct sunlight into diffuse window light so the viewer can see the glaze. Write in English and stop at the synopsis.

Read the proposed opening, what changes on screen and the final shot that proves the point. The synopsis can be revised before you request a storyboard. To continue with the same episode, follow Making an episode.

Supply credentials to the server

A local server can inherit variables from its host. It also reads ~/.config/social-flow/.env, or .env inside the directory named by SNS_TOKEN_DIR. A nonempty environment value takes precedence. Use a private editor to enter only the variables your selected providers require.

mkdir -p ~/.config/social-flow
chmod 700 ~/.config/social-flow
touch ~/.config/social-flow/.env
chmod 600 ~/.config/social-flow/.env

Keep keys out of the project settings, storyboard, prompts and issue reports. After changing variables, reconnect the MCP server or start a fresh host session. Check the configuration from that session. For ASTRA, inspect the catalog for the media type you selected. A key in a terminal alone does not establish which endpoint a running host uses.

Budget an episode

The generated-video share counts shots. For example, video_50 targets 50% to under 80% generated shots and no_video targets zero. Still images, speech and music can each have their own provider costs. An episode with no generated video can still include these assets.

Set an optional episodeBudgetUsd at project setup. Review the estimate for the episode, including possible retries, before authorizing generation. A configured cap limits spend. After a run, inspect output/video/cost-report.txt and the saved generation receipts. The provider's billing record gives the final charge.

For assembly, install FFmpeg (including FFprobe), Python 3 and Google Chrome for headless capture. Blender supports 3D location and composition work. Local transcription and local image or video models have their own runtime requirements. Requirements · Local LTX runbook

Making an episode

An episode belongs to one channel. In this walkthrough, field-notes is the channel and window-light is the episode slug. Use the same two names to resume a session. Workspace setup

Build the storyboard

After reviewing the synopsis, tell the assistant to use it for window-light. In Claude Code, the storyboard skill also takes the channel and topic directly:

/social-flow:storyboard field-notes window-light
  1. Prepare the cast. Reuse a channel character or describe a new one. Each visible cast member needs an identity and face, front and back images. A voice-only narrator needs an identity. If a panel is missing, the assistant identifies it and asks for any spending authorization needed to make it.
  2. Read the scene before reviewing its shots. For “Window Light,” the scene should establish where the cup starts, what the potter does and when the glaze becomes visible. Check who speaks and what the viewer can see during each line.
  3. Open the review page. Open data/field-notes/episodes/window-light/storyboard/storyboard.html in a browser. Keep its sibling files with it. Check the cast, shot order, framing, dialogue and planned sound. To request a correction, cite a shot or scene and the change you want.
  4. Approve the plan you want to produce. A text-only board can stop at the shot plan. You can request shot images or a camera review separately. The assistant keeps the episode's saved model choices on resume.

Produce and review the video

When the board is approved, run:

/social-flow:produce field-notes window-light

Review the cost estimate and the proposed generated shots before authorizing paid work. The production sequence prepares the props and locations, then the shot images. For generated scenes, the assistant plans a request with the ordered shots and their sound direction. Approve the shots you want to render. The assistant can then assemble the selected footage, sound and platform copy.

Play the delivered output/video/video.mp4 with sound. Check that the opening frame matches the promise, speech finishes before a cut, and the last shot shows the result. The master has no burned-in subtitles. Request a separate subtitle track if you need one. Read the caption or post for each target platform. For a dedicated thumbnail or platform crop, request the cover workflow.

/social-flow:setup-youtube field-notes

Publish to a specific platform

In Claude Code, the following command selects YouTube for this episode:

Troubleshooting

Start in the workspace that owns the episode. Keep the channel slug, episode slug and any request ID from the original operation. Those identify the existing work when you reconnect.

Symptom What to check
The skill appears, but its tools are missing In Claude Code, open /mcp and inspect the social-flow connection. The marketplace install needs Node on the host's executable path. For a clone, point --plugin-dir at the repository root.
project_setup_required Run /social-flow:project-init status with the selected workspace. Complete the listed choices with project-init. After moving a workspace, select the new directory.
A provider looks configured but the request fails capability_status reports locally visible configuration. Check the selected operation, endpoint and model catalog in the same MCP session. Restart the server after changing its environment.

Did the image provider get the request?

A timeout leaves a video producer with an awkward choice. Submitting the same shot again might buy a second image. Waiting might mean waiting for a job that never started.

From the social-flow project · Maintained by Zeans at Ttalkkak Lab

One missing frame, two possible bills

Imagine a storyboard with one image left to generate. The provider accepts the request, but the connection closes before the response reaches the editor. From the editor's side this looks much like a request that never reached the provider. An empty output directory fits both stories.

In social-flow's managed image path, the editor saves a plan and a request ID. Before calling the adapter, the server writes a receipt and reserves capacity. If the adapter loses the response, the server can still say which request it tried. An ambiguous error leaves that request in submission_unknown.

Count the calls yourself

With Git and Node.js 20 or newer, run the two regression cases below. The fake adapter either writes a one-pixel PNG or throws a timeout. The tests use a temporary episode directory and require no provider credentials.

git clone https://github.com/ttalkkaklab/social-flow.git
cd social-flow/server && npm ci
node --import ./test/isolate.mjs --test --test-name-pattern='managed success|ambiguous failure' test/image-routing.test.mjs

In the success case, calling the same plan twice returns the saved result. The dispatch counter stays at one. If the saved file changes, the hash check catches it. In the timeout case, a second call with the same request ID stops before dispatch. With the fixture's single slot occupied, giving the request a new name also stops before dispatch.

What it costs to wait

An unresolved request can hold up another shot. Reading image_status returns the recorded state. A supported adapter can refresh provider status. To close out an uncertain request manually, the operator records evidence and the amount spent. In the test, the local child exited without output and the spend is zero. A real provider needs its own evidence.

The same distinction matters when a job succeeds. A decoded image with the expected hash can still show the wrong character. The generation receipt marks it not_reviewed. Someone still has to inspect the picture.

Stock media and attribution

Use stock_search to find images or clips for a shot. Start with a literal description of the subject and its setting. If the search returns no usable match, try an English query, a wider orientation or another media type. Pexels and Pixabay require their own keys. The NASA and Wikimedia Commons searches work without a provider key.

Before using a result, open its item page and inspect the actual media. Keep the returned visual.license record with the shot, including the author, source URL, license and attribution. Check the item terms for the intended edit and distribution. An archive can hold works under several different terms.

For Korean historical material, browse the National Museum of Korea's eMuseum, the Korea Copyright Commission collection and the KTV film archive. Record the item-specific rights statement when importing media from these collections.

Video model call reference

This page records how social-flow calls each video model, model by model and operation by operation. For every engine it gives the plugin's adapter input, the request the adapter sends, and the vendor's own specification. It covers text-to-video, image-to-video, audio-to-video and reference generation, and it pays particular attention to character consistency: how a face and a voice reach the model and how many references one request can carry.

The facts were collected on 2026-11-25 from the plugin source at f4fb5359 plus the adapter changes listed under Changes made with this survey, from vendor pages fetched that day, and from read-only calls to the services that were reachable. Each engine section has its own numbered source list; [n] refers to that section's list. A value no source confirmed is marked unverified.

The plugin's own schema is authoritative for what a call accepts. video_catalog {engine, operation} returns each adapter's parameters as JSON Schema, read from the adapter's zod schema, and video_plan reports the limits it applied. Changes made with this survey

The survey found adapter defects. These were fixed in the same change:

  • Hosted LTX API — data URI limits (7 MB image, 15 MB audio) are now checked on the base64 size, as the vendor measures them. A 6 MiB PNG used to pass the plugin and fail at the vendor.
  • Veo — adapters take enhancePrompt and send it when the call sets it. Vertex defaults to true and may rewrite the prompt; false is not the default yet because no live call has confirmed that the 3.1 models accept it.
  • MLX-Serve LTX — the decoded RGB cap is 768 MiB, MLX-Serve's own limit (was 800 MiB).
  • Seedance 2.5 — the face-video note uses @Video N, matching the rest of a 2.5 prompt.
  • MiniMax — both adapters take generateAudio, sent as generate_audio. Planning now sets it on minimax_img2video shots without lines: true keeps scene sound, false when the shot's sound is an external speech track or its direction reads silent.
  • LTX Desktop — extend and retake now send promptProvenance:"enhanced" for a written prompt (Desktop rewrites typed prompts there too); the local adapter no longer accepts .ogg, which Desktop's asset ingest refuses; a model whose spec reports capabilities: null no longer breaks the local catalog.

Each engine section lists the differences that remain open.

ASTRA GenAI gateway (LTX-2.5 and Licon MSR)

The in-house GenAI gateway runs the open LTX-2.5 22B weights (distilled and dev) and the Licon MSR IC-LoRA on its own GPUs. Its per-model /v1/ltx/v2/* routes copy the names of Lightricks' hosted API [12]; the plugin calls none of them. Every GenAI video request goes through the gateway's common generation API: POST /v1/generations, POST /v1/generations/validate, GET /v1/generations/{id} and GET /v1/models (user directive, 2026-11-25). The saved selection for LTX is {engine:"astra-genai", model:"ltx-2.5-22b-distilled", operation:"reference", resolution:"1792x1024"} (1024x1792 for 9:16) (model-settings.md). Status: current. Credentials: ASTRA_GENAI_API_KEY, with the base URL in ASTRA_GENAI_URL (astra-genai-client.ts). The Desktop adapters (astra_genai_desktop_*) and the legacy astra_* tools are separate families.

The render records are one token's job history, about 24 hours long. A finished job says nothing about output quality. The job status does not show whether an I2V job carried MSR references.

Calling it

  • Submit: POST /v1/generations {kind:"video", model, mode, input, parameters} with mode text2video, image2video, audio2video, msr or scene. The gateway answers 202 with {id}. A scene is first sent to POST /v1/generations/validate, which reserves nothing.
  • Poll: GET /v1/generations/{id}. Status is queued|running|succeeded|failed|cancelled, and the file URL is outputs[0].url (astra-genai-video.ts).
  • Timing: the plugin polls for up to 30 min and waits up to 15 min for the submit acknowledgement (astra-genai-client.ts). POSTs are never retried.
  • Receipt: a receipt beside the output records the job id. Recovery reads the receipt and never resubmits. A scene is posted under an X-Request-Id derived from its exact body and output path, and the body is kept beside the receipt; within 23 hours video_status recovers a lost response by posting that body again, which returns the first job [12].
  • Uploads: local pictures and voices go up first through the chunked POST /v1/uploads and travel as genai-file:// ids (astra-genai-upload.ts). Each file may be at most 32 MiB. If the gateway has no upload API, the inline body is capped at 8 MB.
  • Result URL lifetime: unverified for /v1/generations outputs.

Text-to-video

  • Plugin input (astra-genai-video.ts):
  • prompt: 1–2000 characters.
  • model: distilled or dev.
  • resolution: WxH with even sides of at least 64. The sides, rounded up to multiples of 64, must each be at most 1920 and multiply to at most 2,064,384.
  • Length: duration (integer ≥1, or null for automatic length) or numFrames (25–361, 8k+1).
  • fps: 24, 25, 48 or 50 (default 24). generateAudio: default true.
  • seed, numGeneratedKeyframes (0–16).
  • lora: 1–2 names, plain distilled only. The live catalog lists cinemagraph and slow-motion [13].
  • Dev only: negativePrompt (≤2000), numInferenceSteps (1–50) and guidance.
  • Wire request: POST /v1/generations {kind:"video", model, mode:"text2video", input:{text}, parameters:{width, height, fps, generate_audio, duration_seconds|num_frames, seed?, lora?, num_generated_keyframes?, guidance?, num_inference_steps?, negative_prompt?}}. Optional fields are first checked against /v1/models parameters_by_mode. The plugin's bodies for every direct mode pass the gateway's own VideoGeneration model and adapter (docs/loops/038-genai-common-api/gateway-validate.md).
  • Limits:
  • Frames: 25–361, 8k+1. The gateway rounds a duration up to 8k+1 and trims back [12]. The 8k+1 rule comes from the model [5].
  • Prompt: 2000 characters on the local backend; the gateway schema allows 5000 [12].
  • Audio: generate_audio switches the soundtrack on or off.
  • Plugin vs vendor:
  • The hosted API takes only presets: 6–20 s, 720p to 4K, and a camera_motion enum [7][8]. The gateway takes any even WxH and refuses camera_motion [12].
  • The gateway still accepts shots (2–4). The plugin no longer sends it.

Image-to-video

  • Plugin input: everything in Text-to-video, plus:
  • Start image: exactly one of imageUri or imagePath. PNG or JPEG, at most 32 MiB and 4096 px per side.
  • End image: optional lastFrameUri or lastFramePath.
  • keyframes[]: {frameIdx 0–360, strength 0–1, crf 0–51}. Start, end and keyframes share 8 slots, and every index must be distinct and inside the clip.
  • An end image or keyframes need duration or numFrames.
  • Without references the prompt is capped at 2000 (astra-genai-video.ts).
  • Wire request: POST /v1/generations {…, mode:"image2video", input:{text, images:[{url}], last_frame?:{url}, keyframes?:[{url, frame_idx, strength?}], references?}}.
  • Limits: frames and resolution as in Text-to-video. The live /v1/models I2V limits are first_frame:1, last_frame:1 and temporal_images_including_endpoints:8 [13]. An end image cannot be combined with automatic length [12].
  • Plugin vs vendor:
  • Hosted I2V takes only a first and a last frame [9].
  • The open pipelines take --image PATH FRAME_IDX STRENGTH repeatedly, with no count limit found in the code [5]. The gateway and the plugin cap the pins at 8.

Audio-to-video

  • Plugin input (astra-genai-video.ts):
  • Audio: exactly one of audioPath or audioUri. Formats .wav .mp3 .m4a .ogg .opus. A data URI may hold at most 15,000,000 base64 characters.
  • prompt: 1–2000 characters.
  • Optional start image, plus an end image that needs the start image. Keyframes share 8 slots with the endpoints.
  • fps: 24, 25, 48 or 50.
  • Dev only: negativePrompt, guidance and numInferenceSteps.
  • There is no duration field; the audio sets the length.
  • Wire request: POST /v1/generations {…, mode:"audio2video", input:{text, audio:{url}, images?:[{url}], last_frame?, keyframes?}, parameters:{width, height, fps, seed?, guidance?, negative_prompt?}}.
  • Limits [12]:
  • Frames: the shortest 8k+1 count (at least 25) that covers the audio, up to 361. That is 15.04 s at 24 fps.
  • Channels: mono or stereo; three or more answer 422.
  • Sample rate: an AAC standard rate between 7350 and 96000 Hz, otherwise 422.
  • Output: the engine muxes the input once as AAC, and the trim copies that stream.
  • Voice: supplied full track only.
  • Plugin vs vendor:
  • The local backend runs dev only. The plugin enum also lists distilled, which the live catalog does not offer, so the plugin refuses it before submission [12][13].
  • Hosted A2V needs at least 2 s of audio. Its maximum is 10 or 20 s by model and resolution [10].

Reference

  • Plugin input (astra_genai_msr, astra-genai-video.ts; msr-opening.ts):
  • references[]: 1–5 entries {imageUri|imagePath, background, nonCharacter?, audioUri|audioPath?}.
  • openingPositions[]: required, {character, images:[subject numbers], position}.
  • referenceStrength: 0–1, default 1. referenceFrames: 25 or 33, default 33.
  • width and height: multiples of 64 from 64 to 1920, at most 2,064,384 px in all. Default 1536×1024.
  • Length: numFrames (25–361, 8k+1, default 121) or duration, which rounds to the nearest 8k+1.
  • frameRate: 1–60, default 24. seed: default 42.
  • skipStage2: renders at half size.
  • negativePrompt needs guidanceScale above 1 or nagScale above 0.
  • astra_genai_img2video with references follows the same rules and adds the start and end images and keyframes. That form is distilled only and needs an explicit length.
  • Wire request: POST /v1/generations {kind:"video", model:"ltx-msr", mode:"msr", input:{text, images:[{url, background, audio?:{url}}]}, parameters:{width, height, fps, seed, num_frames, reference_strength, reference_frames, skip_stage_2?, negative_prompt?, guidance_scale?, nag_*?}}. The plugin prefixes the prompt with Opening frame, from the viewer’s perspective: followed by one line per character, <character> (Image 1, Image 2): <position>. That header counts toward the prompt limit.
  • Checks before submission: optional fields and the prompt cap are read from the model's GET /v1/models row; the gateway refuses at submission what its backend does not take.
  • References per request:
  • Images: 4 subjects plus 1 background, 5 in all [1][3][12][13].
  • Videos: none.
  • Audio: up to 2 voice samples, so 7 files in all.
  • Size: each picture at most 32 MiB and 4096 px per side (astra-genai-client.ts 112-128).
  • Strength: the live gateway pins reference_strength at exactly 1.0, and lower values answer 400 for GPU memory [13].
  • Identity: slot order is the order of the non-background references[] entries. The gateway always moves the background to the last slot [12]. The prompt names pictures Image N, and the background takes the next number.
  • Voice:
  • Binding: references[i].audio_uri on subject 1 or 2 pairs with that picture [1][12]. A sample on the background or on subject 3 or later is refused.
  • Speakers: 2 per render [3]. Lightricks calls two speaking subjects "the practical sweet spot" and suggests covering a third with cuts [4]. A third speaker can still talk without a sample, voiced from the prompt.
  • Length: the V2 weights condition on the first 5 s (reference_audio_slot_duration_seconds = 5.0, read from the weights' header). The tail is cut and a short clip is not padded [2][3]. The gateway accepts up to 10 s [12].
  • Plugin checks: refuses a sample over 10 s and warns over 5 s (video-voice.ts); the scene path refuses one over 10 s before anything is reserved (genai-scene.ts checkSceneVoices).
  • Audio output: MSR always renders speech and effects natively. On I2V with references, generateAudio:false mutes the output after the render [12].
  • First frame with references:
  • Allowed only through astra_genai_img2video with distilled. The gateway checks image_conditioning, which is true today [13].
  • astra_genai_msr takes no frame pins.
  • No upstream source combines frame pins with MSR, and the gateway README leaves the quality to a GPU check after deployment [12].
  • Prompt labels:
  • Reference line: Audio N: <name>'s voice, belongs only to Image N.
  • On-screen turn: Turn K: Image N (<name>) speaks using Audio N. … Audio N (Image N): "<line>".
  • Scene-direction boards: <id> (Image N, Audio N): "<line>" (video-voice.ts).
  • The model card advises labels such as Image 1 and Image 2 and matching each audio to its subject [3].
  • Plugin vs vendor:
  • Licon's Guide still accepts a hidden audio_ref3 [1]. The card, the gateway and the plugin all use 2 voices.
  • Prompt limit: the schemas advertise 5000. The deployed MSR backend reports 2000 [13]; the gateway refuses a longer prompt at submission.
  • referenceStrength is advertised as 0–1 but live is fixed at 1.0. The plugin refuses other values before submission.
  • Known model issue: environmental sound needs background music in the voice sample [3].

Scene

The planner composes the scene as one LTX MSR render and names each input after the cast member and picture it shows ({hero.face}, {hero.voice}, {opening.image}).
  • Wire request:

``` POST /v1/generations/validate (free; no job) POST /v1/generations (X-Request-Id: scene-)

{kind:"video", model, mode:"scene", input:{prompt, cast:[{id, images:[{role, uri}], voice?:{uri}}], references:[{id, role, uri}], shots:[{id, seconds, image?:{uri, strength?}}]}, parameters:{width, height, fps, seed?}} ```

The gateway numbers the names (voiced cast first, then cast order, objects, background last) and adds no sentence. LTX Desktop

LTX Desktop is Lightricks' open-source desktop app, and it runs LTX models on the machine it is installed on [1]. The plugin reaches it in two ways:

  • Gateway Desktop ({engine:"astra-genai-desktop"}, deployment gateway-desktop-v1): an ASTRA GenAI gateway forwards jobs to a Desktop app on the gateway's own host [17][18].
  • Credentials: ASTRA_GENAI_DESKTOP_URL and ASTRA_GENAI_DESKTOP_API_KEY. Without them it falls back to ASTRA_GENAI_URL and ASTRA_GENAI_API_KEY (astra-genai-client.ts).
  • Local app ({engine:"ltx-desktop-local"}, deployment native-desktop-loopback): the plugin calls the Desktop backend on the MCP host.
  • Address: LTX_DESKTOP_BASE_URL, default http://127.0.0.1:41954, loopback only [13].
  • Credential: the backend bearer LTX_DESKTOP_API_KEY [14] (ltx-desktop-local.ts).

Status: current, local. On 2026-11-25 the configured production gateway answered /v1/ltx/desktop/models with HTTP 503 "Desktop is not configured", and no local app was running on the survey machine. Every per-device cell below is therefore unverified.

Calling it

Gateway (astra-genai-desktop.ts): 1. Each input file goes to POST /v1/ltx/desktop/assets as multipart file, which returns {id}. - The asset is owned by the token and expires 24 h after creation [22]. - Accepted inputs: .png .jpg .jpeg .webp .wav .mp3 .m4a .mp4 .mov .webm, at most 100 MiB each and at most 50 MiB for images [18]. 2. The plugin writes a receipt <video>.astra-genai.json, then calls POST /v1/ltx/desktop/generations/{feature}. The answer is 202 with a job id [17]. 3. It polls GET /v1/ltx/desktop/generations/{id} every 5 s for up to 30 min (astra-genai-client.ts). - status is queued | running | cancelling | succeeded | failed | cancelled. - The job also carries outputs[], resolved_params and error [18]. 4. It downloads the one media_kind:"video" output from its url (/v1/ltx/desktop/assets/{id}/bytes) with the same token. The lifetime is the asset's 24 h [18][22]. 5. Recovery uses astra_genai_desktop_status with the receipt. The plugin never resubmits.

Local (ltx-desktop-local.ts, vendor-video.ts): 1. It reads GET /api/generate/models-specs to check the cell. A model whose spec.capabilities is null (allowed by [1]) reads as unavailable. 2. It registers each file by path with POST /api/assets {path} [1]. 3. It submits POST /api/generations/{feature} and reads id [2]. 4. It polls GET /api/generations/{id} every 2.5 s, up to 1440 polls (60 min). The error_code values are listed in [1]. 5. It downloads GET /api/assets/{id}/bytes and checks for an MP4 ftyp box.

Desktop ingest accepts images .png .jpg .jpeg .webp up to 50 MiB and 50 MP, and audio .wav .mp3 .m4a up to 100 MiB [7]. The local adapter checks the same extensions before calling the app, so .ogg is refused.

Calling it

  • Submit: POST /v2/{endpoint} with Authorization: Bearer <key> and a JSON body. The response is 202 {id, created_at} [1][10]. The whole body is capped at 32 MB, else 413 request_too_large_error [8].
  • Poll: GET /v2/{endpoint}/{id}. status is pending, processing, completed or failed. A failed job still answers HTTP 200 with error{type,message} [10][4]. The vendor asks for at least 5 s between polls, with jitter [10].
  • Result: result.video_url. The signed URL expires one hour after the status check; a new poll returns a fresh one. Job status is kept up to 24 h after the job ends, then 404 [4][10].
  • Plugin: polls every 6,000 ms, at most 300 times (30 min), then stops and asks for video_status action:reconcile. It never repeats the paid POST (ltx-api-video.ts, vendor-video.ts).
  • No webhook, no idempotency key, no seed, no negative prompt. None of these appears in the OpenAPI spec [1]. A failed job cannot be resumed and must be submitted again [12].
  • Concurrency: 2 running jobs per organization by default, up to 100 waiting in pending; the next submission returns 429 rate_limit_error [11].
  • Output: MP4, H.264 8-bit 4:2:0, BT.709 SDR, AAC stereo. No codec option [9].

Retake and extend

The vendor offers these for ltx-2-3-pro only; the plugin does not expose them [1].

  • POST /v2/retake requires video_uri, start_time and duration.
  • The input video may be up to 3840x2160 and must have at least 73 frames.
  • The section is at least 2 s and at most 505 frames, and at least 2 s must remain after start_time.
  • mode is replace_audio, replace_video or replace_audio_and_video (the default).
  • Billed at $0.10 per second of input video [1][13].
  • POST /v2/extend requires video_uri and duration.
  • duration is 2–20 s. mode is end (the default) or start.
  • context is 1–20 s, and context + duration must be at most 505 frames. The input video may be up to 100 MB.
  • Billed at $0.10 per second of the extension plus context [1][8][13].

Video post-processing

The vendor offers these; the plugin does not expose them. Each takes video_uri and no model: /v2/video-to-video-hdr, /v2/video-to-video-reframe, /v2/video-alpha-gen and /v2/video-upscale [1][15]. Input video may be up to 200 MB [8].

  • It decodes each reference video to 24 fps JPEG frames, with a long side of 768 px at most.
  • It keeps at most numFrames frames, snapped down to 17k+5. A clip that would lose frames is refused unless trimReferenceVideos is set.
  • It converts soundtracks and standalone audio to 32 kHz stereo PCM16 WAV.
  • Limits:
  • Frames: 24 fps. The plugin range is 124–362 frames (5.17–15.08 s). FastVideo and diffusers accept the same range [6][7]. The MiniMax card states output of 4–15 s [5]. MLX-Serve snaps any count of 5 or more up to 17k+5 [1].
  • Scene length: for a scene, the plugin renders the next 17k+5 count above the authored length, then trims to it fasth3-omni.ts.
  • Canvas: the plugin caps decoded RGB at 256 MiB fasth3-omni.ts. MLX-Serve caps it at 768 MiB and also checks memory per request [1]. MiniMax defaults to a 768 px short edge and supports 21:9 to 9:16 [5].
  • Prompt: the plugin allows 32,000 chars; the server limit is unverified.
  • Audio: always on, 32 kHz stereo [2][5]. There is no switch. The plugin fails a take that comes back silent when voice samples were sent mlx-serve-client.ts.
  • References per request:
  • Counts: ≤9 images, ≤3 videos, ≤3 audio clips, ≤12 files in total, and at least one image or video [1][4][5].
  • Clip length: the plugin requires each video and audio clip to be 2–15 s, with each type at most 15 s in total. This matches MiniMax's stated limits [5]. MLX-Serve itself enforces only a minimum of 5 frames per video [1].
  • Encoded upload: the plugin caps it at 60 MiB. MLX-Serve accepts bodies up to 512 MiB [1].
  • Identity:
  • There is no identity field. A picture is identified by its position in ref_images, and the prompt names it <Picture i>.
  • The plugin maps a speaker to pictures only through the character's voiceReference.imagePaths, never by array position. It refuses an on-screen speaker without an owned face and a pinned sample (character_voice_required) video-voice.ts.
  • Voice:
  • The binding is written in the prompt only. The plugin adds <Name> (speaker <id>), shown in <Picture i>, uses <Audio j> for voice timbre only.
  • Each line becomes <Subject N> (<Name>, <Picture i>, <Audio j>) (SN) says <d>[<Language>] <words></d>, and dialogue that contains <d> is refused video-voice.ts.
  • The plugin allows up to 3 speakers per render (referenceAudioPaths maximum), within the 12-file total video-registry.ts.
  • The voice is imitated, not preserved. The plugin checks whether the sample was replayed into the take (voiceReferenceCheck) fasth3-omni.ts.
  • First frame with references: MLX-Serve accepts both in one request [1]. The plugin does not send frames. Quality is unverified.
  • Prompt labels:
  • Labels are <Picture i>, <Video k> and <Audio j>, numbered from 1 within each type, in the order images, videos, standalone audio [1][4][7].
  • A reference video's soundtrack takes an <Audio j> number ahead of every standalone clip. With one video that has sound plus one voice sample, the soundtrack is <Audio 1> and the sample is <Audio 2> [1][5].
  • The plugin counts soundtracks with ffprobe and shifts the sample numbers video-voice.ts.
  • MiniMax's documented prompt adds a subject_definitions: line such as <Audio 2> is the voice timbre reference for <Subject 1>'s voice [5].
  • Plugin vs vendor:
  • RGB cap: 256 MiB in the plugin, 768 MiB in MLX-Serve. The plugin refuses 1344×768×124 (384 MB).
  • Reference video length: by default the plugin refuses a reference video longer than the output. MLX-Serve would cut it silently [1].
  • Clip seconds: the 2–15 s per clip and 15 s total rules come from MiniMax's hosted-model card [5], not from MLX-Serve.
  • Audio cap: MLX-Serve's limit of 3 audio clips counts only ref_audios. Soundtracks count toward the 12-file total [1].

Calling it

  • Submit: POST {base}/contents/generations/tasks. The default base is https://ark.ap-southeast.bytepluses.com/api/v3 [1].

  • The body must be at most 64 MB [1]. The plugin checks this before sending (seedance-client.ts).
  • Poll: GET {base}/contents/generations/tasks/{id} [2].
  • status is one of queued, running, succeeded, failed, cancelled or expired.
  • On success, content.video_url holds the video and usage.completion_tokens the billing basis.

Text-to-video

  • Plugin input (seedance-client.ts):
  • prompt: string, required, no maximum length.
  • model: default dreamina-seedance-2-0-260128.
  • resolution: 480p, 720p, 1080p or 4k; default 720p. A resolution the model lacks is refused.
  • durationSeconds: integer, default 5. Range 4–15 on 2.0 and 4–30 on 2.5, or -1 to let the model choose.
  • ratio: 16:9, 9:16, 4:3, 3:4, 1:1, 21:9 or adaptive; default 16:9. Planning sets 9:16 on a shorts-9x16 board.

  • The vendor's ratio default is adaptive on 2.x; the plugin's is 16:9.
  • The vendor's 2.5 duration default is -1; the plugin's is 5.

  • Submit: POST https://api.minimax.io/v2/video_generation with Authorization: Bearer <key>. The response is {"task_id": "…"} [1].
  • Poll: GET /v2/query/video_generation/{task_id} returns task.status, one of queued, running, succeeded, failed or cancelled. A failure carries task.error {code, message}. Only tasks from the last 7 days can be queried [2]. MiniMax recommends polling every 10 s [6].
  • Result: task.content.url, which is time-limited. The exact lifetime is unverified [2]. task.usage reports billed seconds and the input image count [2].
  • Plugin: the submit timeout is 5 min. The plugin polls every 10 s, up to 180 times (30 min). It accepts both the task and the flat response shape. After a timeout it asks for video_status reconcile and never resubmits (minimax-video.ts, vendor-video.ts). A 4xx answer is terminal except 408, 409, 425 and 429.
  • Other endpoints the plugin does not call:
  • list: GET /v2/query/video_generation?page_num&page_size&filter.* [3]
  • cancel or delete: DELETE /v2/video_generation/{task_id}. Only a queued task can be cancelled, and cancelling it costs nothing [4].
  • callback_url, which must echo a challenge within 3 s [1]
  • China region: platform.minimaxi.com redirects to platform.minimax.cn, whose API host is api.minimax.cn [16]. The plugin uses only api.minimax.io.

Text-to-video

The vendor offers this; the plugin does not expose it. The request content is a single text item. ratio is required and cannot be adaptive [1]. All seven V2 models support it [1][7].

Image-to-video

  • Plugin input (minimax_img2video, minimax-video.ts):
  • prompt: string, 1–7000.
  • model: one of the four IDs; default MiniMax-H3.
  • resolution: 480P, 768P or 2K; default 768P. Checked per model: MiniMax-H3 allows 768P/2K, the others 480P/768P.
  • durationSeconds: int, 4–15, default 5; Max needs at least 5.
  • generateAudio: optional boolean.
  • sourceImagePath: required; PNG, JPEG or WEBP.
  • lastImagePath: optional.
  • There is no ratio field; the vendor ignores ratio on this operation anyway [1].
  • Wire request: POST /v2/video_generation json { "model": "MiniMax-H3", "content": [ {"type":"text","text":"…"}, {"type":"image_url","image_url":{"url":"data:image/png;base64,…"},"role":"first_frame"}, {"type":"image_url","image_url":{"url":"data:…"},"role":"last_frame"} ], "resolution": "768P", "duration": 5, "generate_audio": false }
  • generate_audio is sent only when generateAudio is set.
  • On MiniMax-H3-Max the body adds "extra": {"prompt_expansion_mode": "disabled"}.
  • For a shot with no lines the planner sends generateAudio. It is false when the shot's sound source is speech (an external voiceover track) or its sound direction reads silent. Otherwise it is true, so the clip keeps its scene sound (video-routing.ts).
  • Limits [1][6]:
  • One first frame and one last frame.
  • Each image is JPG, JPEG, PNG, WEBP, HEIC or HEIF, at most 30 MB, 256–5760 px per side, with an aspect ratio (w/h) of 0.4–2.5.
  • The image sets the output ratio.
  • Durations, resolutions and the audio switch are as above.
  • Plugin vs vendor:
  • The vendor's content rules allow a last frame alone. Its own role description says a last frame "must be paired with first_frame" [1]. The plugin requires a first frame either way.
  • The plugin sends images only as inline data URIs (30 MiB per file on disk). It does not accept HEIC/HEIF, URLs or mm_file://.
  • The plugin does not check pixel size or aspect ratio. The vendor rejects bad images with 400 after the POST; that answer is terminal and no job is created.
  • The plugin refuses spoken cuts on this tool: its voice lane is none and dialogue is refused (video_catalog).

Audio-to-video

The vendor does not offer this as a mode. V2 has no field for a full soundtrack that drives the clip. Audio enters only as reference_audio in a reference request: at most 3 clips, 2–15 s each, 15 s in total [1]. The H3 reference prompt guide defines a fully_copy marker, "the complete source audio serves as the target video's complete final audio track" [10]. Whether the hosted API honours it is unverified. The plugin exposes no audio-to-video route. minimax_reference reports suppliedSpeech: "unsupported" and exactAudioPreservation: false (video-registry.ts).

Reference

  • Plugin input (minimax_reference):
  • the common fields above, including generateAudio
  • ratio: adaptive, 21:9, 16:9, 4:3, 1:1, 3:4 or 9:16; default adaptive. Lite refuses adaptive.
  • referenceImagePaths: 1–9, required.
  • referenceAudioPaths: 0–3 WAV or MP3 files, default [].
  • The planner uses it only for shots in which a character speaks. Silent and voiceover shots are refused with reference_speech_route (video-routing.ts).
  • Wire request: POST /v2/video_generation json { "model": "MiniMax-H3", "content": [ {"type":"text","text":"…"}, {"type":"image_url","image_url":{"url":"data:…"},"role":"reference_image"}, {"type":"audio_url","audio_url":{"url":"data:audio/wav;base64,…"},"role":"reference_audio"} ], "resolution": "768P", "duration": 6, "ratio": "9:16" } Pictures go first, then audio. Before submitting, the plugin reads each sample's length with ffprobe: 2–15 s each and at most 15 s in total. A file over 15 MiB is refused (minimax-video.ts).
  • Limits: duration, resolution, fps, the prompt limit and generate_audio are as in Calling it, above. MiniMax-H3-Lite and MiniMax-H3-NC need a concrete ratio [1].
  • References per request [1][6][9]:
  • Images: at most 9; 30 MB each, 256–5760 px, aspect ratio 0.4–2.5.
  • Videos: at most 3; MP4 or MOV, H.264 or H.265, at most 50 MB each, 2–15 s each, at most 15 s in total, 23.976–60 fps.
  • Audio: at most 3; WAV or MP3, at most 15 MB each, 2–15 s each, at most 15 s in total.
  • All files together: at most 12.
  • The create page gives one table for every model. No per-model reference counts are documented.
  • Identity: no identity field exists. A reference_image is tied to a character only by prompt text [1].
  • The planner sends the cast's sheet panels in cast order with the background picture left out. The shot's start image goes last.
  • It adds an "Image reference roles:" block that names each picture's role.
  • More than two referenced characters are refused (msr_character_limit) (video-image-inputs.ts).
  • Voice: a reference_audio clip is tied to a speaker only by prompt text.
  • MiniMax's API example reads "Voice timbre follows reference audio 1" [1].
  • The H3 guide writes <Audio 1> is the voice-timbre reference for <Subject 1> (S1). [10].
  • The plugin writes " (speaker ), shown in reference image i, uses reference audio k for voice timbre and accent only. Speak the authored shot dialogue, not the sample's words." (video-voice.ts).
  • At most three sampled speakers fit in one render (maxPinnedVoicesPerRender: 3).
  • MiniMax states no limit on speakers and no claim of voice consistency across renders.
  • First frame with references: not allowed. "Image-to-video and reference-to-video are mutually exclusive" [1]. The plugin sends the start image as the last reference_image, so the opening frame is not pinned.
  • Prompt labels:
  • The plugin writes reference image N and reference audio N (scene-prompt-profile.ts).
  • MiniMax documents three styles:
    • plain ordinals in the API examples ("reference images 1 and 2", "reference video 1") [6]
    • "Image 1: …" in the feature gallery [8]
    • <Subject N>, <Picture N>, <Video N> and <Audio N> in the guide, with speaker IDs (S1) and dialogue in <d>[Language] …</d> [10][19]. Video and audio labels are numbered separately.
  • Plugin vs vendor:
  • The plugin sends no reference_video (the vendor allows 3).
  • Spoken shots are capped at two characters, while three voice samples are allowed.
  • The plugin blocks adaptive on Lite but not on NC. NC is not in the plugin.
  • MP3 is sent as data:audio/mpeg. MiniMax asks for data:audio/<format> [1]. Whether mpeg is accepted is unverified.

HeyGen

HeyGen Video 1 (heygen-video-1) is HeyGen's prompt-to-video model, built on MiniMax H3 and post-trained by HeyGen [1]. It renders picture and sound in one call. The plugin calls it through the common hosted-vendor layer as deployment heygen-v3 (video-registry.ts). The saved selection is {engine:"heygen", model:"heygen-video-1", resolution:"768p", operation:"reference"} (model-settings.md). Status: current. Credential: HEYGEN_API_KEY.

Calling it

  • Every local file is uploaded first with POST https://api.heygen.com/v3/assets (multipart field file). The returned data.asset_id is passed as {type:"asset_id", asset_id} (heygen-video.ts).
  • An asset ID does not expire [4]. The vendor also accepts url and base64 inputs [1]; the plugin never sends them.
  • Submit: POST /v3/models/videos with header x-api-key. The answer is 202 with data.video_id and status:"pending" [2]. The plugin waits up to 5 minutes for that answer.
  • Poll: GET /v3/models/videos/{video_id} [3]. Statuses are pending, processing, completed, failed and cancelled. On failure the record carries failure_code, one of generation_failed, generation_cancelled or usage_limit_reached, with failure_message [3].
  • The plugin polls every 5 s, up to 360 times (30 minutes) (heygen-video.ts). A job still running after that is reported and never resubmitted (vendor-video.ts).
  • Result: data.video_url is a signed link, and a new poll returns a fresh one [1][3]. Its lifetime is unverified.
  • Retries: the vendor takes an optional Idempotency-Key header. A repeat with the same key within 24 hours replays the original answer, and a repeat while the original is in flight returns 409 [2]. The plugin sends no key.

Image-to-video

  • Plugin input
  • heygen_img2video takes prompt (1–16,000), resolution (480p | 768p, default 768p) and durationSeconds (integer 5–15, default 5).
  • It also takes seed (0–4,294,967,295, optional), sourceImagePath (required) and lastImagePath (optional) (heygen-video.ts).
  • The voice lane is none, so spoken cuts are refused with voice_lane_required (video-registry.ts, video-voice.ts).

  • First and last frame: image is the literal first frame, and its EXIF orientation is followed. end_image guides the last frame and requires image [1][2].
  • Ratio: the output always follows image. A supplied aspect_ratio is ignored [2].

  • The plugin offers only 480p and 768p. Its code comment says 1080p and 2k have no published standard price (heygen-video.ts). The help center lists those prices as "—" after the promotion [13].

Audio-to-video

Video 1 has no supplied-track mode in HeyGen's official documents. One secondary source says a reference_audio clip becomes the clip's soundtrack when the prompt says "his speech is <Audio 1>, word for word" [14]. This is unverified with HeyGen.

The vendor offers supplied-speech rendering on other endpoints; the plugin does not expose any of them:

  • Avatar 6 — POST /v3/models/avatars, then poll GET /v3/models/videos/{id}. Fields [9]:
  • model is heygen-avatar-6 or heygen-avatar-6-turbo.
  • reference_images takes one image and reference_videos one video of at least 2 s. A realistic-human video needs Enterprise access, else 422 realistic_human_reference_not_allowed.
  • audio is required, and the video runs the length of the audio.
  • resolution is 1080p (default) or 2k, and the ratio follows the reference.
  • motion_prompt takes up to 1,200 characters, and motion_expressiveness is default or less.
  • Talking Photo (Avatar IV) — POST /v3/videos type:"image". It takes image plus either script with voice_id, or audio_url, or audio_asset_id [10][11].
  • The image needs a detectable human-like face, or the call returns 400 [10].
  • Resolution is 720p or 1080p [10].
  • Audio is MP3 or WAV up to 32 MB, and up to 30 minutes per request [11].
  • Avatar video from audio — POST /v3/videos type:"avatar" with audio_url or audio_asset_id, on an owned avatar look [11].
  • Lipsync — POST /v3/lipsyncs puts new audio on an existing video [7]. This is post-render lip-sync, which the project forbids for synthesized speech.

  • HeyGen documents reference_audio only as "Reference audio recordings. At most three." It has no voice_id and no field per subject [2]. The binding lives in prompt text.
  • A secondary source shows two uses. "speaks … in the voice of <Audio 1>" takes pitch and timbre and ignores the sample's words. "the advisor from <Picture 1> in the voice of <Audio 1>, the client from <Picture 2> in the voice of <Audio 2>" binds two speakers [14].

  • First frame with references — not allowed together. image and end_image exist only in image_to_video, and a field from another mode returns 400 [1][2]. The shot's start image is sent as a picture reference and is not pinned as the first frame.
  • Prompt labels
  • The plugin writes <Picture N> and <Audio N> (scene-prompt-profile.ts).
  • HeyGen documents <Picture N> and <Video N> and says images, videos and audio are numbered independently. It never writes <Audio N> [1]. That form appears only in the secondary source [14].
  • Prompt enhancement does not rewrite labels [1].
  • Plugin vs vendor
  • reference_videos is not exposed.
  • The plugin requires at least one image. The vendor pages disagree on whether audio alone is allowed: the model page needs an image or video [1], while the OpenAPI example and the MCP tool text allow audio only [2][7].
  • The plugin's 12-reference cap is lower than the 15 on the model page. It cannot be reached in practice, because the plugin sends at most 9 + 3.
  • The plugin's voice sentence differs from the secondary source's tested phrase "in the voice of <Audio N>" [14].

Calling it

Every operation uses the same submit and poll calls on the model resource projects/{GOOGLE_CLOUD_PROJECT}/locations/us-central1/publishers/google/models/{model} [2][5]veo-video.ts.

  • 16:9 or 9:16 [1]. Output 720p or 1080p, plus 4K on veo-3.1-generate-001 only [1].
  • Prompt length: unverified. No fetched page states a limit.
  • The documented prompt language is English [1].
  • Native audio is controlled by generateAudio, default true [3].
  • Dialogue: the model synthesizes speech from the prompt.
  • Google writes speech as A woman says: My name is Clara., with a colon and no quotation marks, so no text is drawn [10][11].

  • The scene compiler writes Speaker (delivery): "line" with quotes (scene-prompt.ts), against Google's advice [10].

Image-to-video

  • Plugin input:
  • sourceImagePath (required): the first frame.
  • lastImagePath (optional): the last frame.
  • durationSeconds 4, 6 or 8 (default 8).
  • Images must be PNG or JPEG of at most 20 MB (veo-video.ts).
  • Wire request: {"instances":[{"prompt":"…","image":{"mimeType":"image/png","bytesBase64Encoded":"…"},"lastFrame":{"mimeType":"image/png","bytesBase64Encoded":"…"}}],"parameters":{…}}.
  • Limits:
  • Durations, frame rate, aspect ratios and resolutions are the same as text-to-video [6][7].
  • The image must be image/jpeg or image/png, sent as base64 bytes or a gcsUri [2], at most 20 MB [1].
  • Google recommends an input of 720p or more at 16:9 or 9:16. Other shapes are resized or center-cropped [6].

  • resizeMode (pad or crop, default pad) is not exposed [3][6].

Reference

  • Up to 3 asset images, or 1 style image [2]. The two kinds do not share a request.

Legacy ASTRA self-hosted LTX server

The engine is legacy. Its successor for LTX is astra-genai. It is still registered and selectable, and planning does not refuse it the way it refuses retired engines (video-routing.ts). The credential is ASTRA_VIDEO, and ASTRA_VIDEO_URL overrides the host (config.ts).

Calling it

  • Upload: POST /v1/uploads. The body is the raw file bytes, and Content-Type picks the kind. It returns upload_id and expires_at, plus duration for audio or width/height/frames/fps for video.
  • Submit: POST /v1/jobs with a JSON body. It returns 202 {job_id, status, queue_position, status_url, result_url}.
  • Poll: GET /v1/jobs/{job_id}. status moves queued → running → succeeded | failed, and the response echoes the request the server recorded.
  • Result: GET /v1/jobs/{job_id}/result returns the mp4, or 409 while the file is not ready.
  • Plugin polling: every 5 s, giving up at 1,800 s. That equals the server's generation_timeout_seconds [1].
  • Receipt: the plugin writes <video>.astra-job.json so a timed-out call resumes without resubmitting (astra-video-client.ts).
  • Uploads expire after 24 h, with at most 200 files per key [1]. The server also has POST /v1/jobs/{id}/cancel, which the plugin does not use.

Rules shared by every operation:

  • Frames are 8k+1 from 25 and default to 121. The plugin caps all modes at 361. The server allows 721 on generate and 481 on every other mode [1].
  • duration in seconds becomes the nearest 8k+1 frame count, the shorter on a tie. The plugin converts it client-side.
  • fps runs 1–60, default 24.
  • Width and height sit on a 64 grid from 64 to 1920 (a 32 grid on guided_fast), with an area of at most 2,064,384 px. Defaults are 1536×1024 (768×512 on fast) [1]. For 9:16, use 1024×1920.
  • Prompts take up to 2,000 characters and have no label syntax. Seeds run 0–2,147,483,647 [1].
  • Every mode generates sound. generate_audio:false strips it after rendering, so GPU time is the same [1].

Motion design system

The theme definitions specify the typography, spacing and motion for each context.

Intent

A theme coordinates the presentation of an argument. A semantic motion type chooses the representation; a theme controls typography, spacing, surface geometry, color and temporal character. Never select a theme by shot number or rotate themes for variety. Channel identity wins; otherwise choose the communication context.

Composition plan

  • Report: left-aligned claim, common plot region, aligned data and units. Use scale and exact labels to explain evidence. Keep color count low.
  • Product: a task and its result share generous working space. Distinguish an actionable surface from an output. A mock must remain labelled as a mock.
  • Learning: connected stages or relationships, deliberate reading order, time to follow each handoff. Sequence numbers are appropriate only for sequences.
  • Campaign: display type carries a short statement; keep supporting material quiet. This is not the default for long paragraphs or dense charts.

Landscape: [claim / context] above [representation and change] above [source]. Portrait: preserve reading order and stack paired states; do not shrink a landscape composition. Theme dimensions use the 1600×900 or 900×1600 design coordinate system.

Type and timing

Bundled Paperlogy, Black Han Sans, Gowun Batang and Jua supply thematic titles. Space Grotesk and Roboto Flex supply Latin and numeric roles; Pretendard supplies body text and a verified whole-text fallback. See bundled fonts for sources and roles. Variable weights and tracking differentiate theme roles without relying on a system font. Numbers retain tabular alignment. Titles are balanced by available width; source text stays subordinate. Font-family variety alone does not establish good design.

The theme's end fraction maps the complete deterministic animation to a bounded interval; the remaining time holds the complete result. Every animation branch, including cursors and model counters, uses the same remapped clock. Easing changes acceleration, never the numerical meaning of data or simulation rates.

Critique before expansion

Six theme palettes alone cannot fix a weak illustration or generic composition. The current system provides a reproducible contract and tokens; it does not yet provide bespoke art direction for all 21 semantic families. Physical subjects still require authored assets and articulated meshes. Themes must not replace those with rectangles. Realistic UI proof still requires a recording.

Inspect horizontal and vertical renders, the beginning, transformation and hold, plus arbitrary seeks. Check overlapping text, numerical geometry, subject fit and visual hierarchy independently of input validation.

Episode consistency

THEME.motionGraphicTheme is the storyboard-level default. Shots with no theme or an automatic choice without context inherit it. Explicit shot ids/contexts are exceptions. storyboard_apply recomputes inherited resolutions; preparation and browser rendering resolve against the same board default. The header exposes the common theme and each shot exposes its resolved theme and reason.

Expressive themes use different compositions: campaign uses a saturated poster and an emphasized closing phrase, story centers a quiet serif passage, playful uses rounded type with author-selected word emphasis or alternating entrances. Phrase reveals never cut across a Hangul syllable. Quantitative labels count against the same progress as their bars; comparison deltas connect the endpoints. Input/output keeps its source visible as individual fields are copied and reordered when the author supplies shared field substrings; queue saturation changes state color and exposes overflow.

Part/whole labels connect directly to segments. Semantic emphasis and field reorder metadata are optional: the storyboard author selects the meaningful word or shared fields, while the runtime preserves complete phrases, whitespace and deterministic seeks.
