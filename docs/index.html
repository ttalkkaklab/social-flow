API 키 — 어디까지 넣고 멈출지

키는 서로 독립인 두 묶음이다. 어느 한쪽에서 멈춰도 파이프라인은 돈다.

제작 키. OPENAI_API_KEY 는 커버와 글자가 들어가는 프레임을 그리고 GEMINI_API_KEY 는 생성 영상 클립·연기 나레이션·BGM 을 맡는다. 엄밀히는 둘 다 선택이다 — 씬 배경은 온디바이스 image_local_generate(Z-Image Turbo, 애플 실리콘), 나레이션은 온디바이스 tts_local_generate(Supertonic 3)가 기본 경로라 키 없이도 영상 한 편이 나온다. 다만 OPENAI_API_KEY 가 없으면 글자가 들어간 프레임을 포기해야 한다(로컬 이미지 생성은 한글 자소를 깨뜨린다). GEMINI_API_KEY 가 없으면 움직이는 컷과 음악이 빠진다. 조사용 키(SERPAPI_API_KEY·네이버 한 쌍)도 선택이며, 없으면 스토리보드가 WebSearch 로 조사한다.

플랫폼 자격증명(스레드·인스타그램·유튜브·페이스북) — 선택. 넣어 두면 publish 가 내 계정에 바로 올린다. grow-threads·grow-youtube·grow-instagram 은 /loop 로 채널의 하루 운영을 넘겨받는다 — 댓글 응대, 지표 관찰, 키워드 대화 참여, 대기열 채우기, 게시를 init 때 한 번 승인한 상시 승인서 안에서 알아서 한다. 안 넣어도 제작까지는 그대로 쓴다. produce 가 완성 영상과 플랫폼별 텍스트를 data/<채널>/episodes/<주제>/output/ 에 써 주므로 그 파일을 손으로 올리면 된다. 이때는 게시·인사이트 툴 아홉이 목록에 뜨지 않아 tools/list 가 46종 대신 37종을 보여 준다. 플랫폼별로 따로 걸리는 문제라 전부 아니면 전무가 아니다. 나중에 토큰을 추가해도 서버를 다시 띄울 필요가 없다.

변수 이름·기본값·자격증명 파일 규약의 정본은 README.md 다. 실제로 넣는 순서는 시작하기 — 설치부터 첫 영상까지가 안내한다.

스킬 18종 — 무엇을 언제 부르나

채널 하나를 열어 콘텐츠를 올리기까지의 순서다. 각 단계는 앞 단계의 산출물을 검사해서, 스토리보드가 미승인이면 produce 가, 제작이 안 끝났으면 publish 가 멈추고 이전 단계를 안내한다. 인자 형태와 전체 계약의 정본은 README.md 다.

API 레퍼런스

내부 MCP 서버(server/src)가 실제로 호출하는 모든 외부 API의 공식 계약을 정리하고, 이 저장소의 구현이 그 계약을 어떻게 지키는지(또는 의도적으로 좁히는지) 함께 적었다.
