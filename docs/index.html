social-flow user manual

social-flow helps you run a video channel from a local folder. You work with a coding assistant to plan episodes, review shots, assemble videos and publish to the accounts you choose. A channel keeps its cast, voice choices and visual style across episodes.

Start with Getting started. The first exercise sets up a channel and gives you a synopsis to review before you spend money on episode media.

Other ways to work

  • Use your own footage. Start with a recorded walkthrough. The ingest skill builds a timestamped timeline from the recording and transcript for the storyboard. Screen recording workflow
  • Make a targeted change. Ask for a particular line to be re-recorded or a single cut to be inspected. Include the channel, episode and shot so the assistant can find the existing material. Speech editing · Content inspection
  • Review published episodes. Compare recent YouTube and Instagram results. If you want the assistant to act on a channel, its growth skill has a separate plan and authorization. Recent performance · YouTube · Instagram · Threads
  • Prepare a character broadcast. Use a channel character and its voice to prepare an opening, welcomes and moving standby clips. You can request a local preview and decide when to go live. Character livestreams

Getting started

This walkthrough uses Claude Code and a new channel called field-notes. You will finish with a local channel profile and a short synopsis. You can leave publishing accounts disconnected.

Install and check the connection

Install Claude Code and Node.js 20 or later. From a terminal, add the marketplace and install the plugin. The plugin ships with its MCP server already built.

node --version
claude plugin marketplace add ttalkkaklab/social-flow
claude plugin install social-flow@social-flow

Create a workspace for your content. You can also use an existing project folder.

mkdir -p ~/Videos/field-notes
cd ~/Videos/field-notes
claude

In the new Claude Code session, enter /mcp and look for the connected social-flow server. Ask “Show the available project setup options using project_manage.” This reads the bundled options without creating project files. If skills appear but the tool is unavailable, check the connection before starting setup. Troubleshooting

Set up the channel

In the same session, run the following skill. Give it your chosen workspace path when prompted.

/social-flow:project-init init ~/Videos/field-notes

Use field-notes as the channel slug. For this example, choose an English-language explainer in portrait format (shorts-9x16). The assistant asks which models you can use, how the channel should look and how many shots should use generated video. You can choose existing music or no new music, and skip separate text-to-speech when the project does not need it. Choose connect later for publishing accounts you want to add later. Configuration and costs

When setup finishes, look for .social-flow/models.json and data/field-notes/profile.md. The former holds workspace choices. The profile describes the channel's audience, tone and recurring cast. To see which choices still need an answer, run:

/social-flow:project-init status ~/Videos/field-notes

Request a first synopsis

Tell the assistant what the audience should learn and which artifact you want.

For field-notes, draft a synopsis for a short called “Window Light.” Show a potter moving a cup from direct sunlight into diffuse window light so the viewer can see the glaze. Write in English and stop at the synopsis.

Read the proposed opening, what changes on screen and the final shot that proves the point. The synopsis can be revised before you request a storyboard. To continue with the same episode, follow Making an episode.

Supply credentials to the server

A local server can inherit variables from its host. It also reads ~/.config/social-flow/.env, or .env inside the directory named by SNS_TOKEN_DIR. A nonempty environment value takes precedence. Use a private editor to enter only the variables your selected providers require.

mkdir -p ~/.config/social-flow
chmod 700 ~/.config/social-flow
touch ~/.config/social-flow/.env
chmod 600 ~/.config/social-flow/.env

Keep keys out of the project settings, storyboard, prompts and issue reports. After changing variables, reconnect the MCP server or start a fresh host session. Check the configuration from that session. For ASTRA, inspect the catalog for the media type you selected. A key in a terminal alone does not establish which endpoint a running host uses.

Budget an episode

The generated-video share counts shots. For example, video_50 targets 50% to under 80% generated shots and no_video targets zero. Still images, speech and music can each have their own provider costs. An episode with no generated video can still include these assets.

Set an optional episodeBudgetUsd at project setup. Review the estimate for the episode, including possible retries, before authorizing generation. A configured cap limits spend. After a run, inspect output/video/cost-report.txt and the saved generation receipts. The provider's billing record gives the final charge.

For assembly, install FFmpeg (including FFprobe), Python 3 and Google Chrome for headless capture. Blender supports 3D location and composition work. Local transcription and local image or video models have their own runtime requirements. Requirements · Local LTX runbook

Making an episode

An episode belongs to one channel. In this walkthrough, field-notes is the channel and window-light is the episode slug. Use the same two names to resume a session. Workspace setup

Build the storyboard

After reviewing the synopsis, tell the assistant to use it for window-light. In Claude Code, the storyboard skill also takes the channel and topic directly:

/social-flow:storyboard field-notes window-light
  1. Prepare the cast. Reuse a channel character or describe a new one. Each visible cast member needs an identity and face, front and back images. A voice-only narrator needs an identity. If a panel is missing, the assistant identifies it and asks for any spending authorization needed to make it.
  2. Read the scene before reviewing its shots. For “Window Light,” the scene should establish where the cup starts, what the potter does and when the glaze becomes visible. Check who speaks and what the viewer can see during each line.
  3. Open the review page. Open data/field-notes/episodes/window-light/storyboard/storyboard.html in a browser. Keep its sibling files with it. Check the cast, shot order, framing, dialogue and planned sound. To request a correction, cite a shot or scene and the change you want.
  4. Approve the plan you want to produce. A text-only board can stop at the shot plan. You can request shot images or a camera review separately. The assistant keeps the episode's saved model choices on resume.

Produce and review the video

When the board is approved, run:

/social-flow:produce field-notes window-light

Review the cost estimate and the proposed generated shots before authorizing paid work. The production sequence prepares the props and locations, then the shot images. For generated scenes, the assistant plans a request with the ordered shots and their sound direction. Approve the shots you want to render. The assistant can then assemble the selected footage, sound and platform copy.

Play the delivered output/video/video.mp4 with sound. Check that the opening frame matches the promise, speech finishes before a cut, and the last shot shows the result. The master has no burned-in subtitles. Request a separate subtitle track if you need one. Read the caption or post for each target platform. For a dedicated thumbnail or platform crop, request the cover workflow.

Publishing an episode

Start with a finished episode. Play its master video, inspect the cover at the target crop, and read the caption, title and any first comment. Keep the channel and episode slugs handy so you can find the same files and receipts if a session is interrupted.

Connect the intended account

For a channel named field-notes, run the setup skill for the platform you intend to use. For example:

/social-flow:setup-youtube field-notes

Follow the account selection and consent prompts. Ask the assistant to run sns_account_check for field-notes and show the account attached to that channel. Check the handle or channel ID. Setting up an account and uploading an episode are separate requests.

Platform Setup What to check at delivery

Instagram Instagram setup The platform fetches the media over HTTPS. Open the published Reel and inspect its profile crop.

TikTok TikTok setup Start with Only you, edit and reopen the cover in ego lite, then make that same post public and verify it. An inbox delivery is a draft.

The channel's credential directory defaults to ~/.config/social-flow/field-notes/. Tools called with a channel use that channel's files. A new credential file can make a platform tool available. Check the account again if authorization, scopes or identity change.

Publish to a specific platform

In Claude Code, the following command selects YouTube for this episode:

/social-flow:publish field-notes window-light youtube

Review the target account, final copy, media and visibility before authorizing publication. For platforms that fetch media, provide the hosting method for this channel. The platform needs to be able to fetch the approved file from a public HTTPS URL. YouTube accepts the local video file.

After publishing, open the returned permalink and check the actual visibility and cover. The episode records platform IDs and permalinks in output/publish-log.md and first-comment receipts in output/first-comments.json when applicable. After a timeout, use the recorded ID to check what the platform already received before retrying. Publishing procedure · TikTok cover and visibility

Troubleshooting

Start in the workspace that owns the episode. Keep the channel slug, episode slug and any request ID from the original operation. Those identify the existing work when you reconnect.

Symptom What to check
The skill appears, but its tools are missing In Claude Code, open /mcp and inspect the social-flow connection. The marketplace install needs Node on the host's executable path. For a clone, point --plugin-dir at the repository root.
project_setup_required Run /social-flow:project-init status with the selected workspace. Complete the listed choices with project-init. After moving a workspace, select the new directory.
A provider looks configured but the request fails capability_status reports locally visible configuration. Check the selected operation, endpoint and model catalog in the same MCP session. Restart the server after changing its environment.
A publishing tool is missing or shows the wrong account Check the credential directory and run sns_account_check with the same channel slug you passed to publish. Verify the live account and scopes before uploading.
cast_required, cast_source_missing or character_panel_missing Inspect the episode's storyboard/cast.json. Restore the referenced identity and the visible character's face, front and back panels. Authorize any needed generation before resuming the board.
The render needs more images or voice inputs than the model accepts Inspect the named shot and its role-labelled references in the plan. Revise the inputs or explicitly change the model, then plan the scene again.
A video request timed out Ask for video_status with the episode and original request ID. Keep the receipt, provider job ID and output. If submission is uncertain, check the same job before starting another paid request.
A posted video still looks private Inspect the existing platform ID and publish log. For YouTube, check the private upload and requested visibility. For TikTok, verify the private cover and change visibility on the same post.

Did the image provider get the request?

A timeout leaves a video producer with an awkward choice. Submitting the same shot again might buy a second image. Waiting might mean waiting for a job that never started.

From the social-flow project · Maintained by Zeans at Ttalkkak Lab

One missing frame, two possible bills

Imagine a storyboard with one image left to generate. The provider accepts the request, but the connection closes before the response reaches the editor. From the editor's side this looks much like a request that never reached the provider. An empty output directory fits both stories.

In social-flow's managed image path, the editor saves a plan and a request ID. Before calling the adapter, the server writes a receipt and reserves capacity. If the adapter loses the response, the server can still say which request it tried. An ambiguous error leaves that request in submission_unknown.

Count the calls yourself

With Git and Node.js 20 or newer, run the two regression cases below. The fake adapter either writes a one-pixel PNG or throws a timeout. The tests use a temporary episode directory and require no provider credentials.

git clone https://github.com/ttalkkaklab/social-flow.git
cd social-flow/server && npm ci
node --import ./test/isolate.mjs --test --test-name-pattern='managed success|ambiguous failure' test/image-routing.test.mjs

In the success case, calling the same plan twice returns the saved result. The dispatch counter stays at one. If the saved file changes, the hash check catches it. In the timeout case, a second call with the same request ID stops before dispatch. With the fixture's single slot occupied, giving the request a new name also stops before dispatch.

What it costs to wait

An unresolved request can hold up another shot. Reading image_status returns the recorded state. A supported adapter can refresh provider status. To close out an uncertain request manually, the operator records evidence and the amount spent. In the test, the local child exited without output and the spend is zero. A real provider needs its own evidence.

The same distinction matters when a job succeeds. A decoded image with the expected hash can still show the wrong character. The generation receipt marks it not_reviewed. Someone still has to inspect the picture.

Read the routing code · Read the assertions

Work on this with us

If you've integrated an image provider, what evidence does its API give you after a lost response? A link to the provider's status endpoint and a redacted example response would help us evaluate another recovery path. You can also pick a small change with a local check already described.

Stock media and attribution

Use stock_search to find images or clips for a shot. Start with a literal description of the subject and its setting. If the search returns no usable match, try an English query, a wider orientation or another media type. Pexels and Pixabay require their own keys. The NASA and Wikimedia Commons searches work without a provider key.

Before using a result, open its item page and inspect the actual media. Keep the returned visual.license record with the shot, including the author, source URL, license and attribution. Check the item terms for the intended edit and distribution. An archive can hold works under several different terms.

For Korean historical material, browse the National Museum of Korea's eMuseum, the Korea Copyright Commission collection and the KTV film archive. Record the item-specific rights statement when importing media from these collections.

See the shot schema for the fields to preserve with a stock shot.

Local LTX video on Apple silicon

Use ltx_video_generate with an LTX pack served by MLX-Serve on your Mac. FFmpeg writes the returned picture and audio to an MP4. This is the on-device video adapter. The hosted LTX API and an ASTRA gateway have separate setup instructions. Video routing

Install and start the model

The project's September 2026 test used the 4-bit distilled pack on an M4 Max with 128 GB of unified memory. The pack occupied about 36 GB on disk. Download the full repository, including the text encoder. With the Hugging Face CLI installed, run:

hf download ddalcu/LTX-2.5-MLX-Serve-4bit --local-dir "$HOME/models/LTX-2.5-MLX-Serve-4bit"

Start MLX-Serve from a terminal or a service that will stay running for the full render:

mlx-serve --model "$HOME/models/LTX-2.5-MLX-Serve-4bit" --serve

From another terminal, inspect the default local endpoint:

curl -fsS http://127.0.0.1:11234/v1/models

Look for the LTX model ID, its ready state and the video capability. The plugin uses MLX_SERVE_URL if your service runs at a different address. Supply MLX_SERVE_API_KEY to the MCP process if the service requires it. Choose the local MLX video adapter and the installed LTX model during project setup. See the model card for the pack and its license.

Plan the render

Parameter Local adapter contract
Width and height 256–1920 pixels per side. Use multiples of 64 for the default two-stage pipeline, or multiples of 32 with one_stage.
Frame count 9 through 241 in steps of 8. The default is 49 frames at 24 fps.
Decoded RGB At most 800 MiB for width × height × frames × 3 bytes. Reduce the canvas or the number of frames if the plan exceeds it.
Conditioning Supply a local first-frame image, and a last-frame image when the plan calls for one.

In the September test, a 49-frame clip took about 13 minutes at 768×1280. Treat that as one machine's measurement. RAM pressure, model loading, canvas size and other GPU work change the time. For a managed episode, keep the request ID and inspect video_status if the connection closes. Adapter implementation

FastH3 Omni local adapter

Use fasth3_omni_reference for FastH3 Omni and ltx_video_generate for LTX. mlx_video_generate remains a deprecated LTX alias so saved calls and receipts continue to resolve. New catalog-based LTX planning selects the canonical name. MLX-Serve is the internal backend; engine:"mlx" in saved settings is unchanged. No existing settings or episode snapshots are migrated implicitly.

Architecture

local-video-models.ts is a small Strategy registry. Each entry owns its schema, frame grid, model match and request serializer. fasth3-omni.ts validates and converts reference media. mlx-serve-client.ts is the common HTTP Adapter and RGB/PCM-to-MP4 writer. No inheritance, dependency injection framework or second routing system is needed. video_plan keeps input hashes, saved selection, spending reservations and duplicate protection for both models.

Setup

Run MLX-Serve with ddalcu/FastH3-Omni-MLX-Serve-8bit installed. Configure MLX_SERVE_URL if the service is not at http://127.0.0.1:11234. The adapter does not download models or start the application. The transformer is ~37.3 GB; the full pack is ~71.4 GB. Identical encoder/VAE files may be shared with the MiniMax H3 FL2VA pack after verifying their hashes. Model weights use the MiniMax H3 Community License; the MLX-Serve conversion is a separate runtime from FastVideo's Python MLX implementation.

Example saved video selection (explicitly select it; do not overwrite unrelated settings):

{"engine":"mlx","model":"ddalcu/FastH3-Omni-MLX-Serve-8bit","resolution":"768x448"}

For a configured episode, use video_plan with operation:"reference", record the approved plan with video_approve and submit it with video_execute. A standalone adapter accepts the following inputs.

{
  "prompt":"The person in <Picture 1> waves. Birds chirp.",
  "referenceImagePaths":["/absolute/character.png"],
  "width":768,"height":448,"numFrames":124,"seed":2026,
  "outputPath":"/absolute/output","filename":"fasth3.mp4"
}

Verified upstream call surfaces

Checked on 2026-10-29 against the following primary sources:

  • FastVideo release and examples.
  • FastVideo MLX reference types and validation.
  • FastVideo MLX generate signature.
  • MLX-Serve HTTP parser and reference ordering.
  • Installed conversion model card.

These are different APIs. FastVideo Python accepts generate(prompt, output_path=..., references=[MiniMaxH3Reference(source=..., media_type="image" | "video" | "audio")], num_steps=8, ...). References may also specify soundtrack, fps and sample_rate where applicable. The social-flow adapter uses the separately maintained MLX-Serve HTTP API, not this Python signature.

social-flow input MLX-Serve JSON field Wire value
referenceImagePaths ref_images Ordered base64 PNG/JPEG strings
referenceVideoPaths ref_videos Objects with base64 frames and optional WAV audio
referenceAudioPaths ref_audios Ordered base64 WAV strings
referenceSize ref_image_size match or max
numFrames num_frames Exact frame count
steps steps 8

The adapter POSTs to /v1/video/generations with model, prompt, width, height, optional seed and stream:true. It consumes SSE progress and the final RGB/PCM payload, then writes the MP4 locally. File paths are adapter inputs; they are not passed directly to the HTTP server.

Both the official Ref2VA validator and this conversion require a visual reference: audio-only and text-only requests are rejected. An image reference guides identity/composition; it does not pin the exact first frame. MLX-Serve also parses first_frame_image and last_frame_image in its shared H3 implementation, but this adapter does not expose those fields: their quality and semantics with this Omni pack have not been verified. chain_windows > 1 explicitly rejects REF2VA packs. Do not infer these capabilities from FL2VA or hosted services.

The 256 MiB RGB ceiling, 60 MiB encoded upload limit, dimension range and explicit trim opt-in below are adapter policies. They are not universal FastH3 model limits.

Contract

  • Exactly 8 steps. 24 fps, frames on the 17k+5 ladder from 124 through 362. requiredSeconds rounds UP on this ladder; LTX still uses 8k+1.
  • Width/height: multiples of 32, 256–1536. Decoded RGB must fit this adapter's 256 MiB compatibility limit (the installed MLX-Serve 26.10.3 UI limit). A 15-second request needs a smaller canvas than a 5-second one.
  • Up to 9 PNG/JPEG images, 3 videos and 3 audio files; at most 12 total and at least one image or video. Each clip is 2–15 seconds; video references total at most 15 seconds. The encoded request must fit 60 MiB.
  • Reference videos are decoded to JPEG frames at 24 fps with a maximum 768px side. Their soundtracks are converted to stereo 32kHz PCM WAV. By default, references that require tail trimming fail. trimReferenceVideos:true permits truncation to the output frame count and the 17k+5 ladder; paired audio is trimmed to that same duration. Standalone audio is also converted to stereo 32kHz PCM WAV.
  • referenceSize:"match" is the default; max costs more time and memory.
  • Prompt image labels are <Picture N>. Video soundtrack audio labels precede standalone <Audio N> labels. Automatic pinned-character voice mapping probes video soundtracks and offsets standalone audio labels accordingly.
  • This adapter supports reference generation, not first/last keyframes or clip continuation. Reactor's API capabilities must not be assumed for this pack.
  • Voice reference means timbre guidance. Exact supplied speech, original WAV preservation and validated lip-sync remain unsupported. Output quality is not_reviewed until actual playback has been inspected.

Verification

npm --prefix server run check builds shipped artifacts and runs contract tests. The FastH3 tests cover the frame-grid mismatch, reference limits, image/video/audio serialization and explicit trimming. Routing tests verify saved selection and input hashes. A real generation is still required to measure speed and inspect picture/sound on a particular Mac.

Local smoke test on 2026-10-29: M4 Max, 128 GB, MLX-Serve 26.10.3, the 8-bit pack above, one image, seed 2026, 384x256, 124 frames, 8 steps. The streaming adapter wrote an MP4 in 244 seconds. ffprobe confirmed H.264, 24 fps, 124 frames (5.166667 seconds), AAC stereo at 32 kHz. Five sampled frames were inspected; audio presence was measured, not listened to for quality. This is an integration smoke test, not a quality or speed benchmark. The earlier 768x448 non-streaming request disconnected before completion; SSE progress handling fixes that client timeout. Audio/video reference inputs have serialization tests but have not had separate real-model generation tests.

MCP tool contracts

Skills describe the workflow. The bundled Model Context Protocol (MCP) server exposes the tools that perform individual operations. To discover the schemas available in a session, use the host's tool list. Credential files and tool flags can change which tools it returns. The repository README groups the tools by task. Tool inventory

Behavior annotations

The shared presets in server/src/tools.ts describe what a call can change. Set the fields for the actual operation. A tool that combines several actions may describe its behavior separately.

Preset Use Read only Destructive Idempotent Open world
read Look up external data true omitted omitted true
local Read bundled choices or local state true omitted omitted false
generate Generate or download an artifact through a provider false false false true
generateLocal Generate a local artifact on device false false false false
publish Create an external post or reply false true false true
moderate Set external state, such as a moderation flag false true true true

A repeated publishing call can create a second post. A metadata update sets a particular value on an existing post. Both affect an external account. The workflow obtains the user's authorization before calling the corresponding tool. Definitions and presets

Adding or changing a tool

Describe the inputs and output, the point in the workflow where the skill calls it, and any provider costs or external effects. Use the adapter's constants when defining model and operation choices. On success, return the structured fields declared by the output schema. Report a failed operation as an error and preserve its request ID or receipt where available.

Episode pipeline manifest

The plugin derives an episode's stage from its local files. For example, a saved scenes.js marks a draft. The storyboard's approval record marks an approved plan. The manifest defines the stage order and the next command to show for each one. Pipeline definitions

Export What it describes
STAGES The ladder from empty to drafted, approved, produced and published, and the file or status evidence for each step
GATES Where workflows check operational requirements or record review findings
REVIEWERS The reviewer roles and their result formats
LANES Build paths for generated material, screen recordings and mixed episodes

The episode-state helper reads the artifacts when reporting status. For an interrupted render or upload, use the job receipt or platform record to find the state of that individual operation. A stage label alone cannot verify provider completion or public visibility.

Motion design system

The theme definitions specify the typography, spacing and motion for each context.

Intent

A theme coordinates the presentation of an argument. A semantic motion type chooses the representation; a theme controls typography, spacing, surface geometry, color and temporal character. Never select a theme by shot number or rotate themes for variety. Channel identity wins; otherwise choose the communication context.

Composition plan

  • Report: left-aligned claim, common plot region, aligned data and units. Use scale and exact labels to explain evidence. Keep color count low.
  • Product: a task and its result share generous working space. Distinguish an actionable surface from an output. A mock must remain labelled as a mock.
  • Learning: connected stages or relationships, deliberate reading order, time to follow each handoff. Sequence numbers are appropriate only for sequences.
  • Campaign: display type carries a short statement; keep supporting material quiet. This is not the default for long paragraphs or dense charts.

Landscape: [claim / context] above [representation and change] above [source]. Portrait: preserve reading order and stack paired states; do not shrink a landscape composition. Theme dimensions use the 1600×900 or 900×1600 design coordinate system.

Type and timing

Bundled Paperlogy, Black Han Sans, Gowun Batang and Jua supply thematic titles. Space Grotesk and Roboto Flex supply Latin and numeric roles; Pretendard supplies body text and a verified whole-text fallback. See bundled fonts for sources and roles. Variable weights and tracking differentiate theme roles without relying on a system font. Numbers retain tabular alignment. Titles are balanced by available width; source text stays subordinate. Font-family variety alone does not establish good design.

The theme's end fraction maps the complete deterministic animation to a bounded interval; the remaining time holds the complete result. Every animation branch, including cursors and model counters, uses the same remapped clock. Easing changes acceleration, never the numerical meaning of data or simulation rates.

Critique before expansion

Six theme palettes alone cannot fix a weak illustration or generic composition. The current system provides a reproducible contract and tokens; it does not yet provide bespoke art direction for all 21 semantic families. Physical subjects still require authored assets and articulated meshes. Themes must not replace those with rectangles. Realistic UI proof still requires a recording.

Inspect horizontal and vertical renders, the beginning, transformation and hold, plus arbitrary seeks. Check overlapping text, numerical geometry, subject fit and visual hierarchy independently of input validation.

Episode consistency

THEME.motionGraphicTheme is the storyboard-level default. Shots with no theme or an automatic choice without context inherit it. Explicit shot ids/contexts are exceptions. storyboard_apply recomputes inherited resolutions; preparation and browser rendering resolve against the same board default. The header exposes the common theme and each shot exposes its resolved theme and reason.

Expressive themes use different compositions: campaign uses a saturated poster and an emphasized closing phrase, story centers a quiet serif passage, playful uses rounded type with author-selected word emphasis or alternating entrances. Phrase reveals never cut across a Hangul syllable. Quantitative labels count against the same progress as their bars; comparison deltas connect the endpoints. Input/output keeps its source visible as individual fields are copied and reordered when the author supplies shared field substrings; queue saturation changes state color and exposes overflow.

Part/whole labels connect directly to segments. Semantic emphasis and field reorder metadata are optional: the storyboard author selects the meaningful word or shared fields, while the runtime preserves complete phrases, whitespace and deterministic seeks.

Fonts for motion graphics

The motion font resolver checks the actual text against bundled glyph coverage. It records a whole-text fallback and reports characters the fallback cannot draw.
