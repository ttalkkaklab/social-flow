## 발견 사항

### 수정 완료 — P2: 모순된 시점 선택을 알리지 않는다

`camera.rear`와 `camera.pov`를 같은 샷에 넣으면 `findings()`는 빈 배열을 반환한다. `instructions()`는 인물을 뒤에서 보라는 지시와 인물의 눈으로 보라는 지시를 함께 내보낸다. 이동과 정지의 충돌은 이미 경고하므로 시점에도 같은 수준의 안내를 추가하면 된다. 실행 차단 규칙을 새로 만들 필요는 없다.

재현 입력:

```js
const scene = {
  shot: {techniques: [
    {id: 'camera.rear', reason: 'Hide the face'},
    {id: 'camera.pov', reason: 'See through the actor eyes'}
  ]},
  visual: {camera: {movement: 'static'}}
};
```

결과: 경고 `[]`; 출력에 `View the subject from behind`와 `View from the character eyes`가 함께 들어간다. 정상적인 단일 시점 선택이나 현재 meleon 보드의 생성은 막지 않는 결함이었다.

수정 후 서로 다른 viewpoint가 둘 이상이면 `Conflicting viewpoints`를 안내한다. 스키마는 계속 입력을 허용한다. 새 회귀 검사는 충돌 안내, 비차단 동작, 단일 시점과 정지·눈높이 조합의 무경고 동작을 확인한다. 전체 2,244개 검사는 이 수정 전 결과이며 부모 에이전트가 최종 빌드·설치 검사를 다시 실행해야 한다.

### 수정 완료 — P3: generic 영상 프롬프트에서 일부 지시를 반복한다

`assemble-bg-prompt.js`의 `clipAssemble()`은 `instructions()` 다음에 `sourceInstructions()`를 넣는다. 후자는 정지 이미지용이므로 프레이밍·시점 지시가 두 번 들어간다. 뜻을 바꾸지는 않지만 모델의 프롬프트 길이를 불필요하게 쓴다. 후속 수정에서 부모 에이전트가 영상 조립기의 sourceInstructions 호출을 제거했다. 독립 검토자가 실제 코드를 다시 읽고 검사 10개를 다시 실행해 통과를 확인했다. 정지 이미지 조립기의 sourceInstructions 호출은 유지했다. 새 단언은 영상의 Opening frame과 rear-view 지시가 각각 한 번만 등장하는지 확인한다.

## 검토 범위와 한계

- `/tmp/film-technique-gallery2.png`를 직접 열어 45개 카드의 아이콘·이름·선택 용도·영문 지시를 확인했다. 현재 코드와 같은 항목 구성이다. 이 캡처는 레이아웃 근거이며 새 브라우저 실행이나 키보드 상호작용 검사를 대신하지 않는다.
- `<details><summary>`와 라벨·이스케이프 처리를 코드로 확인했다. 임의 HTML을 기법 이유에 넣어도 텍스트로 표시하는 구조다.
- 캐릭터 4개와 시간 5개는 선택 기준이다. 이 ID만으로 참조 파일을 자동 선택하거나 시간을 고정하지 않는 점은 문서와 일치한다. 실제 파일·측정 음성·성능 타임라인을 계속 사용해야 한다.
- 위 점수는 플러그인 구현에만 적용한다. 생성한 모든 영상에서 45개 기법이 시각적으로 구현됐다는 뜻은 아니다. 실제 영상 95점 달성, 최종 병합, 워크트리 정리는 이 검토로 증명할 수 없다.


## 후속 확인

`/tmp/film-final-check.log`에서 2,245개 통과·실패 0건을 확인했다. 이 전체 실행은 P3 수정 전에 시작했으며 마지막 P3 변경은 독립 재실행한 기법 검사 10개가 검증한다. 설치 5의 결과는 이 검토에서 아직 확인하지 않았다. 점수는 98점을 유지한다.

검토자는 이 세션에서 이미지 파일을 직접 볼 수 있지만 전체 영상의 연속 재생과 오디오를 실제로 지각했다는 증거는 없다. 따라서 음질·발음·립싱크·연속 움직임에 점수를 부여할 수 없다. 프레임 추출이나 파형·파일 검사는 그 한계를 없애지 않는다. 외부 평가 모델로 대체하지 않았다.
