# Render-scoped speech

The revised specification counts pinned voices per native render. A single story scene can own multiple shot renders. The four functional branches and the agreed weights are in loop.md.

- The earlier implementation rejected EP13's one pinned voice without a finished A2V track. Replaying the original board now produces five distilled LTX children in order, with the same 267 frames, fourteen image bindings, ten distinct image files and one voice binding. After normalizing staged upload IDs, four silent-child descriptions gain a closed-mouth direction. All fifteen attachment roles, hashes, byte sizes and positions match the archived submission.
- The regression suite exercises the new decision across storyboard authoring, speech preparation, planning, approval, execution and direct adapter calls. It covers MSR voice slots on a single take and across shots, the four-subject image budget with a separate background and endpoints, silent identities, Seedance 2.0 three-voice requests, authorized generated speech and exact recorded tracks.
- Distinct characters must own distinct decoded voice samples. An audio container metadata change cannot create a second voice. The raw input hashes still bind approval to the original files.
- The owner subsequently prohibited post-render lip-sync. Reject executable post-sync capabilities, historical candidate attachments and on-screen TTS overlays at assembly. A silent A2V output requires its original unshifted driver WAV and a matching generation record. Live playback uses the native performance instead of animating prerecorded mouths from TTS.

The actual EP13 replay and the local gateway schema/guide checks used no paid provider submissions.
