동네 변화 레이더

주소를 저장하면 주변 건축·상가·공공공사의 공식 변화를 모아 알려주는 생활권 구독 서비스 기획안.

문서 상태 아이디어 검증 전 최종 갱신 2026-08-16 가칭 주소워치 · 반경 · 동네레이더 주요 사용자 주거 계약 예정자
한 문장 정의
이사하거나 계약할 주소를 저장하면, 반경 500m 안의 공식 변화가 생길 때 알려준다.

단순 조회 지도가 아니다. 여러 공공데이터에 흩어진 변화를 한 주소에 묶고, 이전 조회와 달라진 내용만 전달하는 감시 서비스다.

해결할 문제와 서비스 경계

주거 계약 예정자는 현재 모습만 보고 집을 결정한다. 계약 뒤 시작될 공사나 주변 업종 변화는 여러 행정 서비스에서 직접 찾아야 한다.

현재의 문제

건축허가, 착공, 영업 인허가, 공공공사가 서로 다른 서비스에 흩어져 있다.

제품의 해결 방식

주소와 반경을 기준으로 데이터를 묶고, 새로 생긴 변화만 타임라인과 알림으로 전달한다.

사용자가 얻는 결과

계약 전에는 생활권의 미래 변화를 확인하고, 계약 후에는 변동을 계속 추적한다.

제품 경계: 이 서비스는 미래를 예측하지 않는다. 행정기관이 공개한 허가·착공·영업 상태의 변경을 발견해 알려준다.

서비스 액터와 핵심 사용자

초기 제품은 주거 계약 예정자에게 집중한다. 다른 액터는 데이터 공급과 운영, 이후 시장 확장에 관여한다.

액터원하는 결과제품에서 하는 행동우선순위
전월세·매매 계약 예정자계약할 집 주변의 앞으로 생길 변화를 확인한다주소 저장, 변화 보고서 확인, 알림 구독핵심
상가 창업 예정자경쟁 매장과 생활권의 변화를 추적한다후보 상권 저장, 신규·폐업 알림 확인후속
현재 거주자집 주변의 공사와 신규 시설을 놓치지 않는다집 주소 저장, 주간 변화 요약 수신후속
공공데이터 제공기관공식 인허가·공사 데이터를 공개한다API 또는 파일 데이터 갱신필수
서비스 운영자중복·지연·오류를 줄이고 출처를 설명한다수집 상태 감시, 데이터 정규화, 문의 처리필수

핵심 페르소나

인터뷰 전 가설이므로 실제 사용자 조사에서 행동과 지불 의사를 검증해야 한다.

김서윤 · 31세 직장인

전세 계약을 앞두고 있다. 채광과 교통은 직접 확인했지만, 맞은편 빈 땅의 건축 계획까지 찾을 방법은 모른다.

박지훈 · 38세 자영업 준비자

카페 후보지를 비교한다. 주변 신규 매장과 폐업을 매번 지도와 행정 사이트에서 따로 확인한다.

이정민 · 45세 아파트 거주자

주변 공사가 시작된 뒤에야 내용을 알게 된다. 생활권 변화만 모은 짧은 주간 요약을 원한다.

주소 구독 사용자 흐름

사용자는 검색보다 구독을 먼저 경험한다. 서비스는 최초 상태를 저장한 뒤 새로 생긴 차이만 알린다.

  1. 주소 저장계약 후보지나 집 주소를 검색한다.
  2. 반경 설정초기 MVP에서는 500m로 고정한다.
  3. 현재 상태 생성건축·영업 인허가를 한 번에 불러온다.
  4. 변화 감지신규 기록과 상태 변경을 이전 결과와 비교한다.
  5. 알림 전달무엇이 언제 바뀌었는지 출처와 함께 보여준다.
핵심 경험: “무엇이 있나”보다 “지난번 이후 무엇이 바뀌었나”를 먼저 보여준다.

공공데이터와 알림 항목

초기 버전은 전국 단위로 확보 가능한 두 종류부터 묶는다. 지역별 공공공사와 철거 정보는 데이터 품질을 확인한 뒤 확장한다.

변화 영역사용자에게 보여줄 사건후보 데이터준비 상태
민간 건축건축허가, 착공 예정, 실제 착공, 사용승인국토교통부 건축HUB 건축인허가정보API 확인
상가·생활시설신규 인허가, 정상 영업, 휴업, 폐업행정안전부 지방행정 인허가 데이터API 확인
공공공사사업 시작, 공정 변경, 준공 예정서울시 건설알림이 등 지자체별 데이터지역 제한
철거·해체해체 허가·신고, 철거 예정건축물 해체 관련 공개 데이터 후보별도 검증

알림 한 건의 정보 구조

사용자가 행정 용어를 몰라도 사건의 의미와 한계를 바로 이해할 수 있어야 한다.

  • 무엇: “맞은편 필지에 공동주택 건축허가가 등록됐어요.”
  • 어디: 저장한 주소에서 직선거리 180m.
  • 언제: 허가일과 서비스가 변경을 감지한 날짜.
  • 현재 단계: 허가, 착공 예정, 실제 착공, 사용승인 중 하나.
  • 근거: 제공기관, 원본 데이터명, 최종 갱신 시각.
  • 주의: 허가가 실제 공사나 영업 시작을 보장하지 않는다는 설명.

유사 서비스와 차별점

조회 기능만으로는 차별화하기 어렵다. 신규 상가 지도와 건축허가 조회 앱이 이미 존재한다.

서비스겹치는 기능남아 있는 틈판단
뭐 생겨? 최근 신규 인허가와 영업 상태를 지도에 표시한다 건축 생애주기와 주소 반경 구독을 함께 제공하지 않는다 신규 상가 지도 단독으로 진입하지 않는다
부동산 건축인허가 주소별 허가·착공·사용승인 일정과 즐겨찾기를 제공한다 주변 반경의 변화 감지와 상가 변화를 결합하지 않는다 건축허가 조회 단독으로 진입하지 않는다
서울시 건설알림이 주변 공공공사와 진행 상황을 지도에서 확인한다 서울 공공공사 중심이며 민간 건축·상가 변화와 분리돼 있다 지역 확장 데이터로 활용한다
오픈업 신규 매장과 상권 변화를 분석한다 상권 분석 중심이며 주거 주소의 건축 변화 감시는 아니다 상가 창업자 확장 시 비교한다
차별화 기준: 지도에 정보를 더 많이 찍는 것이 아니다. 저장한 주소에서 발생한 여러 종류의 변경을 한 타임라인으로 묶고 먼저 알려줘야 한다.

MVP 기능과 제외 범위

최소 기능 제품(MVP)은 “한 주소를 저장하고 유의미한 첫 알림을 받는 경험”을 검증한다.

첫 버전에 포함할 기능

다음 기능만으로 주소 구독의 효용과 데이터 품질을 확인한다.

  • 도로명·지번 주소를 검색하고 한 곳을 저장한다.
  • 저장 주소 반경 500m의 건축·영업 인허가 현황을 보여준다.
  • 신규 기록과 상태 변경을 날짜순 타임라인으로 보여준다.
  • 변경이 있을 때 푸시 또는 이메일 요약을 보낸다.
  • 모든 사건에 출처, 기준일, 행정 상태를 표시한다.
  • 계약 전 확인용 한 장 요약 보고서를 만든다.

첫 버전에서 제외할 기능

데이터 감지와 알림 품질을 검증하기 전에는 범위를 넓히지 않는다.

  • AI 기반 집값·상권·공사 완료 시점 예측.
  • 주민 커뮤니티, 리뷰, 제보 게시판.
  • 전국 모든 지자체의 공공공사 통합.
  • 부동산 매물 중개와 계약 기능.
  • 허가 상태를 실제 현장 상태로 단정하는 표현.

주요 화면 구성

화면은 정보량보다 변화의 의미를 빠르게 읽는 데 초점을 맞춘다.

1. 주소 등록

“계약할 집”, “우리 집”처럼 목적을 붙이고 주소를 저장한다.

2. 변화 홈

지난 확인 이후 생긴 사건 수와 가장 가까운 변화를 먼저 보여준다.

3. 반경 지도

건축, 신규 영업, 폐업, 공공공사를 색과 상태로 구분한다.

4. 사건 상세

행정 단계, 거리, 날짜, 출처, 주의사항을 한 화면에 표시한다.

5. 계약 전 보고서

최근 변화와 예정된 일정을 한 장으로 정리해 공유할 수 있게 한다.

6. 수신 관리

즉시 통지와 주간 요약 중 하나를 고르고 관심 사건을 선택한다.

수익화 가설과 성공 지표

수익화 항목은 모두 검증할 가설이다. 무료 구독으로 반복 사용을 먼저 확인한다.

가설무료 범위유료 후보검증 신호
개인 주소 구독주소 1개, 주간 요약여러 주소, 즉시 알림, 장기 이력주소 저장 후 4주 유지율
계약 전 보고서최근 핵심 변화 미리보기전체 사건·일정·출처가 담긴 보고서계약 예정자의 보고서 구매 의향
상가 후보지 비교후보지 1곳여러 상권 비교와 업종 변화 알림창업 준비자의 반복 조회율

제품 지표

초기에는 가입자 수보다 주소 저장과 알림 반응을 본다.

  • 활성화: 방문자가 주소를 저장하고 첫 현황을 확인한 비율.
  • 알림 가치: 발송한 변화 알림을 열어 상세 내용을 확인한 비율.
  • 지속 사용: 주소 구독을 4주 이상 유지한 비율.
  • 데이터 신뢰: 중복, 오분류, 위치 오류를 신고한 사건의 비율.
  • 지불 의사: 계약 전 보고서 또는 복수 주소 구독을 선택한 비율.

쇼츠·릴스 시나리오

첫 장면에서 계약 뒤 후회할 상황을 보여주고, 마지막에 주소 구독 서비스 아이디어를 꺼낸다. 전체 길이는 25~30초를 기준으로 한다.

“전망이 좋아서 계약했는데, 한 달 뒤 바로 앞에서 공사가 시작됐다.”

구간화면대사·자막제작 메모
0~5초새집 창가에서 계약서를 든 인물이 탁 트인 전망을 보고 웃는다“이 뷰 때문에 바로 계약했거든요.”Seedance 실사 생성. 인물·창문·맞은편 빈 땅을 한 프레임에 둔다.
5~9초같은 구도에서 굴착기와 가림막이 생기고 인물 표정이 굳는다“근데 한 달 뒤…”매치 컷으로 전후 차이를 즉시 이해시킨다.
9~15초휴대폰으로 여러 행정 사이트와 지도를 번갈아 찾는다“건축허가, 착공, 새로 생길 가게가 전부 따로 있네?”검색 화면은 실제 서비스 상표보다 일반화된 UI를 쓴다.
15~22초주소 하나를 저장하자 반경 지도와 변화 타임라인이 나타난다“주소만 저장하면 주변 변화를 먼저 알려주면 어떨까?”프로토타입 UI로 서비스 핵심을 보여준다.
22~28초건축허가·신규 매장·공공공사 알림 카드가 차례로 쌓인다“공공데이터로 동네의 다음 장면을 알려주는 서비스. 만들어볼까?”가칭 로고와 다음 편 예고로 끝낸다.

데이터 제약과 제품 원칙

공식 데이터도 실제 현장과 시차가 생긴다. 서비스는 이 한계를 숨기지 않고 화면과 알림 문구에 반영해야 한다.

위험사용자 오해제품 원칙
허가와 실행의 차이허가가 나면 곧 공사가 시작된다고 생각한다허가·예정·실제 착공을 다른 상태로 표시한다
갱신 지연알림을 실시간 현장 정보로 이해한다데이터 기준일과 서비스 감지 시각을 함께 표시한다
주소·좌표 오류반경 밖 사건이 포함되거나 가까운 사건이 빠진다도로명·지번·필지 좌표를 정규화하고 원본 주소를 공개한다
중복 기록같은 공사를 여러 사건으로 오해한다관리번호와 주소, 날짜를 이용해 중복 후보를 묶는다
지역별 정보 차이전국에서 같은 종류의 공사를 볼 수 있다고 생각한다지역별 제공 범위를 지도와 설정 화면에 명시한다

다음 검증 과제

개발 전에 데이터가 실제 사용자 질문에 답하는지 확인한다. 아래 순서가 끝나야 MVP 범위와 단가를 산정할 수 있다.

  1. 실데이터 표본을 만든다. 성격이 다른 지역 3곳을 골라 최근 12개월의 건축·영업 인허가를 주소 반경으로 묶는다.
  2. 알림 정확도를 점검한다. 중복, 좌표 누락, 상태 변경, 갱신 주기를 직접 측정한다.
  3. 핵심 사용자 5명을 인터뷰한다. 최근 계약 경험, 주변 변화 조사 방식, 놓쳐서 손해 본 사건, 알림 허용 범위, 지불 의사를 묻는다.
  4. 한 장 보고서를 테스트한다. 실제 후보 주소를 넣은 보고서가 계약 판단에 영향을 주는지 확인한다.
  5. 알림형 MVP를 만든다. 앱 전체보다 주소 등록과 주간 이메일 요약으로 반복 사용부터 검증한다.
가장 먼저 답할 질문: 사용자는 “우리 동네가 궁금해서” 돌아오는가, 아니면 “큰 계약을 앞둔 짧은 기간”에만 돈을 내는가?
