# 피드는 첫 프레임이, 목록은 커버가 고른다

이 플러그인이 다루는 일곱 표면 가운데 썸네일이 클릭을 직접 좌우하는 곳은 **YouTube 롱폼 하나뿐이다**. Shorts·TikTok·Instagram Reels·Facebook Reels·Threads 의 피드는 영상을 자동재생하므로 도달은 첫 1~3초 화면이 정하고, 커버는 프로필 그리드·검색·채널 페이지에서 이미 찾아온 사람이 무엇을 볼지 고르게 돕는다. 그래서 베스트 프랙티스는 에피소드마다 두 가지를 따로 설계하는 것이다. 하나는 피드에서 스와이프를 멈추는 첫 프레임 훅이고, 다른 하나는 코드로 쓴 짧은 한글 문구를 얹은 정지 커버 한 장이다. 세로 커버는 9:16(2160×3840, 최소 1080×1920) 한 장이 3:4 그리드, 1:1 피드 크롭, Shorts 가로 표면의 크롭을 모두 견뎌야 하므로 얼굴과 문구를 가운데 가로 띠(1080×1920 기준 y≈656–1264)에 모은다. 롱폼은 3840×2160 을 기본으로 하고 오른쪽 아래 재생시간 배지 자리를 비운다. 디자인 측정 근거는 흔히 듣는 조언보다 훨씬 약하다. Eden 이 50만 개 영상에서 뽑아 코딩한 썸네일 2,960개 비교에서 얼굴·색·대비는 잘된 영상과 부진한 영상 사이 차이가 잡음 수준이었고, 잡음 기준을 넘은 신호는 4~6단어의 짧은 글자, 무글자의 약한 불리, 카메라 응시와 차분한 표정 정도였다. 가장 단단한 규칙은 "썸네일이 약속한 장면을 본편이 실제로 보여 준다"이다. YouTube 정책, 시청 시간으로 승자를 고르는 Test & Compare, 이 저장소의 promise and proof 지침이 모두 이 방향을 가리킨다. 설정 경로는 2024–2026 사이 세 번 바뀌어(Shorts 앱 편집 2024-09, Studio 업로드 2026-07, Data API 2026-11-03) 2026-11 이전 블로그 상당수가 낡았다. TikTok·Threads 는 API 로 커버 이미지를 올릴 수 없고, Instagram 은 비공개 게시도 게시 후 API 수정도 없다. AI 생성 썸네일은 YouTube 에서 공개 대상이 아니라고 공식 문서가 적어 두었지만 TikTok·Meta 커버의 라벨 여부는 확인되지 않았다. 한글 글자는 이 저장소가 지정한 GPT Image 2 도 소규모 벤치마크(문구당 1장)에서 13개 중 1개를 틀렸으므로 코드 렌더링을 기본값으로 둔다.

**근거 등급 표기.** [공식] 플랫폼 공식 문서·API 레퍼런스 · [측정] 표본과 방법을 밝힌 연구(논문·업체 조사 포함, 대부분 상관관계) · [업체] 도구 업체·마케팅 블로그 · [실무] 크리에이터·실무자 의견과 일화 · [요약] 검색 결과 요약으로만 확인하고 원문을 열지 못함(다른 등급에 덧붙는다. 예: [측정·요약]) · [사내] 이 저장소의 이전 실측 · [추론] 이 보고서의 계산·해석. 등급은 올려 적지 않았다. 조사일은 2026-11-18 이다.

## 피드에서는 커버가 안 보인다: 플랫폼 책임자들이 직접 효과를 낮게 본다

세 플랫폼의 책임자와 공식 자료가 같은 이야기를 한다. YouTube 는 2024-07-16 Shorts 맞춤 썸네일을 그해 만들지 않겠다고 하면서 대부분의 Shorts 조회가 썸네일이 보이지 않는 피드에서 나온다는 이유를 댔다 ([PPC Land](https://ppc.land/youtube-ends-2-year-wait-for-shorts-thumbnails-but-blocks-a-b-testing/)). YouTube 공식 블로그(2025-01-28)에서 크리에이터 Jenny Hoyos 는 "99.9% of the views are coming from the Shorts feed"라며 썸네일이 조회에는 중요하지 않지만 "channel marketing and branding" 에는 매우 중요하다고 말했다 ([YouTube Official Blog](https://blog.youtube/creator-and-artist-stories/youtube-shorts-deep-dive/)). 이 99.9% 는 YouTube 전체 데이터가 아니라 크리에이터 한 사람의 발언이다 [실무]. PPC Land 는 같은 수치를 Shorts 제품 책임자의 말로 적었지만 원문 블로그는 Hoyos 의 말로 기록한다. Instagram 의 Adam Mosseri 는 2024-09 Threads 답변에서 릴스 커버가 "only a marginal effect"를 가지며 주로 탐색과 프로필에서 보인다고 했다 ([Lindsey Gamble](https://www.lindseygamble.com/blog/cover-photos-for-reels-have-minimal-impact-according-to-instagram-head-adam-mosseri)) [실무·2차 요약, 원 게시물 직접 인용 미확보]. 이 저장소의 2026-08-17 조사도 릴스 4편의 `reels_skip_rate` 84.8–93.8% 가 커버가 아니라 재생 첫 화면의 문제였다고 결론 내렸다 ([사내 조사](../../2026-08-17-video-cover-design/index.html)) [사내].

그렇다고 커버가 무의미하지는 않다. YouTube 가 2026-07 Shorts 맞춤 썸네일을 내면서 든 이유는 채널 페이지와 홈의 표현이 "to brands is really important"하다는 크리에이터 요구였다 ([PPC Land](https://ppc.land/youtube-ends-2-year-wait-for-shorts-thumbnails-but-blocks-a-b-testing/)). 공식 블로그는 시청자가 "know what to expect"하게 돕는다고 적었다 ([YouTube Official Blog](https://blog.youtube/news-and-events/youtube-studio-custom-thumbnail-updates/)) [공식]. 같은 보도에 따르면 Shorts 는 TV 화면에서만 월 20억 시간이 재생된다(2026-06 YouTube 공개, 2차 보도) [업체]. 커버가 일하는 곳은 새 방문자가 채널 그리드를 훑는 순간, 검색 결과, 구독 피드, 그리고 오래된 영상의 긴 꼬리다. vidIQ 는 피드 밖 표면이 "older Shorts"의 발견과 재시청이 일어나는 곳이라고 보지만 수치는 없다 ([vidIQ](https://vidiq.com/blog/post/youtube-shorts-custom-thumbnails/)) [업체]. "피드 조회가 13% 미만, 맞춤 썸네일로 15–30% 상승" 같은 수치는 1차 데이터로 추적되지 않았다 [요약].

TikTok 쪽은 공식 문서가 거의 읽히지 않았다(고객센터·Creator Academy 가 스크립트 렌더링). 커버가 정지 이미지로 보이는 곳으로 확인된 것은 프로필 그리드뿐이고, 검색·재생목록도 커버를 쓴다는 근거는 "썸네일로 표시되는 모든 곳"이라는 막연한 블로그 문장 하나다 ([Miraflow](https://miraflow.ai/blog/tiktok-cover-image-strategy-2026-profile-grid-convert)) [업체]. 피드에서는 TikTok for Business 광고 지침이 말하는 "첫 3초 안에 제안, 첫 6초에 훅"이 커버 역할을 대신한다 ([사내 조사](../../2026-08-17-video-cover-design/index.html)) [사내, 그 문서가 확인한 공식 광고 지침 인용].

이 차이에서 우선순위가 나온다. 세로 숏폼은 (1) 영상 첫 1초, (2) 채널 그리드·검색용 세로 커버, (3) 링크 미리보기·임베드용 가로 중앙부 순서로 노력을 배분하고, 롱폼은 썸네일 자체에 가장 많은 노력을 쓴다 [추론]. 커버 생성 비용은 도달 개선이 아니라 그리드 정돈과 프로필 방문자 전환 수준의 가치로 잡는 것이 플랫폼 책임자 발언과 맞다 [추론]. 다만 이 플러그인 채널에서 피드 대 채널 페이지·검색 비중을 실제로 재 본 적은 없으므로, YouTube Analytics 의 트래픽 소스별 비중을 먼저 보고 숏폼 커버에 들일 노력을 정하는 편이 맞다.

## 9:16 한 장이 견뎌야 하는 네 번의 크롭

### 롱폼은 3840×2160, 오른쪽 아래는 배지 자리

YouTube 고객센터는 이제 **3840×2160(16:9), 최소 폭 640px, JPG 또는 PNG** 를 권하고, 파일 크기는 **데스크톱 Studio 50MB, 모바일 업로드 2MB** 로 따로 적는다 ([YouTube Help 72431](https://support.google.com/youtube/answer/72431)) [공식]. 흔히 반복되는 "1280×720, 2MB"는 권장값으로서 낡았다. 1280×720 은 Test & Compare 의 품질 하한으로만 남아 있다: 변형 하나라도 720p 미만이면 모든 테스트 썸네일이 480p 로 낮춰진다 ([YouTube Help 16391400](https://support.google.com/youtube/answer/16391400)) [공식]. Data API `thumbnails.set` 도 50MB, `image/jpeg`·`image/png`·`application/octet-stream` 을 받고 해상도 요구는 적지 않으며, 맞춤 썸네일 권한이 없는 계정에는 403 을 돌려준다 ([Thumbnails.set](https://developers.google.com/youtube/v3/docs/thumbnails/set)) [공식]. 세로 영상에 16:9 썸네일을 붙이면 홈·탐색·구독에서 자동 생성 4:5 썸네일로 바뀐다고 같은 고객센터가 적어 두었으므로 롱폼 규칙은 진짜 가로 업로드에만 적용된다 [공식].

YouTube 는 재생시간 배지, 진행 막대, 마우스오버 아이콘의 위치를 공식으로 밝히지 않았다. 도구 업체들은 1280×720 기준 배지가 약 60×120px 이라거나, 오른쪽 아래 200–250px, 또는 폭 20%×높이 15% 를 가려진 영역으로 보라고 적는데 수치가 서로 다르고 YouTube 를 인용하지 않는다 ([wildandfreetools](https://wildandfreetools.com/blog/youtube-thumbnail-safe-zone-guide/), [timeskip](https://timeskip.io/blog/youtube-video-thumbnail-sizes)) [업체·요약]. 보수적인 기본값은 오른쪽 아래 폭 20%×높이 15% 와 하단 5% 띠에 글자·얼굴을 두지 않는 것이다 [추론]. 모바일 피드에서는 썸네일이 폭 약 120–170px 로 보인다는 주장이 많으므로 ([1of10](https://1of10.com/blog/youtube-thumbnail-trends-2026/)) [업체], 160×90 축소본에서 피사체와 글자가 읽히는지 보는 검사가 가장 값싼 품질 확인이다 [추론].

### 세로 커버의 안전 띠는 계산으로 정한다

세로 커버는 네 종류의 잘림을 겪는다. 첫째, Instagram 프로필 그리드는 2025-01 부터 정사각에서 세로 3:4 로 바뀌어 9:16 원본의 가운데 1080×1440(y=240–1680)만 보인다 ([Planoly](https://webflow.planoly.com/blog/the-ups-and-downs-of-instagrams-new-rectangle-grid), [Kapwing](https://www.kapwing.com/resources/instagrams-new-grid-layout-size-and-dimensions-2025/)) [업체]. Mosseri 는 세로 업로드를 정사각으로 자르는 것이 "pretty brutal"하다고 이유를 댔다 ([Engadget](https://www.engadget.com/social-media/instagrams-experimental-profile-grid-has-rectangular-images-instead-of-squares-160007086.html)) [업체]. TikTok 그리드도 가운데 3:4 라는 도구·블로그 주장이 다수다 ([socialk.it grid planner](https://socialk.it/en/tools/tiktok-grid-planner), [nemovideo](https://www.nemovideo.com/blog/tiktok-thumbnail-guide)) [업체·일부 요약]. nemovideo 는 안전영역을 "Y:240~1600"으로 적지만 위아래 240px 를 빼면 1680 이 맞으므로 이 보고서는 240–1680 을 쓴다. 둘째, Instagram API 문서는 `cover_url` 이 9:16 이 아니면 "the middle most 9:16 rectangle"을 쓰고 피드에 공유하면 "middle-most 1:1 square"를 쓴다고 적고 ([IG User Media, v27.0](https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-user/media)) [공식], SocialRails 는 TikTok 그리드가 1:1 이라고 적는다 ([SocialRails](https://socialrails.com/blog/tiktok-thumbnail-size-guide)) [업체, 출처 없음]. 1:1 영역은 y=420–1500 이다. 셋째, YouTube Shorts 썸네일은 Data API 문서가 "cropped to a 9:16 portrait aspect ratio"라고 적는 반면 ([Thumbnails resource](https://developers.google.com/youtube/v3/docs/thumbnails)) [공식], Creator Liaison Rene Ritchie 는 일부 표면에서 "3:2 에 가깝게" 보인다고 말했다는 보도가 있다 ([PPC Land](https://ppc.land/youtube-ends-2-year-wait-for-shorts-thumbnails-but-blocks-a-b-testing/), [Relevant Audience](https://www.relevantaudience.com/social-media-marketing/youtube-shorts-custom-thumbnails-no-ab-testing/)) [업체, 두 기사 모두 직접 인용 없음]. 링크 미리보기·임베드·검색은 가로 키(`hqdefault`, `maxresdefault`)를 가져가므로 세로 이미지의 가운데 가로 부분만 쓰인다는 해석이 가장 단순하다 [추론]. 넷째, 커버가 영상 첫 프레임과 같을 때는 Reels 재생 UI 가 위 14%·아래 35%·좌우 6% 를 덮는다 ([Adnova](https://adnova.ai/blogs/meta-ad-safe-zones-guide)) [업체, 광고 안전영역 정리].

네 조건을 1080×1920 캔버스에 겹치면 세 겹의 띠가 나온다 [추론·계산]. **핵심 띠 y≈656–1264** 는 가운데 16:9 가로 조각(높이 608px)으로, Shorts 의 가로 표면 크롭, 1:1 피드 크롭, 3:4 그리드를 모두 견디고 Reels 하단 35% UI 경계(y=1248)와도 거의 맞닿는다. 얼굴과 핵심 문구는 이 띠 안에 둔다. **보조 띠 y=420–1500** 은 1:1 크롭까지 견디므로 시리즈 번호·보조 문구를 둘 수 있다. **바깥 띠 y=240–1680** 밖에는 그리드에서 보이지 않으므로 필요한 정보를 두지 않는다. 좌우는 x=65–1015(6%)를 지킨다. 이 계산에서 가장 불확실한 경계는 핵심 띠다. Shorts 의 "3:2" 주장이 틀리고 API 문서의 9:16 이 맞다면 핵심 띠는 1:1 띠까지 넓어진다. 반대로 시리즈 제목을 3:4 띠의 위쪽 1/3(y≈300–700)에 두는 배치는 Reels 상단 UI 와 3:4 그리드는 피하지만 1:1 크롭에서 잘리므로 이 보고서의 기본값으로 쓰지 않는다. 사내 교집합 안전영역(상 15·하 35·좌 6·우 18%)은 이미 3:4 그리드 크롭을 견딘다고 2026-08-17 조사가 확인했다 ([사내 조사](../../2026-08-17-video-cover-design/index.html)) [사내].

두 종류의 안전영역을 섞지 않아야 한다. 피드 UI 안전영역(아래 캡션·오른쪽 버튼 줄을 피함)은 영상 프레임에 적용되고, 썸네일 안전영역(가운데 띠)은 업로드한 커버에 적용된다 ([vidIQ](https://vidiq.com/blog/post/youtube-shorts-custom-thumbnails/)) [업체+추론]. 커버를 첫 프레임과 겸하게 할 때만 둘을 함께 만족시킨다.

### 플랫폼별 파일 규격

Instagram `cover_url` 은 공개 서버의 JPEG, 최대 8MB, sRGB(다른 색공간은 변환), 9:16 권장이고 최소 해상도는 문서에 없다 ([IG User Media](https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-user/media)) [공식]. Facebook `thumbnails` 는 최대 10MB 이고 "We recommend that you use thumbnails with the same aspect ratio as the video"라고 적는다 ([Video Thumbnails](https://developers.facebook.com/docs/graph-api/reference/video/thumbnails/)) [공식]. Facebook Reels Publishing API 는 9:16, 1080×1920 권장, 최소 540×960, 3–90초다 ([Reels Publishing guide](https://developers.facebook.com/docs/video-api/guides/reels-publishing)) [공식]. TikTok 커버 이미지 규격(1080×1920, 최소 720×1280, JPG/PNG, 최대 20MB)은 블로그가 같은 글 FAQ 에서 5MB 미만을 권하는 등 자체 모순이 있어 확정하지 못했다 ([SocialRails](https://socialrails.com/blog/tiktok-thumbnail-size-guide)) [업체]. 더 근본적인 미확인 사실은 TikTok Studio 가 업로드한 커버를 3:4 로 잘라 저장하는지 9:16 으로 저장하는지다. 2024-01 보도는 데스크톱 웹 업로드에 3:4 크롭 도구가 뜬다고 적었다 ([RouteNote](https://routenote.com/blog/upload-tiktok-thumbnail/)) [업체]. 3:4 로 저장한다면 TikTok 용 커버는 1080×1440 으로 따로 준비해야 한다.

## API 로 되는 것과 앱에서만 되는 것, 날짜별로

### YouTube: 롱폼은 오래전부터, Shorts 는 2026-11-03 부터 API

롱폼 맞춤 썸네일은 계정 인증이 필요하고 하루 업로드 한도가 있으며 한도는 "may vary by country/region or channel history"라고 고객센터가 적는다 ([YouTube Help 72431](https://support.google.com/youtube/answer/72431)) [공식]. Studio 의 Test & Compare 는 제목만, 썸네일만, 제목+썸네일 조합을 최대 3개까지 시험하고 **CTR 이 아니라 시청 시간으로 승자를 고른다**: "we optimize tests for overall watch time over other metrics, like click-through-rate" ([YouTube Help 16391400](https://support.google.com/youtube/answer/16391400)) [공식]. 데스크톱 전용이고, 며칠에서 2주 동안 돌며, 아동용·성인용·비공개 영상과 Shorts·예약 라이브·프리미어는 제외되고, 테스트 중 제목이나 썸네일을 고치면 멈춘다 [공식]. 결과 표시는 현재 페이지에서 Winner·Performed Same·Inconclusive 인데, 옛 썸네일 전용 페이지 요약에는 "Preferred"라는 표시도 보여 표시 체계가 바뀐 것으로 보인다 ([YouTube Help 13861714](https://support.google.com/youtube/answer/13861714)) [공식+요약]. Data API 가 Test & Compare 를 만들거나 읽는다는 근거는 찾지 못했으므로 이 단계는 Studio 수작업이다 [추론]. 제목 테스트는 2025-07 일부 크리에이터에게 먼저 열렸고 이후 전체 확대가 보도됐다 ([Tubefilter](https://www.tubefilter.com/2025/07/16/youtube-feature-test-and-compare-titles-thumbnails/), [Search Engine Journal](https://www.searchenginejournal.com/youtube-title-a-b-testing-rolls-out-globally-to-creators/562571/)) [요약]. 2026-03-10/11 에는 다국어 오디오 트랙을 올린 크리에이터가 언어별 번역 썸네일을 붙일 수 있게 됐다는 보도가 있다. 이미지는 크리에이터가 직접 올리고 AI 번역은 언급되지 않았다 ([Denfami Nico Gamer](https://news.denfaminicogamer.jp/news/260311i)) [업체·보도, 1차 공지 원문 미확보].

Shorts 는 일정이 촘촘하다. 2024-09-04 iOS·Android 앱에 프레임 선택과 글자·필터·이모지 편집이 들어왔다 ([Search Engine Journal](https://www.searchenginejournal.com/youtube-rolls-out-new-shorts-thumbnail-editing-features/526162/)) [업체·보도]. 2026-07-24 공식 블로그는 "YouTube Partner Program creators can start uploading custom thumbnails for Shorts"와 데스크톱 추천 프레임 3개를 알렸다 ([YouTube Official Blog](https://blog.youtube/news-and-events/youtube-studio-custom-thumbnail-updates/)) [공식]. 현재 고객센터는 YPP 를 언급하지 않고 "Your account must be verified"만 적는다 ([YouTube Help 72431](https://support.google.com/youtube/answer/72431?hl=en)) [공식]. Data API 는 2026-09-14 썸네일 최대 크기를 2MB 에서 50MB 로 올렸고, **2026-11-03 "The thumbnails.set method now supports uploading custom thumbnails for YouTube Shorts after video processing is complete"** 를 추가하면서 `thumbnails` 리소스에 `shortsAspectRatio` 키를 넣었다 ([Revision history](https://developers.google.com/youtube/v3/revision_history)) [공식]. 레퍼런스는 처리 완료(`processingDetails.processingStatus` = `succeeded`) 전에 호출하면 "the custom thumbnail might not be applied to the Short"라고 경고한다 ([thumbnails.set](https://developers.google.com/youtube/v3/docs/thumbnails/set)) [공식].

이 변화 이전의 사내 실측과 충돌하는 지점을 정확히 적어 둔다. 2026-08 실측에서 `thumbnails.set` 은 가로 표면(hq720/maxresdefault: 검색, 링크 미리보기, 임베드, 추천)만 바꿨고, Shorts 탭·피드·Shorts 검색이 쓰는 세로 `oar*` 프레임은 웹 Studio "Select from video"(2026-08-19 확인)나 앱 프레임 선택으로만 바뀌었다 ([shorts-surface-adb.md](../../../../skills/publish/references/shorts-surface-adb.md)) [사내]. 2026-11-03 변경이 이 결과를 뒤집었는지, 비 YPP 채널에도 세로 타일이 바뀌는지는 아직 아무도 확인하지 않았다. 현재 `youtube_publish` 는 처리 완료를 기다린 뒤 썸네일을 넣고, 공개 Shorts 탭에서 API 커버가 확인될 때까지 Studio 프레임 선택 단계를 유지한다 ([publish SKILL.md](../../../../skills/publish/SKILL.md)) [사내]. 이 보고서도 그 순서를 유지하라고 권한다. Shorts 에는 A/B 테스트가 없고("A/B testing is not available for Shorts"), 3분 이하의 정사각 이상 세로 영상은 Shorts 로 분류되므로 Test & Compare 가 필요한 에피소드는 16:9 로 올리거나 3분을 넘겨야 한다 ([YouTube Help 13861714](https://support.google.com/youtube/answer/13861714?hl=en)) [공식].

### TikTok: API 는 프레임 번호만, 이미지 커버는 Studio 에서

Content Posting API 의 Direct Post 본문에는 `video_cover_timestamp_ms` 하나만 있다: "Specifies which frame (measured in milli-seconds) will be used as the video cover." 비우거나 잘못된 값이면 첫 프레임이 커버가 된다. **커버 이미지 업로드 필드는 없고**, 게시 후 커버나 공개 범위를 바꾸는 엔드포인트도 없다 ([Direct Post reference](https://developers.tiktok.com/doc/content-posting-api-reference-direct-post)) [공식]. `privacy_level` 은 `/creator_info/query/` 가 돌려준 값(`PUBLIC_TO_EVERYONE`, `MUTUAL_FOLLOW_FRIENDS`, `FOLLOWER_OF_CREATOR`, `SELF_ONLY`)만 받는다 [공식]. 사진 캐러셀은 `photo_cover_index` 로 커버를 고른다 ([Photo Post reference](https://developers.tiktok.com/doc/content-posting-api-reference-photo-post)) [공식]. Display API 는 정적 `cover_image_url`(TTL 6시간)과 `width`·`height` 를 주므로 저장된 커버를 받아 비교하는 검증이 가능하다 ([Video Object](https://developers.tiktok.com/doc/tiktok-api-v2-video-object)) [공식].

이미지 커버를 넣는 길은 앱 또는 TikTok Studio 웹이다. Creator Academy 요약은 웹에서 "자신의 커버를 업로드하거나 영상의 한 프레임을 커버로 선택"할 수 있다고 적는다 ([Creator Academy](https://www.tiktok.com/creator-academy/article/tool-web-creation-intro)) [공식·요약]. 날짜 없는 Tabcut 글은 업로드 기능이 "has since been removed"라고 적어 충돌한다 ([Tabcut](https://tabcut.com/blog/post/how-to-upload-a-custom-tiktok-cover-image-shorts-tiktoktipsandtricks)) [업체]. 게시 후 수정은 2026-07-28 JoinBrands 가 앱 ⋯ → "Edit post"에서 **게시 후 7일 안, 하루 1회** 가능하다고 적었지만 근거는 크리에이터의 YouTube 시연이고 "availability can vary by account, region, and app version"이라는 단서가 붙는다 ([JoinBrands](https://joinbrands.com/blog/how-to-edit-tiktok-videos-after-posting/)) [업체]. Kapwing 은 예전에 "변경 불가"라고 적었다 ([Kapwing](https://www.kapwing.com/resources/how-to-change-tiktok-thumbnail/)) [업체]. 저장소의 2026-11-18 지침은 이미 비공개(SELF_ONLY)로 올리고, ego lite 에서 커버를 편집·저장·재확인한 뒤 같은 게시물을 Everyone 으로 바꾸고, 막히면 비공개로 두고 보고하라고 정해 두었다 ([tiktok-private-cover.md](../../../../skills/publish/references/tiktok-private-cover.md)) [사내]. 하루 1회 제한이 사실이면 비공개 단계에서 한 번에 맞춰야 하므로, 커버 파일을 Studio 에 올리기 전에 로컬에서 3:4·1:1 크롭 미리보기를 끝내 두는 편이 맞다 [추론].

`video_cover_timestamp_ms` 로 영상 안의 커버 화면을 고르는 방법은 이 저장소 안에서 지침끼리 부딪치는 지점이다. 현재 produce 규칙 10은 첫 화면을 코드로 쓴 훅 제목 화면으로 만들고, publish 지침은 Instagram 에 그 시각을 `thumbOffsetMs` 로 넘기며 Shorts 도 그 프레임을 고르게 한다 ([publish SKILL.md](../../../../skills/publish/SKILL.md)) [사내]. 반면 2026-09-05 지침은 움직이는 그림 위에 어떤 글자도 두지 않는다고 정했다. 코드로 그린 정지 화면이 그 금지에 해당하는지는 소유자가 정할 문제다. 그 결정 전까지는 커버 화면이 있는 에피소드에서 그 시각을 `coverTimestampMs`(플러그인의 `tiktok_publish` 입력, `video_cover_timestamp_ms` 로 전달)로 넘기고, 없는 에피소드는 Studio 업로드로 이미지 커버를 넣는 것이 현실적인 선택이다 [추론].

TikTok 은 1분을 넘는 16:9 영상에 전체화면 버튼을 붙이고 업로드 길이를 60분까지 시험했지만(2024), 가로·롱폼 영상 커버가 그리드에서 어떻게 보이는지 다룬 공식 안내는 찾지 못했다 ([Search Engine Land](https://searchengineland.com/tiktok-testing-60-minute-video-uploads-440588), [Kapwing](https://kapwing.com/resources/horizontal-tiktoks)) [업체·보도]. 세로 그리드 타일에 16:9 프레임이 들어가면 레터박스나 가운데 잘림이 생길 가능성이 높으므로, 가로 영상일수록 9:16 맞춤 커버 업로드의 이득이 크다 [추론].

### Instagram·Facebook·Threads: 게시 순간이 유일한 기회인 곳과 나중에 고칠 수 있는 곳

Instagram REELS 컨테이너는 `cover_url` 과 `thumb_offset`(ms, 기본 0 = 첫 프레임)을 받고 "If you specify both `cover_url` and `thumb_offset`, we use `cover_url` and ignore `thumb_offset`"이다. `share_to_feed=false` 면 릴스 탭에만 올라가며, 게시된 미디어를 수정하는 항목은 "This operation is not supported"다 ([IG User Media](https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-user/media)) [공식]. 사람은 앱에서 릴스 → ⋯ → Edit 으로 커버를 바꾸거나 카메라 롤 이미지로 교체할 수 있고 ([Later](https://later.com/blog/instagram-reels-cover-photo/)) [업체], 길게 누르기 → "Adjust Cover"로 그리드 미리보기 위치도 옮길 수 있다 ([Lindsey Gamble](https://www.lindseygamble.com/blog/instagram-rolls-out-thumbnail-customization-as-part-of-profile-updates)) [업체, 게시일 "Feb 12" 에 연도 없음, 맥락상 2025]. 그리드 위치는 API 로 지정할 수 없으므로 커버 자체를 가운데 정렬 구도로 만드는 것이 API 게시의 유일한 통제 수단이다 [추론]. Instagram 은 API 로 비공개 게시할 방법이 없어 TikTok·YouTube 의 "비공개 → 확인 → 공개" 순서를 쓸 수 없다 ([사내 조사 2026-11-18](../../2026-11-18-sns-video-publish-apis/README.md)) [사내]. 그 자리를 로컬 크롭 미리보기가 대신해야 한다.

Facebook 은 2025-06-17 "all videos will be shared as reels"를 발표했고 Video 탭을 Reels 탭으로 바꿨다 ([Meta Newsroom](https://about.fb.com/news/2025/06/making-it-easier-create-videos-facebook/amp/), [TechCrunch](https://techcrunch.com/2025/06/17/facebook-announces-that-all-videos-on-its-platform-will-soon-be-shared-as-reels)) [공식]. 그런데 Reels Publishing API 는 여전히 3–90초이므로, 100–215초 에피소드 대부분은 이 플러그인에서 일반 Page 영상(`/{page-id}/videos`)으로 올라간다 [공식+사내]. 커버는 업로드 때 `thumb` 로 붙이거나 게시 뒤 `POST /{video-id}/thumbnails` 에 `source` 와 `is_preferred=true` 를 보내 교체한다. 이 엔드포인트는 Page 에 연결된 영상에서만 되고 `pages_read_user_content`·`pages_manage_engagement`·`pages_show_list` 권한이 필요하다 ([Video Thumbnails](https://developers.facebook.com/docs/graph-api/reference/video/thumbnails/), [Page Videos](https://developers.facebook.com/docs/graph-api/reference/page/videos/)) [공식]. 일곱 표면 가운데 게시 후 API 로 커버를 바꿀 수 있는 곳은 YouTube 와 Facebook 뿐이다.

Threads 게시 API 의 27개 파라미터에는 cover·thumbnail 계열이 하나도 없고 영상 전용은 `video_url` 뿐이다 ([Threads Publishing reference](https://developers.facebook.com/docs/threads/reference/publishing)) [공식]. Postmypost 는 Threads 커버를 지원한다고 표시하고 SocialPilot 은 "No"로 표시하는데 ([Postmypost](https://help.postmypost.io/docs/tools/publications/faq/video-cover), [SocialPilot](https://help.socialpilot.co/article/855-how-to-edit-video-thumbnails-on-socialpilot-in-the-new-create-post-experience)) [업체], 공식 파라미터가 없으니 Postmypost 는 영상 앞에 프레임을 붙이는 우회일 가능성이 높다 [추론]. Threads 에서는 첫 프레임이 곧 미리보기다.

## 얼굴과 색은 기본 문법일 뿐, 짧은 글자와 약속 이행이 근거가 가장 단단하다

### 대규모 조사가 실제로 잰 것

2025–2026 의 큰 썸네일 조사 셋은 모두 **CTR 이 아니라 채널 자기 평균 대비 조회수(브레이크아웃)** 를 쟀고, 썸네일을 제목·주제·시점에서 떼어 내지 못했다 [측정]. 그중 비교군을 둔 것은 Eden 하나다. Eden 은 2025-08~2026-08 에 올라온 롱폼 507,478개(8,691개 채널)에서 채널 기준의 2배 이상을 브레이크아웃(33.7%), 기준 이하를 부진(42.1%)으로 나누고 썸네일 2,960개를 비전 모델로 코딩했으며 약 2.5%p 미만의 차이는 잡음으로 본다 ([Eden](https://eden.so/blog/what-makes-a-good-youtube-thumbnail/)) [측정]. 결과는 흔한 조언을 상당 부분 무너뜨린다. 얼굴은 브레이크아웃 84.2% 대 부진 82.2%, 정확히 한 얼굴 55.6% 대 54.1%, 화면 절반 이상 얼굴 15.8% 대 14.9% 로 차이가 없다. 밝기 40.9 대 40.5, 대비 23.5 대 23.1, 채도 35.2 대 34.7, 따뜻한 색 비중 31.1 대 30.5 도 모두 잡음 안이다. 잡음 기준을 넘은 신호는 작다: **4~6단어 글자 30.6% 대 26.5%, 무글자 13.4% 대 16.8%**(무글자가 부진 쪽에 25% 더 흔함), 차분·진지한 표정 51.1% 대 47.4%, 카메라 응시 32.4% 대 29.2%, 화살표·원 같은 그린 그래픽 41.8% 대 38.1%. 놀란 얼굴은 8.5% 대 7.7% 로 잡음 안이고, 구독자 10만 이상 채널의 브레이크아웃에서만 11.7% 로 높았다. 제목을 그대로 반복한 글자(6.3% 대 6.8%)와 제목과 단어를 하나도 공유하지 않는 글자(39.2% 대 39.1%)도 차이가 없다 [측정].

vidIQ 는 2026-06 브레이크아웃 롱폼 500개(30개 분야, 채널 평균의 18배 이상)를 비교군 없이 기술했다. 얼굴 69%(상위 50개 80%), 고대비 56%(상위로 갈수록 46% 로 감소), 글자 사용 72%·글자 썸네일 중앙값 **5단어**, 과장된 표정 5% 였고, 가장 흔한 승자 구도는 화면 약 3분의 1 을 채운 얼굴과 그 반대편의 짧은 굵은 문구였다 ([vidIQ Research](https://vidiq.com/research/youtube-thumbnail-study/)) [측정, 기술 통계]. vidIQ 의 단어 수 분포는 합계가 맞지 않아(약 59개가 빠짐) 세부 분포는 인용하지 않는다. 1of10 은 30만 개 이상의 2025 바이럴 영상에서 "thumbnails with faces and thumbnails without faces perform similarly"라고 보고했고 얼굴이 금융에서는 도움, 비즈니스에서는 손해였다고 했다 ([Search Engine Journal](https://www.searchenginejournal.com/do-faces-help-youtube-thumbnails-heres-what-the-data-says/563944/)) [측정, 방법 미공개]. 같은 조사의 "여러 얼굴이 가장 좋았다"는 주장은 수치가 없어 근거로 쓰지 않는다. 1of10 블로그의 "승자는 네온 색 하나를 포함한 3색"이라는 주장은 Eden 의 채도 무차이 결과와 충돌한다 ([1of10 Trends 2026](https://1of10.com/blog/youtube-thumbnail-trends-2026/)) [업체].

학술 근거도 방향은 비슷하고 강도는 약하다. Cui·Chung·Peng·Wang(*Journal of Business Research* 183권, 2024)은 2023-02 에 올라온 YouTube 영상 16,215개에서 썸네일 이미지의 강한 감정(긍정·부정 모두)이 조회수와 함께 오르고 "captions"의 강한 감정은 반대 방향이라고 보고했다 ([Lingnan Scholars](https://scholars.ln.edu.hk/en/publications/clicks-for-money-predicting-video-views-through-a-sentiment-analy/)) [측정]. 보도자료는 얼굴·고해상도·선명한 색이 클릭 증가와, 긴 글자가 클릭 감소와 연관된다고 적었지만 원문을 열지 못했고 "captions"가 썸네일 위 글자인지 제목인지도 확인하지 못했다 ([Asia Research News](https://www.asiaresearchnews.com/node/20288)) [측정·요약]. 그러므로 "감정은 그림이 전하고 글자는 감정어를 덜어 낸다"는 해석은 가설로만 쓴다. 아이트래킹에서는 Florida 대 Jain Lab(ETRA 2018) 참가자들이 볼 영상을 고를 때 제목 영역보다 썸네일에 약 두 배의 시선을 썼다 ([Jain Lab](https://faculty.eng.ufl.edu/jain/research/completed-projects/eye-tracking-for-online-user-experience/)) [측정·요약]. "얼굴 +30% CTR", "Creator Insider 데이터 2.3배"는 검색 요약에만 나오고 원 페이지를 찾지 못했다 [요약]. "맞춤 썸네일 154% 상승"은 출처 미상이고 "시각 처리 6만 배 빠름"은 1982년 Business Week 광고 문구로 거슬러 올라간다 ([Mark Studios 집계표](https://www.markstudios.com/research/video-thumbnail-and-ctr-statistics)) [업체].

### CTR 만 보면 틀린 승자를 고른다

YouTube 의 유일한 공식 기준은 "Half of all channels and videos on YouTube have an impressions CTR that can range between 2% and 10%"이고, 홈처럼 노출이 많은 표면에서는 CTR 이 자연히 낮아진다 ([YouTube Help 7628154](https://support.google.com/youtube/answer/7628154?hl=en)) [공식]. 같은 페이지는 높은 CTR·낮은 평균 시청 시간을 클릭베이트 신호로 보고 그런 영상은 "less likely to get recommended"라고 적는다 [공식]. Test & Compare 가 시청 시간으로 승자를 고르는 것도 같은 원리다. 반면 오도 썸네일이 시청 유지·만족도를 얼마나 깎는지 직접 잰 영상 연구는 찾지 못했다. 신뢰도 하락 근거는 뉴스 헤드라인 실험에서 나오는데, 그쪽도 클릭베이트 헤드라인이 호기심을 더 일으키지 못했다는 결과가 함께 있다 ([Penn State](https://pure.psu.edu/en/publications/does-clickbait-actually-atract-more-clicks-three-clickbait-studie/)) [측정·요약]. 같은 채널 안에서 "감정적 미끼" 영상이 조회수 중앙값 +65.6% 였다는 키즈 채널 프리프린트도 있으므로 ([Mark Studios 집계표](https://www.markstudios.com/research/video-thumbnail-and-ctr-statistics)) [측정·2차 집계, 원문 미열람], 미끼가 단기 조회를 늘릴 수 있다는 신호도 있다. 이 저장소가 미끼를 피하는 근거는 효과가 없다는 증명이 아니라 YouTube 가 그 대가를 추천과 정책으로 매긴다는 공식 문서다.

Eden 수치에서 하나 더 읽힌다. 영상 길이별 브레이크아웃률은 5분 미만 26.9% 에서 40분 초과 41.1% 로, 제목 길이별로는 30자 미만 26.1% 에서 75자 초과 35.9% 로 움직였다 ([Eden](https://eden.so/blog/what-makes-a-good-youtube-thumbnail/)) [측정]. 이 14%p·10%p 차이는 썸네일 요소 어느 것보다 크다. Eden 이 이 비교를 직접 주장한 것은 아니지만 [추론], 썸네일 최적화에 들이는 노력이 주제·길이·제목보다 앞설 이유는 근거에서 나오지 않는다.

### 장르별 차이는 측정되지 않았다

장르별 썸네일 전략을 비교한 측정 연구는 없다. vidIQ 는 DIY·음식·제품 분야 브레이크아웃에서 사물 중심 구도가 반복된다고 질적으로만 적었고 ([vidIQ](https://vidiq.com/research/youtube-thumbnail-study/)) [측정, 질적], 1of10 블로그는 오락·라이프스타일·게임·리액션에서는 무글자가, 교육·금융·법률·의료에서는 글자가 필요하다고 적었다 ([1of10 Trends 2026](https://1of10.com/blog/youtube-thumbnail-trends-2026/)) [업체]. 숏드라마 광고 분석은 짧은 노출에서도 통하는 약속으로 관계의 결정, 뜻밖의 정체, 위협받는 인물을 든다 ([AdMapix](https://www.admapix.com/blog/ad-intelligence/reelshort-ad-strategy-2026)) [업체]. 이를 합치면 드라마·스토리는 인물이 결정·위협에 놓인 실제 장면의 클로즈업에 0~4단어, 설명·주장형은 결과물(증거) 이미지에 시청자 말로 쓴 짧은 약속 문구, 튜토리얼·리뷰는 결과나 제품을 크게 보여 주는 사물 구도가 근거 방향과 맞는다 [추론]. 설명·주장형 규칙은 이 저장소의 promise and proof 지침과 같은 원리다.

## 한글 썸네일: 짧은 단어형, 코드로 쓴 글자

한국어 썸네일의 글자 양·색과 CTR 의 관계를 표본으로 잰 국내 연구나 에이전시 보고서는 찾지 못했다(네이버 검색 경로가 이번 조사에서 막혀 있었다). 남은 근거는 실무 블로그와 한 편의 논문이다. 오픈애즈(2023-09-07)는 피사체 하나(많아도 2~3개), 색 3가지 이하, 시청자가 가장 궁금해할 한 가지, 80% 이상이 휴대폰으로 보므로 생각보다 20% 크게, 그리고 썸네일 문구는 후킹·제목은 내용 설명으로 역할을 나눠 같은 말을 반복하지 말라고 권한다 ([오픈애즈](https://www.openads.co.kr/content/contentDetail?contsId=11601)) [실무]. 고구마팜(2024-02-21)은 요소를 큰 덩어리로 묶고, 타이틀과 이미지 사이 명도 차를 가장 크게, 설명 문구 4개 이하, 폰트 종류를 최소로 하라고 한다 ([고구마팜](https://gogumafarm.kr/브랜드-유튜브-디자인-전략-토크-예능-콘텐츠-썸네일/)) [실무]. 크몽·NONOWIKI 등은 "3~5단어", "4단어 또는 8글자", "10글자 이내"로 기준을 저마다 다르게 적고, 굵기 800 이상·외곽선 4px 이상, 흰 글자+검정 외곽선, 강조어 하나만 노랑을 권한다 ([크몽](https://kmong.com/article/1015--%EC%A1%B0%ED%9A%8C%EC%88%98-%EC%98%AC%EB%A6%AC%EB%8A%94-%EC%9C%A0%ED%8A%9C%EB%B8%8C-%EC%8D%B8%EB%84%A4%EC%9D%BC-%EB%94%94%EC%9E%90%EC%9D%B8-%ED%8C%81-5%EA%B0%80%EC%A7%80), [NONOWIKI](https://nonowiki.com/%EC%9C%A0%ED%8A%9C%EB%B8%8C-%EC%8D%B8%EB%84%A4%EC%9D%BC-%EC%83%89%EC%83%81-%ED%8F%B0%ED%8A%B8-%EC%A0%84%EB%9E%B5-%ED%81%B4%EB%A6%AD%EB%A5%A0ctr%EC%9D%84-%EB%86%92%EC%9D%B4%EB%8A%94-%EC%8B%A4/)) [실무·요약]. "CTR 18~22% 상승", "카피 테스트로 6% → 10%" 같은 수치는 출처가 없다. 현직 PD 관찰로는 문장형 썸네일에서 짧은 "단어형 썸네일"로 옮겨 가는 추세가 보이고, 예로 '또간집'은 지역명만 적는다 ([careet](https://www.careet.net/1417)) [실무·요약].

KAIST 의 WWW '26 논문은 한국 뉴스 채널 7개(292,136개 영상)와 미국 16개(105,761개)에서 썸네일과 제목을 함께 분류했다. "타인 비난" 수사의 조회수 IRR 은 미국 1.94 인데 한국은 1.04 에 그쳤고, 한국에서는 "중립"이 모든 지표를 낮췄으며 "타인 칭찬"은 두 나라 모두 참여를 낮췄다 ([arXiv 2601.21815](https://arxiv.org/html/2601.21815v2)) [측정]. 미국 실무자의 "분노·자극" 조언을 한국어 채널에 그대로 옮기면 안 된다는 신호지만 뉴스 채널 한정이다. 같은 논문은 한국 썸네일이 오버레이 캡션을 자주 넣어 도덕적 단서가 더 명시적이라고 해석했는데 이는 측정이 아니라 저자 해석이다 [측정 논문 속 해석].

영어 단어 수를 한글로 옮기는 기준은 없다. 영어 4~6단어는 한글로 대략 2~4 어절, 10~12음절 이하에 해당한다고 보는 것이 이 보고서의 환산이다 [추론]. 썸네일 크기(폭 120~360px)에서 한글 글자 높이별 판독률을 잰 연구는 없고, 국내 가독성 논문은 본문 크기(모바일 고딕의 굵기·획 대비·속공간·자간, 차량 화면 최소 가독 크기)를 다룬다 ([KoreaScience 2023](https://koreascience.kr/article/JAKO202325051029868.pdf), [KoreaScience 2012](https://koreascience.kr/article/JAKO201212851254986.pdf)) [측정, 초록 수준]. 한글은 한 음절에 초성·중성·종성을 쌓아 같은 높이에서 라틴 대문자보다 획이 촘촘하므로, 받침이 단순한 짧은 단어를 고르고 글자 높이를 넉넉히 잡고, 외곽선은 글자 바깥으로만 그려(paint-order stroke) 속공간을 메우지 않는 편이 맞다 [추론, 측정 없음]. 접근성에서 쓸 수 있는 가장 권위 있는 수치는 WCAG 의 큰 글자 대비 3:1 이다 ([web.dev](https://web.dev/learn/accessibility/color-contrast)) [공식 표준·이미지 위 글자 적용은 해석]. 노랑·흰 글자에 검정 외곽선은 적록 색각 이상에서도 명도 차가 커서 안전하고, 빨강·초록만으로 대비를 만드는 조합은 피한다 [추론].

생성 모델로 한글을 그리는 일은 아직 위험하다. 2026-05-29 스냅숏의 korean-text-render-bench 는 흰 포스터에 검정 산세리프 한글만 그리게 하고 GPT-4o 가 판독했다. **gpt-image-2 는 CER 0.038, 13개 중 12개 정확(92%)** 으로 상위권이었지만 완벽하지 않았고, imagen-4 는 14개 모두 한글처럼 보이는 가짜 글자를 그렸다. 실패 사례는 떡볶이→덕볶이, 맑음→맘음, "커피 2잔"→"커피 22잔"처럼 겹받침·된소리·숫자에서 나왔다 ([korean-text-render-bench](https://github.com/hankimis/korean-text-render-bench)) [측정, 셀당 1장·판독자도 모델·README 와 본문의 모델 수 불일치]. 이 저장소가 쓰는 Qwen-Image·Z-Image 는 이 벤치마크에 없다. 그러므로 썸네일 문구는 코드로 합성하고 모델에는 배경과 인물만 그리게 하는 방식이 기본값이다. 장면 속 간판·포장처럼 그림 안의 글자가 필요할 때만 저장소 지침대로 GPT Image 2 를 쓰고 결과 글자를 판독한다. 글자를 별도 층으로 두면 YouTube 언어별 썸네일도 이미지 재생성 없이 만들 수 있다 [추론].

## 공개 의무는 YouTube 만 분명하고, 오도 금지는 모든 플랫폼에 걸린다

YouTube 의 합성 콘텐츠 공개 도움말은 "generative AI tools to create or improve a video outline, script, thumbnail, title, or infographic"을 제작 보조로 분류해 **썸네일 자체는 공개 대상이 아니라고** 명시한다. 공개 대상은 실제 인물이 하지 않은 말·행동, 실제 사건·장소 영상의 변경, 일어나지 않은 사실적 장면이며, 비현실적·애니메이션 콘텐츠는 제외된다. 다만 YouTube 는 C2PA 메타데이터가 있거나 내부 시스템이 탐지한 콘텐츠에 자동 라벨을 붙일 수 있고, 그렇게 붙은 라벨은 크리에이터가 바꿀 수 없다 ([YouTube Help 14328491](https://support.google.com/youtube/answer/14328491?hl=en)) [공식]. 이 저장소는 이미 사실적 생성 인물이 나오는 영상에 `containsSyntheticMedia: true` 를 붙인다 ([produce SKILL.md](../../../../skills/produce/SKILL.md)) [사내]. 썸네일 공개 여부와 영상 공개 여부는 별개다.

TikTok 은 Direct Post 의 `is_aigc` 를 켜면 설명란에 "Creator labeled as AI-generated" 태그를 붙이고, `brand_content_toggle`(제3자 유료 협찬)과 `brand_organic_toggle`(자기 사업 홍보)을 따로 둔다 ([Direct Post reference](https://developers.tiktok.com/doc/content-posting-api-reference-direct-post)) [공식]. TikTok 은 C2PA Content Credentials 를 읽어 자동 라벨을 달고 2026-07 기준 30억 건 이상에 라벨을 붙였다고 보도됐다 ([Tubefilter 2026-07-14](https://www.tubefilter.com/2026/07/14/tiktok-ai-transparency-tools-content-labels/)) [업체·보도]. Meta 는 2024-02 부터 C2PA·IPTC·보이지 않는 워터마크로 AI 이미지를 탐지해 라벨을 달고 2024-07 이름을 "AI info"로 바꿨으며 ([Meta Newsroom](https://about.fb.com/news/2024/02/labeling-ai-generated-images-on-facebook-instagram-and-threads/), [TechCrunch](https://techcrunch.com/2024/07/01/meta-changes-its-label-from-made-with-ai-to-ai-info-to-indicate-use-of-ai-in-photos)) [공식·요약], IPTC 분석은 Instagram 이 IPTC DigitalSourceType 은 읽지만 C2PA 는 읽지 않았다고 적는다 ([IPTC](https://iptc.org/?p=9040)) [업체·요약]. **TikTok 커버나 Instagram 릴스 커버 이미지 자체가 라벨 대상인지, 라벨이 그리드 타일 위에 보이는지는 어느 1차 문서에서도 확인하지 못했다.** 안전한 기본값은 생성 에피소드에서 `is_aigc`(TikTok)와 `isAiGenerated`(Instagram)를 사실대로 켜고, 생성 커버 파일에 C2PA·IPTC 메타데이터가 남아 있는지 기록해 두는 것이다. 라벨이 예상치 못하게 붙으면 원인을 그 기록으로 추적할 수 있다 [추론].

정책 쪽에서 썸네일을 명시한 곳은 YouTube 다. 스팸·기만 정책은 비공개·미등록 영상과 썸네일에도 적용되고 "Using maliciously misleading titles, thumbnails, descriptions, or imagery … to trick users into clicking on a video that does not deliver what was promised"를 금지한다 ([YouTube Help 2801973](https://support.google.com/youtube/answer/2801973?hl=en)) [공식]. 나체·성적 도발, 혐오, 폭력, 위험한 내용의 썸네일은 거부되고 경고를 받을 수 있으며, 반복하면 맞춤 썸네일 권한을 30일 잃는다 ([YouTube Help 72431](https://support.google.com/youtube/answer/72431)) [공식]. 2024-12 보도는 YouTube 가 "egregious clickbait"(영상이 지키지 않는 약속을 하는 제목·썸네일) 영상 삭제를 인도에서, 특히 속보·시사부터 경고 없이 시작한다고 전했다 ([TechCrunch](https://techcrunch.com/2024/12/18/youtube-says-it-will-start-cracking-down-on-videos-with-clickbait-titles-in-india)) [요약]. 다른 나라로 확대됐는지는 확인하지 못했다. TikTok 커뮤니티 가이드라인에서는 썸네일을 직접 지칭한 규정을 찾지 못했고, 오해 소지 콘텐츠와 미공개 협찬은 일반 규정과 For You 노출 제외로 다뤄진다 ([TikTok Integrity and Authenticity](https://www.tiktok.com/community-guidelines/en/integrity-authenticity/)) [공식·요약, 2024 판 기준]. Meta 는 2025-07-14 남의 콘텐츠를 반복 재사용하는 계정의 수익화와 배포를 깎는다고 발표하면서 워터마크 추가는 의미 있는 개선이 아니라고 적고 타사 워터마크가 보이는 콘텐츠를 피하라고 했다 ([Meta for Creators](https://creators.facebook.com/blog/combating-unoriginal-content)) [공식]. 자기 콘텐츠를 여러 Meta 표면에 교차 게시하는 것은 허용되지만, TikTok·YouTube 로고가 박힌 커버나 마스터를 재사용하면 안 된다 [공식+추론].

이 세 정책이 생성기에 주는 지시는 하나다. 썸네일의 사건·숫자·사물·결과는 모두 본편에서 보이거나 전달돼야 하고, 드라마라면 지어낸 장면이 아니라 회차의 실제 순간이어야 한다 [추론]. 썸네일과 본편 키프레임의 얼굴 일치로 불일치를 잡는 연구 방법도 있다 ([arXiv 2112.08611](https://arxiv.org/pdf/2112.08611)) [측정·프리프린트].

## 플러그인 자동 생성에 바로 쓸 규칙

아래는 기본값이고 경고로 보고하는 항목이다. 이 저장소의 2026-10-31 방침대로 새 게이트나 점수를 만들지 않으며, 어떤 항목도 게시나 빌드를 거부하지 않는다.

1. **커버와 첫 프레임을 두 자산으로 나눈다.** 현재 `build-reel.sh` 는 `reel.mp4` 의 `COVER_TS`(기본 3.2초) 프레임을 잘라 `cover.jpg` 를 만들고([build-reel.sh:1710](../../../../skills/produce/references/build-reel.sh)), produce 규칙 12는 이것을 YouTube 썸네일 겸 IG·FB 영상 첫 화면으로 쓴다. 조사 결과는 두 역할이 다른 표면을 맡는다고 보여 준다: 첫 프레임은 피드의 스와이프를 멈추고, 커버는 그리드·검색에서 무엇인지 알린다. 첫 화면에 코드로 쓴 제목을 두는 현재 관행(produce 규칙 10)과 영상 위 글자를 금지한 2026-09-05 지침 사이의 경계는 소유자 결정 사항으로 둔다. story-first 경로가 커버를 어떻게 만드는지는 이번에 읽지 않았으므로, 별도 정지 커버 파일을 만들지는 그 경로를 확인한 뒤 정한다.
2. **원본 캔버스.** 롱폼 3840×2160(최소 1920×1080, 1280×720 미만은 쓰지 않고 경고), 세로 2160×3840(최소 1080×1920). 내보내기는 YouTube JPG/PNG ≤50MB(모바일 경로가 생길 때만 ≤2MB 사본), Instagram JPEG sRGB ≤8MB, Facebook ≤10MB 에 영상과 같은 비율. TikTok 은 Studio 저장 비율을 확인하기 전까지 9:16 과 3:4(1080×1440) 둘 다 준비한다.
3. **안전 띠.** 롱폼은 오른쪽 아래 폭 20%×높이 15% 와 하단 5% 에 글자·얼굴을 두지 않는다. 세로는 얼굴과 핵심 문구를 y≈656–1264, 보조 요소를 y=420–1500, 모든 정보를 y=240–1680·x=65–1015 안에 둔다(1080×1920 기준, 다른 해상도는 비례).
4. **축소·크롭 미리보기를 보고한다.** 롱폼 160×90 축소본, 세로 커버의 3:4·1:1·가운데 16:9 크롭본을 만들어 보여 주고, 핵심 띠 밖으로 나간 글자·얼굴을 경고로 적는다.
5. **글자.** 롱폼 기본은 한글 2~4 어절(대략 10~12음절 이하), 숏폼 커버는 1~3 어절. 어절 수는 영어 단어 조사에서 환산한 값이다 [추론]. 썸네일 문구는 제목을 반복하지 않고 보탠다. 강조어는 하나만 색을 바꾼다. 드라마·오락에는 무글자 변형을 하나 허용하되 기본값으로 두지 않는다.
6. **글자 렌더링.** 커버 문구는 코드로 합성한다(produce 규칙 10 유지). 굵은 고딕(굵기 800 이상), 글자 바깥으로만 그리는 외곽선, 글자와 외곽선·바로 뒤 배경 사이 명도 대비 3:1 이상을 측정해 미달이면 경고한다. 빨강·초록만으로 만든 대비는 피한다. 장면 속 글자가 꼭 필요하면 GPT Image 2 를 쓰고 결과를 판독한다.
7. **배경 프롬프트.** 이미지 모델에는 "no text, no letters, no watermark, no logo"와 글자가 들어갈 단순한 빈 영역을 명시한다. 다른 플랫폼 로고·워터마크를 넣지 않는다.
8. **장면 출처.** 커버 장면은 본편에 실제로 있는 샷에서 고르고 그 샷 id 를 기록한다. 표정은 해당 샷의 `shot_characters.expression` 을 따르며 놀란 얼굴을 기본값으로 쓰지 않는다. 드라마는 결정·위협의 순간에 놓인 한두 인물, 설명·주장형은 증거 장면(promise and proof 의 `payoff` 샷)과 시청자 말로 쓴 약속, 튜토리얼·리뷰는 결과물이나 제품을 크게 보여 준다.
9. **변형.** 16:9 롱폼은 큰 발상 하나(피사체, 구도, 문구)만 다른 2~3개 변형을 만들어 Studio Test & Compare 에 넘긴다(수작업). 테스트 중에는 제목·썸네일을 고치지 않는다. Shorts 는 A/B 가 없으므로 변형을 만들지 않는다.
10. **시리즈.** 회차마다 다른 장면을 쓰고, 채널 색·로고·회차 번호 위치를 고정한다. 회차 번호는 보조 띠 안에 둔다.
11. **게시 순서.** YouTube 는 비공개 업로드 → 처리 완료 → `thumbnailFilePath` 로 `thumbnails.set` → Shorts 는 `shortsAspectRatio` 를 읽어 확인하고 기존 Studio "Select from video" 단계를 유지한다. TikTok 은 기존 `tiktok-private-cover.md` 순서를 따른다. 커버 화면이 영상 안에 있으면 그 시각을 `tiktok_publish` 의 `coverTimestampMs` 로 넘기고, 없으면 Studio 에서 이미지 커버를 올린다(API 에는 이미지 필드가 없다). Instagram 은 비공개 단계가 없으므로 4번 미리보기를 게시 전에 끝내고 `coverUrl`(없으면 `thumbOffsetMs`)을 넘긴다. Facebook 은 Graph API `POST /{video-id}/thumbnails` 에 `is_preferred=true` 로 영상과 같은 비율의 커버를 올리는 경로가 있지만, 현재 `facebook_publish` 클라이언트(`server/src/sns-client.ts`)에는 썸네일 입력이 없으므로 도구에 추가하기 전까지는 Business Suite 수작업이다. Threads 는 첫 프레임 외 수단이 없으므로 영상이 커버로 읽히는 장면으로 시작하게 한다.
12. **공개 표시.** 생성 에피소드는 TikTok `is_aigc`, Instagram `isAiGenerated` 를 사실대로 켜고, 사실적 생성 인물은 YouTube `containsSyntheticMedia` 를 유지한다. 생성 커버 파일에 C2PA·IPTC 메타데이터가 있는지 빌드 기록에 적는다.
13. **피드백.** 썸네일 성과는 같은 채널의 이전 영상 CTR 과 트래픽 소스별로, 평균 시청 시간과 함께 비교한다. 절대 CTR 목표를 두지 않고, 시청 시간을 깎고 올린 CTR 은 개선으로 세지 않는다.
14. **언어별 썸네일.** 문구를 별도 층으로 보관해 두고, 에피소드에 해당 언어 오디오 트랙이 있을 때 그 언어로 다시 합성한다.

## 실제 계정에서 확인해야 할 것

1. **YouTube Shorts 세로 타일.** 2026-11-03 이후 `thumbnails.set` 으로 올린 이미지가 Shorts 탭의 세로 `oar*` 타일까지 바꾸는지, 비 YPP·전화 인증만 된 채널에서도 되는지, `shortsAspectRatio` 가 돌려주는 실제 픽셀 크기는 얼마인지 확인한다(공개 후 채널 Shorts 탭 DOM 의 `img` 와 비교).
2. **Shorts 의 "3:2" 표면.** 데스크톱 홈·검색·TV 에서 Shorts 썸네일이 어느 비율로 잘리는지 캡처로 확인한다. 9:16 만 쓰인다면 핵심 띠를 1:1 띠로 넓힌다.
3. **Shorts 트리밍.** Studio 에서 트리밍하면 선택한 프레임이 초기화되는지 확인한다.
4. **YouTube 롱폼 UI 기하.** 재생시간 배지·진행 막대·마우스오버 아이콘이 실제로 덮는 영역을 모바일·데스크톱 캡처로 잰다. Test & Compare 결과 표시(Winner/Performed Same/Inconclusive vs Preferred)와 언어별 썸네일의 실제 자격 조건도 Studio 에서 확인한다.
5. **TikTok Studio 커버 저장 비율.** 9:16 이미지를 올린 뒤 Display API `cover_image_url` 의 `width`·`height` 를 읽어 Studio 가 3:4 로 잘라 저장하는지 확인한다. 웹 업로드 기능이 아직 있는지(Tabcut 의 "removed" 주장)도 같이 본다.
6. **TikTok 그리드 크롭과 오버레이.** 프로필 그리드 타일이 3:4 인지 1:1 인지, 재생수 배지 위치, 캡션 첫 줄 자동 오버레이(SocialRails 주장), AI·유료 파트너십 라벨이 타일 위에 보이는지 캡처한다.
7. **TikTok 게시 후 수정 제한.** "Edit post"의 7일·하루 1회 제한이 이 계정·지역·앱 버전에서 적용되는지, 비공개 게시물에도 같은 제한이 걸리는지 확인한다.
8. **TikTok 가로 영상 커버.** 16:9 영상의 그리드·검색 타일 표시를 확인한다.
9. **Instagram 그리드와 탐색.** 그리드가 3:4 인지(API 문서의 1:1 서술과 비교), 탐색 탭 타일 비율, `cover_url` 의 최소 해상도, "AI info" 라벨이 그리드 커버에 보이는지 확인한다.
10. **Facebook.** `video_reels` 로 올린 릴스에 `/{video-id}/thumbnails` 가 적용되는지, DRAFT 상태에서 썸네일이 붙는지, 90초 넘는 `/videos` 업로드가 Reels 탭에 어떤 비율로 보이는지 확인한다.
11. **Threads.** 앱 작성 화면에 커버 선택 기능이 있는지, 피드 미리보기 크롭, `crossreshare_to_ig` 로 함께 올릴 때 Instagram 커버가 어떻게 정해지는지 확인한다.
12. **AI 메타데이터.** 우리 이미지 경로(ASTRA GenAI, GPT Image 2)가 만든 커버 파일에 C2PA·IPTC 메타데이터가 남는지, 각 플랫폼 업로드 뒤 라벨이 붙는지 확인한다.
13. **트래픽 비중.** 우리 채널의 Shorts·Reels·TikTok 조회 중 피드와 채널 페이지·검색 비중을 각 플랫폼 분석 화면에서 확인해 숏폼 커버에 들일 노력을 정한다.

## 결론

이번 조사가 바꾼 가장 큰 판단은 "좋은 썸네일 디자인"이라는 질문의 무게다. 코딩한 썸네일 약 3천 개의 브레이크아웃·부진 비교에서 얼굴·색·대비가 사실상 차이를 만들지 못했고, 숏폼 플랫폼 책임자들은 커버의 도달 효과를 스스로 낮게 본다. 남은 지렛대는 디자인 기교가 아니라 세 가지다. 피드에서는 스와이프를 멈추는 첫 프레임, 목록에서는 크롭을 견디는 가운데 띠의 짧은 약속, 그리고 그 약속을 본편이 지키는지다. 셋째는 YouTube 가 시청 시간으로 승자를 고르고 클릭베이트를 정책으로 처벌하기 때문에 측정·정책·저장소 지침이 모두 같은 쪽을 가리키는 유일한 규칙이다. 그래서 커버 생성기는 새로운 그림을 지어내는 도구보다, 본편의 샷과 그 표정·증거를 골라 코드로 쓴 한글 몇 어절을 얹는 편집 도구에 가까워야 한다.

두 번째 함의는 이 분야의 사실이 몇 달 단위로 낡는다는 점이다. Shorts 맞춤 이미지 업로드는 2024-07 "올해 계획 없음" 발표 뒤 2년 만에 2026-07 Studio, 2026-11-03 API 로 열렸고, TikTok 의 게시 후 수정과 웹 업로드는 블로그마다 다른 시점을 기록한다. 커버 규칙은 고정된 사양으로 박아 두기보다 위 확인 목록을 실제 계정에서 주기적으로 재고, 플랫폼별 크롭 수치를 설정값으로 두어 고칠 수 있게 하는 편이 오래 맞는다.
