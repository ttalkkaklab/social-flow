AI 영상 컷은 3D 사전 렌더가 먼저 — 프리비즈 필수화

social-flow · 지시와 구현 기록 · 2026-09-11 · 플러그인 0.73.0 (feat/previz-mandatory) · 앞선 조사 블렌더 산출물을 영상 AI 에 넘기는 세 갈래

진의 지시는 한 문장이다. AI 영상 생성 유형의 샷은 반드시 블렌더나 three.js 로 먼저 렌더하고 그 렌더로 영상 AI 를 더 정확하게 쓴다. 0.68.0 에서 선택 사항으로 붙어 있던 프리비즈 레인을 generated_video 컷 전부의 필수 조건으로 올렸고, 블렌더가 없는 기계를 위해 three.js 렌더러를 새로 만들었고, 앞선 조사가 「빠졌다」고 적은 두 가지 가운데 프롬프트 게이트 쪽을 닫았다.

1. 무엇이 바뀌나

이전에는 「카메라 경로나 타이밍이 정확히 맞아야 하는 컷」에만 프리비즈를 달았다. 이제는 영상으로 생성하는 컷이면 예외 없이 3D 에서 카메라와 배치를 먼저 잡고, 그 렌더가 세 갈래로 영상 모델에 들어간다.

갈래프리비즈가 넘겨주는 것어디서
참조 영상회색 클레이 mp4 가 Video 1. 카메라 경로·샷 리듬·피사체 궤적·배치API 레인 — Seedance 2.x seedance_reference(modelPurpose:"previz", handoff:"reference_video")
첫 프레임 → 스틸1번 프레임 png 를 구도 참조로 놓고 스틸을 편집한다. 클립이 시작하는 구도와 스틸의 구도가 같아진다양쪽 레인 모두 — spatial-prompts.js 가 previz.firstFrame 을 이미지 툴 참조 첫 자리에 넣고 구도 잠금 문장을 붙인다
프롬프트카메라 무브가 클립과 같아야 한다. §6.3 바인딩 문장은 조립기가 쓴다호스트 레인(Grok image_to_video 처럼 클립 입력이 없는 툴)은 이것과 스틸만으로 간다 — handoff:"frame_and_prompt"

예외는 넷이다. 가져온 클립(visual.reuse), 무료 소재(stock_video), 녹화, 공유 아웃트로. 이것들은 우리가 생성하지 않는다.

두 가지는 진이 고른다(같은 날 추가 지시). 첫 프리비즈를 렌더하기 전에 어느 렌더러(블렌더·three.js)인지, 영상 호출 전에 어느 모델인지. 후자는 video-model-options.js 가 보드 전체를 모델마다 견적 내어 표로 보여 주고 답한 모델을 PRODUCTION.videoModel 과 컷마다 적는다. production-mode.js 는 생성 컷이 있는데 두 기록이 없으면 보드를 거절한다.

2. 저장 계약

previz: {
  renderer: "blender" | "threejs",
  clip: "previz/s4.mp4",  firstFrame: "previz/s4-f0001.png",
  sha256: "<64 hex>",  fps: 24,  seconds: 5,          // 과금 길이와 같은 정수 초
  camera: { movement: "arc shot" },                     // visual.camera.movement 와 같아야 한다
  handoff: "reference_video" | "frame_and_prompt",     // 레인이 정한다, 안 적어도 된다
  actors: [{ color: "red", is: "the porter", image: 2 }] // 선택 — 색 바인딩 문장의 재료
}

render-routing.js checkPreviz 가 보는 것: 렌더러 이름, 로컬 mp4, 로컬 png, 해시, 정수 초, 24~60fps, 카메라 무브 일치, 레인에 맞는 handoff, 그리고 Seedance 경로에서는 referenceImagePaths[0] 이 소스 스틸인지, 끝 프레임이 없는지, 프롬프트가 Video 1·Image 1·「Do not reference its visual content」를 담는지. checkScene 은 --draft 밖에서 previz 가 없는 generated_video 컷을 거절한다. 라우트(seedance-route.js)는 1.5 Pro 에 previz 를 달면 「참조 영상을 안 받는 모델」이라고 바로 말한다.

3. three.js 렌더러

블렌더 브릿지와 같은 숫자를 받는다. 미터, Z 업, 프록시는 -Y 를 본다. 페이지 하나(previz-template.html)가 슬라이드 렌더러의 seek API 를 그대로 구현해서, 이미 있는 render-motion-slide.mjs 가 --previz 플래그로 프레임을 잡는다. 새로 짠 건 계약 파일(previz-contract.js — spec 검사, LINEAR 보간, 좌표 변환, 긴 변 36mm 렌즈)과 런타임 번들(previz-runtime.js, three.js 를 물어 499KB)뿐이다.

4. 앞선 조사의 빈칸 둘 가운데

  • 클립과 싸우는 텍스트 — 닫았다. 프롬프트의 카메라 문장은 네 개 visual.camera 슬롯에서 조립되고, 클립은 previz.camera.movement 를 수행한다. 둘이 다르면 검사기가 거절한다. 형용사 셋 제한과 「한 번에 한 가지만 바꾸기」는 문서 규칙으로 두었다 — 형용사 수는 기계가 세기 어렵고 오탐이 더 큰 비용이다.
  • 컨트롤 패스(depth·pose → Wan VACE) — 그대로 빈칸. ComfyUI 로컬 구성이 먼저라 이번 범위 밖이다.

5. 비용이 바뀐다

참조 영상은 Seedance 2.x 만 받고 입력 초까지 과금한다. 그래서 프리비즈 필수화는 컷당 단가를 한 자릿수 올린다.

7. 웹 조사 보강 — 여섯 질문

앞선 조사가 다루지 않은 여섯 가지를 따로 찾았다(범용 에이전트, WebSearch·WebFetch, 2026-09-11). 못 찾은 것도 그대로 적는다.

7.1 three.js·브라우저 렌더를 프리비즈로 쓰는 사례

하나뿐이다. previz-motion-studio는 three.js 로 마네킹 포즈와 카메라 무브를 잡아 MP4 로 내보내고, 용도를 "image-to-video AI tools (Kling, Seedance, Runway, Veo, etc.) as a motion + camera-work reference" 라고 적었다(별 0, 커밋 5). 헤드리스 브라우저 캡처를 참조 클립으로 쓴 글은 없고, 브라우저 렌더와 Blender 렌더가 같은 취급을 받는다는 문서도 없다. 모델 쪽 계약은 전부 파일 규격(mp4·초·해상도)이지 렌더러 종류가 아니고, Mixar는 모델이 읽는 게 "silhouette, depth and framing" 이라고 쓴다. 같은 플랫 셰이딩·같은 카메라면 같은 입력이라는 추론까지만 된다. 우리 three.js 레인은 이 추론 위에 서 있고, 첫 실전 컷의 콘택트 시트가 그 근거가 된다.

7.3 첫 프레임 리스타일

Nano Banana·GPT Image 2 로 첫 프레임을 고치는 게 표준 절차다. Flick: "use Nano Banana to edit the first frame, keeping the composition and character pose unchanged", 프롬프트 "Keep composition a 100% exactly match of the provided sketch. Keep camera position 100% unchanged". 두 모델 다 strength 인자가 없고, gpt-image-2 는 항상 high fidelity(input_fidelity 를 주면 실패). Seedream 5.0 Pro edit 는 보호 목록 문장("Keep the … camera crop, and background unchanged")으로 잠근다. 우리 구도 잠금 문장(§1)은 이 둘을 합친 꼴이다.

7.4 depth·pose 패스를 받는 호스팅 API

fal wan-22-vace-fun-a14b: task 에 depth·pose, video_url 필수, preprocess 로 서버가 맵을 뽑거나 미리 뽑은 맵을 받는다, 81~241프레임, 최대 720p. Runway Act-Two 는 실사 연기 영상이 입력이지 깊이 맵이 아니고, Seedance 2.5 edit 는 원본을 유지하며 고치는 모드라 컨트롤 패스가 아니다. Kling·Luma·Veo·Wan 2.5/2.6 호스팅엔 없다. 컨트롤 패스 레인을 연다면 fal VACE 한 곳이다.

7.5 정확도 실측

수치가 있는 비교는 없다. 가장 가까운 것: technology.org 필자 테스트(2026-02-23)는 5초 돌리 푸시인 하나를 참조로 프롬프트 셋을 돌려 "all three outputs had the exact same camera movement" 를 얻었고, 12초짜리(돌리+걷기+팬)는 "picked random parts each time", 6초 돌리만 남기니 일관됐다. Kling 사용자 실측: 첫 프레임이 깨끗하면 성공률 90% 이상. 학술 벤치마크(PostCam·Track2View·WorldStereo)는 연구 모델 대상이라 상용 API 수치가 아니다.

7.6 실패 유형과 수렴한 설정

  • 디테일이 많으면 나빠진다 — Mixar "Untextured grey boxes … guide the model better than a finished render", Flick "Too much detail can confuse the model".
  • 한 무브에 한 생각 — WaveSpeed "Either the subject moves or the camera moves, not both, unless you really need it"; 무브가 무시되면 조금 과장하고 피사체를 가운데 두고 가장 강한 2~3초만 잘라 쓴다.
  • 길이 3~8초, 2초 아래는 뭉개진다(WaveSpeed). Atlas Cloud "A busy reference dilutes the one beat you actually wanted".
  • Kling 은 마네킹·CG 를 조건부로만 읽는다 — "Real human actions are recommended, while certain stylized humanoid … can be recognized", 빠른 동작·가림 금지.
  • 뻣뻣한 참조 동작이 결과로 옮겨 가는지는 아무도 실측하지 않았다. 간접 증거만 있다("respect push-in from reference: reinterpret texture and color").
  • 인코딩 — 네이티브 프레임레이트 H.264, 과압축 금지(플랫 영역의 매크로블록이 텍스처로 샌다), 앞뒤 4~6프레임 미세 흔들림 제거.

못 찾은 것: three.js 자동화 파이프라인, 브라우저 렌더와 Blender 렌더의 동등성 근거, 프롬프트 대 참조 영상의 수치 비교, 뻣뻣한 동작의 전이 실측, 리스타일 strength 권장값. 전체 보고서는 세션 스크래치 previz-research-report.md.
