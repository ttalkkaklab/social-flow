캐릭터가 행동하면
이야기가 된다

기억과 목적을 가진 인물이 같은 3D 공간에서 만나고 대화하며 사건을 만드는 구조. 캐릭터 제작부터 MCP, 애니메이션, 스토리보드 확장까지.

문서 범위: 대화에서 조사한 기술과 저장소 구조를 종합한 설계안. 외부 프로젝트는 공식 문서를 확인했으며 설치·실행 성능은 검증하지 않았다.

입체감에는 두 층이 있다

몸의 정교함과 인물의 설득력을 함께 설계한다. 연구의 첫 질문은 “얼마나 사실적인가”보다 “경험이 다음 선택을 바꾸는가”다.

눈에 보이는 입체감

형태, 재질, 조명, 표정과 동작.

Blender 모델 → 리깅 → 애니메이션 → 렌더링

이야기 속 입체감

기억, 목표, 관계, 믿음과 선택.

관찰 → 기억 → 판단 → 행동 → 결과

연구 방향: 생성형 에이전트 + 공간에서 행동하는 에이전트 + 상호작용에서 생기는 이야기.
여기서 ‘생각’은 기억과 목표를 참고해 행동을 선택하는 계산 구조를 뜻한다.

VRM은 휴머노이드 캐릭터용 규격이다. 사용하려면 해당 규격에 맞춘 제작·내보내기가 필요하다.

GLB는 메시, 재질, 뼈대와 애니메이션 등을 전달한다. 복잡한 재질·털·제약 조건은 그대로 옮겨지지 않을 수 있어 베이크나 재구현이 필요하다. 브라우저 외에도 Blender 자체, 게임 엔진, 렌더된 영상으로 볼 수 있다. [2][3]

세 인물, 하나의 세계

캐릭터별 AI 문맥을 분리하고 공용 MCP 서버로 같은 세계에 연결한다. MCP는 관찰과 행동을 연결하는 인터페이스이며 판단과 실행 루프는 별도 프로그램이 맡는다. [4]

제안 아키텍처. 연속적인 상태 전달에는 WebSocket 등을 사용하며 매 프레임 MCP나 LLM을 호출하지 않는다.

공유하는 것

  • 편지의 실제 위치와 소유자
  • 문이 열렸는지 여부
  • 누가 어디에 있는지
  • 실행된 행동과 결과

인물마다 분리하는 것

  • 직접 보고 들은 사건
  • 상대에 관한 믿음과 오해
  • 개인 목표와 관계
  • 대화 문맥과 기억

공간이 사건을 바꾼다. 가구에 가리면 손동작을 볼 수 없고 문밖에서는 작은 목소리를 듣지 못한다. A의 행동을 본 C에게만 관찰 사건을 전달한다.

서버가 세션과 캐릭터 신원을 연결해야 한다. 요청의 캐릭터 ID만 바꾸어 다른 인물의 기억을 읽을 수 없게 한다. 두 인물이 같은 물건을 집으려 하면 세계 시뮬레이터가 처리 순서와 성공 여부를 판정한다.

도구는 적게, 동작은 풍부하게

손가락마다 MCP 도구를 만들 필요는 없다. AI가 의미 있는 행동을 선택하면 애니메이션 시스템이 여러 관절과 표정을 함께 움직인다.

개념적 동시 실행도. 막대 길이는 측정한 시간이나 성능 수치가 아니다.

줄어드는 것은 도구 수다. 재사용할 동작 제작과 리깅은 여전히 필요하다. 물건을 정확히 집는 행동에는 IK 외에도 잡는 자세, 접촉, 소유권 이전을 연결해야 한다.

이미 있는 부품을 연결한다

조사한 프로젝트는 연기 실행과 자율 행동을 각각 해결한다. 아래 조합이 바로 연결되는 완제품이라는 뜻은 아니다.

프로젝트확인한 기능활용 위치추가로 필요한 부분
TalkingHead
MIT		GLB 아바타, 립싱크, 감정, 시선, 손 제스처대화와 몸짓 실행세계 상태·기억·물체 조작
three-vrm
MIT		VRM 표시, 표정, 뼈대, 시선 제어직접 만드는 3D 실행부행동 선택·대화·세계 운영
Amica
MIT		VRM 캐릭터 음성 대화와 감정 표현통합 대화 UI 참고다중 인물의 공동 세계
AI Town
MIT		가상 마을, 캐릭터 대화, 공유 상태와 시뮬레이션세계·대화 운영 참고3D 몸과 정교한 연기
Generative Agents논문의 기억·성찰·계획 기반 시뮬레이션인물 행동 연구3D 연기와 제작용 통합

라이선스 표기는 확인한 저장소 코드 기준. 캐릭터 모델·모션 자산·외부 음성 및 LLM 서비스의 조건과 비용은 별도다. 저장소 문서 확인 기준이며 실행·유지보수 품질의 순위는 아니다.

연기부터 검증한다면

TalkingHead로 한 명의 표정·몸짓을 연결한다. setMood, playGesture, lookAtCamera 같은 API를 MCP로 감쌀 수 있다.

Mixamo 호환 뼈대와 ARKit·Oculus viseme 구조가 필요하다. 한국어는 기본 립싱크 언어 목록에 없어 별도 처리나 음성 서비스의 입 모양 데이터 연계를 검토한다. [5]

직접 실행부를 만든다면

three-vrm으로 표정·뼈대·시선을 제어한다. Amica에서 음성 대화를 연결한 구조를 참고한다.

TalkingHead와 three-vrm은 서로 다른 실행 선택지다. 모델 규격과 제어 방식을 맞추지 않고 그대로 합칠 수는 없다. [6][7]

우리 캐릭터 시트에 담는 방법

현재 시트는 연기 성향을 저장하고 생성용 지침으로 전달한다. 여기에 동작 자산과 재생 기능을 연결하는 확장을 제안한다.

컷에서는 행동을 시간순으로 선택한다

질문
B → A

A의 얼굴을 보며 “그 편지 못 봤어?”라고 묻는다.

0.6초
A / 망설임 + 숨기기

대답을 멈추고 편지를 쥔 손을 등 뒤로 옮긴다.

대답
A → B

시선을 되돌리며 “아니, 못 봤는데.”라고 답한다.

반응
B / 시선 이동

A의 손 쪽을 바라본다. 다음 판단의 관찰 정보가 된다.

예시 연출 시간이며 실제 음성·모션 길이를 측정한 값은 아니다. 한 컷의 감정과 임시 상태는 공용 캐릭터 성격을 덮어쓰지 않는다.

첫 실험: 방 하나, 세 인물, 비밀 하나

사실적인 외형과 무제한 행동을 한 번에 구현하기보다 선택과 결과가 연결되는지 먼저 확인한다.

텍스트로 세계를 실행한다

말하기·관찰·이동·집기를 허용한다. 인물별 관찰과 기억을 분리한다.

확인: 보지 못한 사건을 아는 척하는가?

한 명의 3D 연기를 연결한다

대기·끄덕임·망설임·손짓을 재생한다. 대사와 시선·표정의 타이밍을 맞춘다.

확인: 같은 대사도 연기에 따라 의미가 달라지는가?

같은 공간에서 서로 반응하게 한다

시야·거리·가림·행동 실패를 관찰 사건으로 전달한다. 편지의 소유권을 관리한다.

확인: 공간 배치가 선택을 바꾸는가?

반복 실행하고 비교한다

기억 있음/없음, 제한된 관찰/전체 정보 조건을 비교한다. 사건 로그로 원인을 추적한다.

확인: 이전 약속과 관계가 다음 행동을 바꾸는가?

종료 조건: 편지를 발견하거나 누군가 비밀을 고백하면 장면을 끝낸다. 대화가 자율적으로 이어지는 것과 이야기가 끝까지 완성되는 것은 별도 설계 문제다.

현재와 다음 작업의 경계

지금 있는 기반새로 연결할 부분
캐릭터 성격·연기 설정과 시트 출력3D 모델·동작 자산과 미리보기
컷별 행동·시각 연기·타이밍 계획계획을 실행 명령으로 변환하는 어댑터
Blender 구성·포즈·모션 관련 제작 도구실시간 자율 캐릭터의 판단·관찰 루프

이 문서는 설계 제안이다. 캐릭터 시트 스키마, 스토리보드 실행부와 MCP 도구는 이번 문서 작성에서 변경하지 않았다.

근거와 더 읽을 자료

외부 근거는 공식 문서와 원본 저장소를 사용했다. 현재 지원 범위는 저장소 코드와 계약 문서를 확인했다. 성능 수치나 오픈소스의 완성도 점수는 측정하지 않았다.

  1. Blender 기능 소개 — 모델링, 리깅, 애니메이션, 렌더링.
  2. Blender glTF 내보내기 — 지원 데이터와 변환 제약.
  3. Three.js 애니메이션 시스템 — 클립, 액션과 믹서.
  4. MCP 아키텍처 — 클라이언트와 서버의 역할.
