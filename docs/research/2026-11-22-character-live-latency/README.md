# AI 진행자는 채팅이 없을 때 무엇을 말하고, 질문에는 얼마나 빨리 답할까

2026년 11월 22일 한서린 유튜브 라이브에서는 첫 질문에 답하는 두세 마디가 송출되기까지 119.7초가 걸렸다. 같은 방송에서 캐시에 있던 오프닝 영상은 0.83초 만에 재생 준비를 마쳤다. 이 차이를 기준으로 실제 AI 방송 소프트웨어와 실시간 아바타 구현을 살펴봤다.

## 한서린 방송 실측

채팅 수신 시각은 송출기가 유튜브 메시지를 읽은 순간이다. 음성 시작은 해당 메시지 ID의 첫 발화 프레임이 인코더로 들어간 순간이다. 영상 작업 시간은 같은 작업 ID로 게이트웨이가 반환한 생성 요청 접수 시각부터 완료 시각까지다. 게이트웨이 안에서 순번을 기다린 시간도 들어간다.

| 질문 수신 순서 | 수신 → 답변 문장 확정 | 영상 작업 접수 → 완료 | 영상 완료 → 송출 시작 | 수신 → 송출 시작 |
|---|---:|---:|---:|---:|
| 첫째 | 5.1초 | 108.6초 | 5.4초 | 119.7초 |
| 둘째 | 93.6초 | 67.3초 | 4.4초 | 165.9초 |
| 셋째 | 9.4초 | 90.2초 | 3.3초 | 103.6초 |
| 넷째 | 8.8초 | 121.0초 | 5.5초 | 135.9초 |

둘째 질문은 첫 답변 영상이 준비될 때까지 기다렸다. 93.6초에는 그 대기와 문장 생성 시간이 함께 들어 있다. 네 건 모두 발화 마지막 샘플까지 송출했다. 10분 동안 채팅을 받았고 마지막 답변을 마친 뒤 녹화를 닫았다. 전체 녹화 738.7초 가운데 대사 클립을 재생한 시간은 48.3초였다. 시청자 기기에서 음성이 들리기까지의 지연은 별도로 측정하지 않았다.

## 이번 구현에 반영한 내용

- 방을 예약할 때 정한 주제로 문을 열고, 시청자에게 댓글로 의견을 남겨 달라고 말한다.
- 새 멘트가 준비되면 먼저 틀고, 생성이 늦으면 공통 환영 인사와 앞서 방송한 독립적인 주제 멘트를 돌려 쓴다. 같은 멘트를 연달아 내보내지 않는다. 개별 시청자에게 한 답변과 오프닝은 한 번만 재생한다.
- 동시 영상 요청 수의 기본값은 3이다. 진행 멘트가 한꺼번에 모든 자리를 차지하지 않게 해 시청자 답변을 받을 여유를 둔다. 시청자 답변끼리는 여러 건을 함께 생성할 수 있다.
- 질문이 채택되면 새 맥락으로 다음 영상을 계획한다. 이미 제출한 진행 영상은 완료까지 자리를 차지하고, 맥락이 바뀌어 쓸 수 없게 된 결과는 재생 전에 버린다.
- 위 실측은 수정 전 방송의 기록이다. 세 요청을 동시에 접수해도 GPU가 세 작업을 병렬 연산하는지는 별개다. 수정 후 실제 지연은 같은 조건에서 채팅 수신, 영상 접수·완료, 첫 송출 프레임을 다시 측정해야 알 수 있다.

## 수정 후 로컬 확인

같은 캐릭터와 목소리로 “내말 들려요?”에 답한 실제 클립을 다음 방송의 정해진 답변으로 등록했다. “네, 잘 들려요.”를 선택하고 영상 65프레임과 오디오 65,016샘플을 캐시에서 읽는 데 0.49초가 걸렸다. 시청자가 기다리는 시간에는 채팅 수신과 앞 문장의 남은 길이, 유튜브 재생 지연도 더해진다.

외부 영상 생성기를 모의 응답으로 바꾸고 로컬 송출기를 실행했다. 동시에 요청한 영상은 최대 세 편이었다. 다른 시청자의 캐시 답변이 먼저 나갔고, 같은 사람이 연달아 보낸 두 질문은 뒤 영상이 먼저 완성돼도 질문 순서대로 답했다. 새 질문 전에 요청해 둔 진행 멘트 두 편은 재생 목록에서 빠졌다. 그동안 환영 멘트가 이어졌고 세 답변 모두 끝까지 재생됐다.
