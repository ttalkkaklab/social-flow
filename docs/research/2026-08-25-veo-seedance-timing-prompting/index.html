02길이 선택 — 한 클립에 몇 초를 주나

4 vs 6 vs 8을 직접 비교하는 벤더 가이드는 없다(부재 확인). 대신 더 좋은 것이 생겼다 — "숏클립 하나 = 한 장면·한 순간"이 Veo 공식 규범이 됐다.

한 순간 원칙 [vendor]

"For short videos, dedicate each prompt to a single, focused moment. Trying to chain multiple distinct events (A then B then C) in one prompt for a short video often leads to muddled or incomplete videos." — Veo Best practices, 2026-08-24. Seedance 2.5도 같은 실패를 자기 말로 적는다: 시간에 비해 플롯이 적으면 "the model may improvise more freely", 많으면 과잉 컷·플롯 누락. 스토리보드의 1씬 = 1호출 계약의 벤더 측 근거다.

  • 실무 합성 규칙 [blog 합성 — 명문 없음]: 비트 하나(동작 하나+무브 하나)면 4초, 대사 한 호흡이나 전개-반응 2비트면 6~8초, 8초 멀티비트는 타임스탬프 워크플로(2초×4비트)로만.
  • 서버 허용표가 구속 계약이다 — Veo 4/6/8초(1080p·4K·참조 레인은 8초 전용), 기본 엔진 Seedance 1.5 pro는 4~12초. 문서 곳곳의 "Seedance 15초"는 2.0 수치였고, 나레이션 상한 13초와 충돌해 이번에 12초로 바로잡았다.
  • duration: -1 [vendor, API 08-24] — 모델이 유효 범위 안에서 정수 초 길이를 스스로 고르는 레인이 공식으로 생겼다(1.5 pro·2.0, 2.5는 기본값; 1.0 계열 제외). 우리 파이프라인은 나레이션이 길이를 결정하므로 확정 경로가 기본이고, -1은 길이가 정말 무관한 컷용.

03클립 안의 시간 — 엔진·세대별 3분법

"클립 안에서 언제 무엇이 일어나는가"를 적는 법이 셋으로 다르다. 하나의 규칙을 전 엔진에 이월하면 틀린다.

레인클립 안의 시간 표기근거 등급
Veo 3.1[00:00-00:02] 구간 분할 — 공식 예제는 8초를 2초×4비트로. 구간마다 샷 사이즈+행동+SFX:/Emotion: 라벨blog 레퍼런스 docs 3곳 모두 진입 없음 (00:0·timestamp 검색 0건)
Seedance 1.5 pro침묵 — 금지도 지원도 없다. 전 예문이 시점을 대사·동작 비트로 적는다 ("손바닥을 펴면, 컷") · 동작 속도 서술("within two seconds")은 벤더 예문에 있는 허용 용법vendor 침묵 우리 "타임코드 금지"는 계약이지 벤더 금지가 아니다
Seedance 2.0"does not respond to timestamps and only responds to shot numbers" — 08-15에 본 "불안정"보다 세게 적었다vendor
Seedance 2.5정수 초 3형 공식 지원 — 구간("0-3 seconds"·"[1s-4s]") · 시점("At the 2-second mark") · 상대("After 3 seconds"). 타임라인에 갭 금지, 고빈도 동작 통제엔 불가vendor

조립기 --clip 모드가 이 3분법을 기계로 지킨다 — seedance 경로는 시계 타임코드·숫자 초 차단, veo 경로는 [mm:ss] 허용·숫자 초 차단, --engine seedance-2.5는 정수 초 개방. 상태 변화 길이는 어느 경로든 말로 적는다("in under half a second").

04i2v 작법 — 두 벤더가 정반대

우리 주력 레인(승인된 PNG를 영상으로)의 프롬프트 작법이 양쪽 다 공식화됐는데, 방향이 서로 다르다.

Veo 3.1 [vendor]Seedance [vendor]
규범"Your source image already provides the subject, scene, and style. Focus your prompt on the motion" — 재서술은 Not recommended 명문 1.5 pro 가이드에 i2v 절이 없다(EN 전문에 "image" 0건). 정본은 Seedream→Seedance 모범사례 — 이미지 프롬프트의 정체성 낱말 재사용(정적 구도어는 삭제) + 동작 + 짧은 운镜

모션 어휘3분류 — camera motion · subject animation · environmental animation동작 + 衔接 표현(원지 회전·화면 출입·360도 환요)
꼬리—일치 잠금 문장 — "생성 주체는 참조 프레임과 완전히 일치" + 무관 요소 금지 (립스틱 예문)

공통 불변식은 살아 있다 — 레이아웃·facing·조명 재서술 금지는 양쪽 일치. 갈라지는 건 주체 지칭뿐이다. 저장 프롬프트 계약(§09)이 이 분기를 경로별로 적는다.

05대사·오디오 문법 — 콜론 반전

공식 입장 반전 [vendor, 2026-08-24]

Best practices §"Avoid quotation marks" — "To prevent the model from rendering text in the video, use a colon (:) after the speaker's action to denote speech and avoid using quotation marks." 권장형: A woman says: My name is Clara. 따옴표가 자막 번인을 부른다는 이유까지 명문이다. Gemini API 문서의 옛 "따옴표 사용" 규칙과 문서끼리 충돌하는데, 더 새 문서가 이유까지 적었으므로 콜론이 정본. Seedance는 따옴표 유지.

  • 보이스 캐스팅은 앞에 얹는다: "In a crisp, analytical voice, Clara says: It has to be here" [vendor]
  • SFX:·Ambient noise: 접두 라벨 — 08-15 조사가 기각했던 문법이 벤더 블로그에 실재함을 확인, [blog] 등급으로 복권. 음악 전용 문법은 여전히 없다(부재 확인).
  • 오디오는 별도 문장으로 — "use separate sentences to describe the audio" [vendor]. 우리 Audio: … 꼬리 계약과 정합.
  • Seedance 1.5 pro ZH판의 보이스 공식(08-13 신설): 성별+연령대+음성 속성+발화 속도+정서 기조 — 모델 음성을 쓰는 컷의 캐스팅 서술 교본.

06부정 지시 — 아티팩트류 카브아웃

"부정 지시는 본문에 쓰지 않는다"는 큰 규칙은 양쪽 다 유지된다. 다만 Seedance 쪽에 벤더가 직접 판 예외가 있다.

2.0 가이드가 아티팩트 3종(자막·로고·워터마크)에 한해 지시형 부정 문구를 공식 템플릿으로 준다 — "keep it subtitle-free", "avoid generating any text or subtitles", "do not generate a logo", "do not generate a watermark". 2.5는 오디오를 더한다("No BGM", "No audio"). 장면 내용이 아니라 출력 아티팩트라서 모델이 "대신 그릴" 것이 없는 부류다. 같은 벤더가 세로 자막을 제약어로 100% 못 막는다고 자인하므로, 카브아웃은 허가이지 보장이 아니다. Veo는 전부 negativePrompt 인자 — 변화 없음. 참고로 negativePrompt 서술이 Gemini API 문서에서 사라졌는데 SDK 타입·Vertex REST 예제에는 그대로 있다 — 파라미터 사망이 아니라 문서 델타로 판정, 다음 유료 호출에서 실효 1회 확인 권고.

07멀티컷 — 1.5 pro 공식 예문

Shot 1: … 번호형과 "The shot cuts to …" 산문형 둘 다 1.5 pro 가이드에 공식 예문으로 있다(예문 2~5컷). 규칙 셋이 따라온다 — ① 컷 시점은 시계가 아니라 대사·동작 비트로 ② 컷 사이 景别·내용을 뚜렷이 구분 ③ 구간별 길이를 제약하지 말 것 — 2.0 가이드 원문: "Do not impose strict limits on the duration of each segment; prioritize allowing the model to naturally generate the pacing based on the plot." 컷 수 상한·권장치는 벤더 문서에 없다(부재 확인) — 예문 관찰이 2~5컷이다.

08그 외 델타

  • seed 반전 [vendor] — 08-15의 "seed로 일관성 잡기 기각"을 Best practices가 부분 반전: 씬 간 시각·스타일·목소리 일관성에 같은 seed + 캐릭터 서술 전문 복붙을 명시 권장. 단 Gemini 문서는 여전히 "결정성 보장 아님" — 레퍼런스 위의 보조 수단. 우리 veo_* 툴은 seed 미노출(서버 검토 안건).
  • 프롬프트 리라이터 [vendor] — Veo 3/3.1은 비활성화 불가, 30단어 미만이면 LLM이 늘려 쓰고 그 리라이트본을 응답으로 돌려준다. 프롬프트 상한 1,024토큰. "짧고 모호하게 쓰면 남의 프롬프트가 된다."
  • draft 모드 [vendor] — 1.5 pro 전용 480p 저가 프리뷰로 장면 구조·샷 스케줄·주체 동작을 본편 단가 전에 검증하는 공식 레인. 서버 미노출(검토 안건).
  • 멀티뷰 완화 [vendor] — 2.5는 멀티뷰 주체 참조를 지원하되 "각도별 별도 파일"만. 한 장짜리 삼면도 시트 금지는 전 세대 유지 — 우리 패널 분리 관례가 정확히 그 허용형이다.
  • 2.5 전용 API [vendor] — output_format: mov(YUV 4:4:4, 편집·확장 체인 색 보존) · omni_reference_task_type(제출 시점 제약 검증). 자산 한도 요청당 50개(이미지 30·영상 10·오디오 10).
  • 문서 운영 — 구글 문서 대이동(위 §01), 바이트댄스는 ZH 먼저 갱신. 둘 다 다음 조사의 수집 절차를 바꾼다.

09플러그인 반영 (0.34.0)

  • 1씬 = 1호출 + 저장 프롬프트 계약 — scenes-schema §clip prompt 신설. 생성 영상 샷마다 계획 경로(visual.engine 또는 유형 기본값)와 최종 프롬프트를 스토리보드에 저장(visual.prompt · visual.video.prompt · visual.clip.prompt), produce는 그대로 전송. 배제 명사는 이웃 negative 필드로.
  • 조립기 clip 모드 — assemble-bg-prompt.js --clip: 카메라 4슬롯 스팬 + 모션 + 잠금 + Audio 꼬리를 기계 조립, 경로별 타이밍·부정 지시·공간어를 exit 1로 차단. 스트립·리뷰어 camera 모드가 같은 검사를 거울로 든다.
  • 길이 상한 수정 — "Seedance 15초"(2.0 수치)를 기본 엔진 1.5 pro의 서버 검증 범위 4~12초로 정정. 나레이션 13초 상한과의 충돌을 스토리보드 결함으로 명명.
  • 문법 갱신 — 콜론 대사(Veo)·i2v 경로별 작법·아티팩트류 카브아웃·멀티컷 비트 규칙을 video-model-selection·produce·storyboard 스킬에 반영.
