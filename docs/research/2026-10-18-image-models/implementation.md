# 이미지 생성 구조 개선

조사일: 2026-10-18. 모델별 API 근거와 팁은 [조사 목록](README.md)을 따른다.
실행 계약과 호출 예시는 [이미지 라우팅 안내](../../../skills/_shared/image-routing.md)에 정리했다.

## 바꾼 이유

기존 도구는 GPT Image, Z-Image, MLX 요청을 각자 처리했다. 저장한 모델 선택과
호출 인수가 충돌하거나 실패한 요청을 다시 보내는 문제를 공통 경로에서 막기 어려웠다.
MLX 모델마다 편집 기능이 다른데도 같은 기능처럼 취급했고 요청한 크기를 실제 출력 크기로 보고했다.

## 레이어

| 레이어 | 담당 모듈 | 역할 |
|---|---|---|
| 모델 계약 | image-models, image-registry | 모델 ID, 종료일, 작업 종류, 지원 인수와 카탈로그 |
| 선택 | image-selection | 작업 공간 설정, 에피소드 스냅샷, 명시적 예외 적용 |
| 계획 | image-routing의 planImage | 선택과 인수 결합, 입력 해시, 출력 경로, 비용 예약 |
| 실행 상태 | image-state, image-pricing | 동시 실행, 시도 횟수, 비용, 중복 호출 관리 |
| 어댑터 | image-client, mlx-serve-client, 기존 로컬 도구 | 공급자 요청과 응답 처리 |
| 결과 확인 | image-media | 실제 크기·형식·해시와 디코딩 확인 |

MCP 진입점은 `image_catalog → image_plan → image_execute → image_status`다.
기존 이미지 도구도 `imageContext`를 받으면 같은 경로를 사용한다. 설정된 제작 디렉터리에서
문맥 없는 직접 호출은 거절한다. 호스트 모델 선택은 호스트 도구로 전달하며 API로 바꾸지 않는다.

## 실행 게이트

1. 저장한 선택과 호출 모델이 일치하는지 확인한다. 종료된 모델을 자동 교체하지 않는다.
2. 모델별 작업과 인수, 참조 이미지, 마스크를 검사한다.
3. 입력·설정·승인 해시를 계획과 비교한다. 출력은 제작 디렉터리 안의 새 파일만 허용한다.
4. 네트워크 호출 전에 비용과 실행 슬롯을 원자적으로 예약한다.
5. 같은 요청 ID는 한 번만 제출한다. 응답이 불명확하면 비용 예약을 유지한다.
6. 파일 디코딩과 해시를 확인하고 응답의 토큰 사용량·요청 ID를 기록한다.

프로세스 종료로 멈춘 요청은 실행자 종료와 공급자 처리 종료, 실제 청구액을 확인한 뒤
명시적으로 정산한다. 새 시도에는 새 요청 ID를 쓴다. 완료한 요청은 파일 무결성을 확인하고
기존 결과를 돌려준다. 시각 품질은 `not_reviewed`로 기록하며 임의의 합격 점수를 만들지 않는다.

## 조사 결과 반영

- GPT Image 2 투명 배경과 mini의 낮은 입력 충실도를 허용했다. 모델별 종료일을 검사한다.
- OpenAI SDK 자동 재시도를 껐다. 사용량이 충분할 때만 토큰 기준 비용을 계산한다.
- FLUX.2 Klein, Krea, Mage, Qwen의 편집·변형 차이를 계약으로 표현했다.
- Qwen 투명 배경, 참조 수, Turbo 스텝 제한을 검사한다.
- MLX 출력 파일에서 실제 크기를 읽는다. 요청값을 측정값으로 보고하지 않는다.
- 아직 연결하지 않은 원격 API와 호스트 내부 모델은 지원한 것처럼 표시하지 않는다.

## 한계

비용 예약액은 호출자가 입력하는 보수적 추정치다. 공급자 청구 자체의 상한은 아니다.
실제 청구가 예약액을 넘으면 이후 요청을 차단하지만 이미 발생한 비용을 취소할 수는 없다.
불완전한 사용량 응답은 예약액을 유지하고 증거로 정산한다. 동시 실행 한도는 디렉터리별이다.
호스트 생성 결과와 시각 품질은 이 서버가 검증했다고 주장하지 않는다.

검증에는 모의 공급자 응답과 작은 합성 이미지를 사용했다. 유료 이미지 생성은 실행하지 않았다.
