맥북에서 쓸 로컬 이미지 생성
모델·도구 조사와 M4 Max 실측

이 맥북(M4 Max·128GB)에서 로컬 이미지 생성이 실제로 되는지 mflux + Z-Image Turbo 로 직접 생성까지 돌려 확인한 조사. 상업 사용 가능한 후보 3계열과 파이프라인(gpt_image·nanobanana API) 대비 위치를 정리한다.

01결론

이 맥북으로 로컬 이미지 생성이 된다 — 실측으로 확인했다. Z-Image Turbo(6B·Apache 2.0)를 mflux 로 돌려 1024² 기준 확산 약 2분, 9:16 세로형(1088×1920) 약 7.4분에 커버 배경으로 바로 쓸 품질이 나왔다. 피크 메모리 32~39GB 로 128GB 에서 여유가 크다. 단, 실측 당시 다른 세션들이 겹쳐 로드 평균 74 인 과부하 상태였으므로 위 수치는 보수적인 하한이다.

추천 구성은 이렇다. 기본은 Z-Image Turbo — 속도·품질·라이선스(Apache 2.0) 모두 걸리는 게 없다. 편집(img2img·멀티 레퍼런스)이 필요하면 FLUX.2 klein 4B(Apache 2.0) 또는 Qwen-Image-Edit-2511(Apache 2.0)을 얹는다. 도구는 스크립트 파이프라인엔 mflux(CLI·Python API), 손으로 탐색할 땐 Draw Things(무료 GUI) 조합이다.

주의할 라이선스 함정: FLUX.2 계열은 4B(klein)만 Apache 2.0 이고 klein 9B·dev(32B)는 비상업 라이선스다. 수익 채널 콘텐츠에 쓰는 이 프로젝트에선 9B·dev 를 제외해야 한다.

02이 맥북 실측 결과 실측

mflux 를 uv tool install --python 3.12 mflux 로 설치하고 Z-Image Turbo(8bit 양자화, 9스텝)를 세 번 돌렸다. 모델 저장소 다운로드는 31GB(bf16 원본 기준)였다.

1차 (부하 보통)1024×1024116초~13초149초31.9GB

측정 중 로드 평균이 74(16코어 대비 4~5배 과부하)였다 — 다른 Claude Code 세션들이 같은 머신에서 돌던 상태다. 한가한 머신에서는 1024² 가 1~2분대로 내려올 여지가 크다. 9:16 은 픽셀 수 2.1배에 어텐션 비용이 제곱으로 붙어 4배 안팎으로 느려진다.

03후보 모델 비교

2026년 8월 기준, 이 사양에서 돌 수 있고 품질이 현역인 모델은 세 계열이다. 크기·라이선스는 Hugging Face 모델 카드(1차 출처)로 확인했다.

Qwen-Image 2.0(7B)은 아직 로컬로 못 쓴다. 2026-02 발표 후 화제였지만 Hugging Face 에 오픈 웨이트가 없다(API·데모 전용). "로컬 가능" 이라고 쓴 블로그가 여럿인데 HF 모델 검색으로 직접 확인한 결과 공개된 것은 Qwen-Image(20B)·Qwen-Image-2512·Edit-2509/2511 뿐이다.

SDXL·FLUX.1·SD 3.5 같은 이전 세대도 물론 돌지만, 지금 새로 시작하면서 고를 이유는 없다. 품질·속도·라이선스 모두 위 세 계열이 앞선다.

04텍스트(한글) 렌더링 실측 실측

커버·썸네일에 글자를 새겨 넣을 수 있는지는 별도 문제다. Z-Image·Qwen-Image 의 타이포그래피 강점은 영어·중국어 기준이고, 한글은 오픈 모델 전반의 약점이다.

실측 결과: 한글은 못 쓴다. "딸깍연구소" 를 흰 고딕 타이틀로 요청하자 "달닥연구소" 로 렌더링됐다 — 받침·자소가 비슷한 다른 글자로 바뀌는 전형적 유사문자 패턴이다. 레이아웃·폰트 무게는 그럴듯해서 언뜻 보면 지나치기 쉽다는 점이 오히려 위험하다. 같은 화면의 영어 "AI LAB" 은 완벽했다.

이 프로젝트 파이프라인에는 영향이 없다 — 커버 배경은 텍스트 없는 이미지로 생성하고 글자는 렌더 템플릿에서 오버레이로 얹는 구조(계획 리뷰 P0 규칙)라, 모델의 한글 렌더링 능력과 무관하다. 글자가 박힌 이미지가 꼭 필요한 경우(카드뉴스류)는 지금처럼 gpt_image API 를 쓰거나 배경 생성 + HTML 오버레이로 우회한다.

05실행 도구

mflux — 스크립트 파이프라인용 이번 실측에 사용

Apple MLX 로 포팅된 이미지 생성 CLI·Python API. uv tool install --python 3.12 mflux 한 줄로 설치되고 33개 명령이 깔린다 — mflux-generate-z-image-turbo, mflux-generate-flux2, mflux-generate-flux2-edit, mflux-generate-qwen, mflux-generate-qwen-edit 등 생성·편집·업스케일(SeedVR2)·ControlNet·LoRA 학습까지 커버한다. 헤드리스 실행이 되므로 지금의 서버 툴(gpt_image 등)과 같은 자리에 로컬 백엔드로 붙일 수 있다. 

# 이번 실측에 쓴 명령
mflux-generate-z-image-turbo \
  --prompt "..." --width 1088 --height 1920 \
  --steps 9 --seed 42 -q 8 --output cover.png

Draw Things — GUI 탐색용

무료 맥 네이티브 앱(App Store). FLUX.2·Z-Image·Qwen-Image 를 모두 지원하고 LoRA 학습도 된다. Metal 최적화로 ComfyUI 보다 빠르다는 평이 많다. 프롬프트를 손으로 다듬으며 탐색할 때 적합하고, 자동화 파이프라인에는 mflux 쪽이 맞다.

ComfyUI — 복잡한 워크플로용

노드 기반 워크플로가 필요할 때(다단계 합성·커스텀 파이프라인)만 고려. 맥에서도 돌지만 MLX 네이티브가 아니라 같은 모델 기준 mflux·Draw Things 보다 느린 경우가 많다.

06파이프라인 관점 — 지금 쓰는 API 대비

social-flow 는 지금 gpt_image(OpenAI)·nanobanana(Gemini) API 로 이미지를 만든다. 로컬 전환의 손익은 명확하다.

비용0원 · 무제한장당 과금
속도1024² 2~3분대 (과부하 실측 기준)수 초~수십 초
품질(사진풍 배경)커버 배경으로 충분 (실측 확인)상급
한글 텍스트사실상 불가gpt_image 는 가능
편집(img2img)qwen-edit·flux2-edit 로 가능성숙
프라이버시·오프라인완전 로컬외부 전송

결론은 대체가 아니라 보완이고, 이 분담은 조사 당일 플러그인에 채택·구현됐다(사용자 결정 2026-08-12). 서버에 image_local_generate 툴이 supertonic 클라이언트와 같은 방식(mflux CLI 서브프로세스)으로 추가되어 텍스트 없는 이미지(points 배경·성장 루프 첨부·시안 탐색)의 기본 경로가 됐고, 글자가 들어가거나 품질 상향이 필요한 건(커버 배경=썸네일·b-roll 소스·브랜딩)만 gpt_image 로 간다. 빌드된 서버로 512×512 를 23초에 생성해 동작을 확인했다.

07디스크·메모리 예산

  • 디스크 — 여유 150GB. Z-Image Turbo bf16 원본 저장소가 31GB 를 차지했다. 커뮤니티 사전 양자화 가중치(filipstrand/Z-Image-Turbo-mflux-4bit, Runpod/FLUX.2-klein-4B-mflux-4bit, OsaurusAI/Qwen-Image-mflux-4bit 등)를 쓰면 모델당 4~12GB 로 줄어 서너 계열을 얹어도 부담이 없다. FLUX.2 dev fp16(64GB급)만 피하면 된다.
  • 메모리 — 실측 피크 32~39GB. 128GB 에서 다른 세션과 겹쳐도 안전하다. 다만 생성 중 CPU·GPU 를 크게 쓰므로 영상 렌더(ffmpeg)나 다른 세션의 무거운 작업과 동시 실행은 피하는 게 좋다.
